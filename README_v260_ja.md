# SERA v260 — 下フリックがサイド、横フリックがバクステになる不具合を修正

## 発生原因
v258でSTEPとBashの入力区画を、共に「セラ正面の画面投影方向」から相対的に90°ずつ分類したため、カメラの斜め構図では画面の下・左右が前後左右の意図とずれていました。STEPの側方移動はもともとカメラ画面右ベースで計算されるため、入力の分類基準と行動の方向基準が混ざっていました。

## 修正
- **STEPの前後左右判定を画面の上下左右へ固定**。上→前ステップ、右→右ステップ、下→バックステップ、左→左ステップ。斜めは90°×4区画（各中心±45°）で一方向に分類。
- STEPを定義する `_classify_step_flick` は共通関数 `FLICK_DIRECTION_POLICY.screen_step_direction(displacement)` を呼び、`Vector2.UP` を基準軸として量子化します。フリックした指の絶対画面方向以外で動作名は変わりません。
- **Bashは引き続きセラ正面に向けた前フリックで発動**。格闘コンボ／ガード派生の両方で投影した機体正面を使用します。セラを画面の斜めから映した場合に限り、STEPとは前の指向が異なることを明記し、混乱を防止します。

## 不変更範囲
- ステップ方向別の実移動計算（前後はセラ正面、横は画面横方向）、距離：前3m／後4m／横2〜4m、モーション、EN15、0.24秒／78px／500px/sの入力条件。
- Bashはv256の0.42秒／正面30px／200px/s、方向はセラ前方90°区画（±45°）。
- 既存の移動・BOOST・ロック受付時間固定（v259）・敵の衝突・カメラ・アニメ・UI・デバッグJumpは変更しません。

## テスト
- v260固有の画面上下左右・回転全域・斜め境界・Bash差別化の数値テストを追加し、過去の静的回帰検査も仕様に合わせます。
- Godot Android実機での操作感は未検証です。
