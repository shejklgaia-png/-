# SERA v299 — 頭部AUTOロックの再修正・WAIT/RUN接地時の最下点補正

## HEADロックを再び取得できなくなった原因
- v298でBODYも実メッシュ交差の候補になった結果、低い頭部とBODYの両方が線分に重なりやすくなりました。
- v297の頭部ロック補正は**本来の頭部上端から上へ1mだけ**の薄い領域で、カメラが本体中心に近い高さにあると、この補正領域の下を線分が通過します。その場合はBODYが手前の交点として選ばれ、HEADを取れません。
- BODYは常に有効候補なので、HEADが一瞬優勢になっても0.22秒の切替時間を満たせずBODYに残る場合もあります。

## 対応
- HEADのロック専用AABBを、本来の頭部の高さ全体から上1mまで連続させ、**頭部前方（敵ローカル+Z）へ0.85m拡張**しました。頭部に入る正面～浅い角度の線分が、BODYに入るより早くHEADへ当たるようにします。
- BODY/HEAD/脚の**カメラから最初の交点を比較する規則そのものは変更しません**。BODYに不利なスコアやHEAD強制優先は設けていません。カメラが後方から本体を見る場合はBODYが選ばれます。
- HEADのモデル、攻撃当たり判定、物理衝突、HUDマーカー、攻撃中のロック固定は不変更です。

## 足の高さ補正
- 待機（`Wait_motion`）中は、表示中の左右足メッシュの**実頂点の最小Y**から床上面に表示用リグの高さを合わせます。
- RUN中は既存の左右接地／足音イベントが出たフレーム**だけ**左右足の最小Yを測定して表示用リグ全体のYを補正します。次の接地までその高さを維持し、歩行中の毎フレーム再計測・靴メッシュだけの一瞬の平行移動は行いません。
- 鳥脚Cにも同じ規則を適用します。従来RUN中に毎フレーム実行していた鳥脚専用の高さ追従はRUN/WAITから外します。
- 格闘、バッシュ、ガード、被弾、ステップ、ブースト、ジャンプは従来の固定装備高さを使用します。重量脚部B/Dの既存SLIDE専用IK処理だけは維持します。
- プレイヤーの衝突体と物理Y、骨格元モデル・キーフレーム、足音の検出時刻は変更しません。

## 検証
- v299の静的検査とGodot実行検査を追加し、正面・斜め上・背後のHEAD/BODY優先、実メッシュの最下点を使ったWAIT/RUN補正、鳥脚C、攻撃中の補正解除を確認します。
- 旧v199・v297静的テストの旧コメント／頭判定範囲に限定した期待値を更新します。Android実機での滑らかさ・モーションの見え方は未確認です。
