# SERA v395 — なぎ払いの4脚対称化と、脚の復帰を優先する頭部制限

## なぎ払い
左前脚だけ正常だった理由は、右前脚と後脚の待機関節角が左前脚とは異なるのに、左前脚の攻撃回転の**差分だけ**をそれぞれの待機姿勢へ足していたためです。なぎ払いについては左前脚の実際のBlockbench攻撃姿勢（上腕・脛・足先）を左右・前後に完全反転し、**胴体の傾きも同じ変換**を適用します。従来の「他脚のWait姿勢＋回転差分」はキック・踏みつけでは維持します。

なぎ払いの足先が地面へ戻る際も、ソースの関節角を強制的な接地IKで折り曲げないようにしました。必要な床接触補正は一時的な足先のワールド位置補正に限定し、次のフレームでBlockbench原本のローカル関節座標へ戻します。足の攻撃時間・速度変化・砂煙・当たり判定は維持します。

## 頭部
v394の機械的な「腕が戻れる可動範囲」の制限を、頭部の見た目だけでなく**実際のYaw状態・追尾フィルター・ダウン中の分岐にも毎フレーム適用**します。脚の再接地・攻撃からの復帰・起き上がり後の歩き直しなど、脚が戻る局面ではプレイヤー追尾より脚の復帰経路を優先します。**頭部前面と各脚の実メッシュ**を約75msごとに照合し、腕の機械的可動限界内で重なりが最小となる回転方向を選びます。頭部を正面0°に固定するとかえって脚へ埋まる場合は、近い安全方向へ最大毎秒140°で滑らかに退避します。Pitchは通常位置へ戻し、攻撃脚が戻り始める0.45秒前から退避を開始します。なぎ払い中も攻撃脚のモーションを変更せず、他の支持脚だけ頭部との干渉回避IKを適用します。既存の10cmの侵入深度制限と頭部上昇回避は維持します。

## 検証
Godot実行テストで4脚のソース軌道と胴体の左右・前後対称性、各攻撃の接地、脚の復帰中の頭部の絶対角度上限を検証します。Android実機での見た目は未確認です。

## 頭部先端70％の当たり判定（追加）
頭全体のメッシュ判定を廃止し、**先頭から前後長70％だけの直方体**を使います。後ろ30％の首・付け根は判定から除外し、剣による頭部ヒット・物理衝突・ロック範囲・脚との干渉回避で同じ矩形を参照します。頭をYaw/Pitch回転した場合も直方体は頭のローカル姿勢に追従します。モデルの見た目と手足のメッシュは変更しません。

## 踏みつけの足先を垂直化（追加）
足先の長辺はローカルY方向です。従来は振りかぶりのBlockbench足首キーフレームを維持したため、足先が横倒しになる瞬間がありました。**振りかぶり開始から0.18秒で垂直へ補間し、その後の振りかぶり・振り下ろし・1.5秒の着地保持中は長辺を垂直**に保ちます。肩・膝の原本キーフレーム、振りかぶり時間、接地位置補正、砂煙・攻撃判定は維持します。

脚が戻る際、首の可動角だけでは前方70％の矩形が支持脚を避けられない場合があります。この場合は**最大1.2mの範囲で頭部を左右へ一時的に退避**させます。退避方向は、現在の頭部角度と脚のメッシュとの実際の侵入深度を比較し、できるだけ小さい移動量を選びます。退避は最大3.0m/秒、脚が戻った後は0.85m/秒で徐々に通常位置へ戻します。通常の頭部追尾と足先の接地位置は変更しません。
