# SERA v446 — 胴体復帰中の足先先端ワールド接地固定と腕の瞬間復帰防止

## 動画で確認した現象
添付動画 `1000036815.mp4` では、胴体が起き上がる際に攻撃脚が胴体とともに大きく持ち上がり、腕の復帰開始時に関節角度が急に変わる現象が見られます。

## 原因
- 従来は「胴体復帰中も攻撃脚の原本ローカル姿勢を維持」していました。そのため親であるBodyが上がると子の攻撃脚も一緒に上がります。既存の接地IKは足先の**床めり込み**を修正するだけで、空中に浮いた足先をワールド座標に固定していませんでした。
- さらに戦闘シーンでは毎フレームの `bittaran_rig.set_motion("Idle")` により、**直前のIK補正済み関節姿勢が上書き**されます。従来の腕戻し補間がそのIdle姿勢を始点として取得することで、胴体復帰→腕戻しの境界にカクつきが生じ得ました。

## 修正内容

### 1. 胴体復帰中は足先先端を固定
- 攻撃が終了して胴体を上げ始める直前に、**実際の足先メッシュの8頂点**から床接触角（同じ高さなら先端側）を1回だけ選択します。足首の中心や足の付け根ではなく、実際の足先メッシュの接触点を基準とします。
- 直前のIK適用後の足先ワールド姿勢から接触点の**ワールドXZ**を保存し、ワールド床Y=0（3mmの余裕）に固定します。
- 胴体を戻している間は、この固定位置へ上肢・下肢の2ボーンIKを適用します。足先の向きも開始時のワールド方向に固定し、毎フレームの原本再読込によって足首が連れ上がらないようにします。
- 膝の曲げ方向は**前フレームのIK補正後の膝位置**を再利用して決定し、膝の突然の反転やねじれを防ぎます。
- 固定が物理的に届かない場合は、骨を引き伸ばさず、既存の関節到達限界内で解きます。残差は `source_ik_body_toe_pin_error_max` と `source_ik_body_toe_pin_drift_max` に記録されます。

### 2. 腕の戻し開始時に「本当に表示されていたIK姿勢」を引き継ぐ
- `scripts/bittaran_foot_ik.gd` が胴体復帰中のIKを適用した後に、`scripts/bittaran_rig.gd` の新しい `remember_source_body_grounded_limb()` へ攻撃脚の3関節ローカル回転・位置を保存します。
- 次フレームの`set_motion("Idle")`によるリセットよりも**前に保存した姿勢**を、腕の戻し補間の開始姿勢として使用します。これにより、前フレームの実表示姿勢と戻し開始姿勢の不一致をなくします。
- 胴体が基本姿勢に戻り切ってから、上肢・下肢・足先を**1.20秒で5次smootherstep**を使って基本姿勢へ直接戻します。途中で脚を振り上げるモーションは挟みません。

### 3. 処理負荷と既存動作
- 接触点を選ぶための8頂点の走査は**復帰開始時の1回のみ**。その後は固定ワールド座標と前回の膝姿勢に対し、1フレームに**2ボーンIKを1回**実行します。レイキャスト・地形探索・メッシュ個別の平行移動はありません。
- 左右なぎ払い・弾き・踏みつけの全6攻撃に適用。支持脚3本の接地IKを維持。
- なぎ払いは往路終了まで**開始から2.00秒**、復路通常速度、胴体復帰1.40秒、腕戻し1.20秒を維持。弾き・踏みつけは胴体復帰0.62秒、腕戻し1.20秒を維持。原本Blockbenchデータは変更していません。

## 新しい回帰テスト
`tools/v435_bittaran_gait_three_support_runtime_check.gd` に以下を追加しました。
- 6種類の攻撃それぞれで、胴体復帰中に固定足先先端の座標が同じワールドXZ・床Y=0からずれないこと。
- 固定目標への到達不能サンプルが発生した場合は別カウントで報告し、到達可能なはずなのに足先が浮く場合は失敗。
- 胴体復帰から腕戻しへの段階移行6回すべてで、戻し補間の開始姿勢が**直前のIK補正済み関節回転と一致**すること、および瞬間的な大きな関節回転が起こらないこと。
- メッシュ18個の親子接続と支持脚3本の接地を従来どおり検証。
