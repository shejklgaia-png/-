# SERA v408

## 概要
実機フィードバック「右前脚からの弾きのモーションが正確なミラーになっておらず、足が浮いたり狙いが異常になる」への対応と、その後の指示「地面を這うように足が伸びる、元のモーションを全ての足で再現したい」を受けた再設計です。弾きは、脚ごとの関節リターゲットをやめ、元のモーション（左前脚）の足先軌道そのものを全ての脚で再生する方式に変わりました。

## 何が起きていたか
- 右前脚の弾きは打撃中に足が浮き（足裏が最大約1.3m）、伸びる向きも流れていました。計測すると、関節空間でクリップを変換する従来方式（差分／鏡像のブレンド）では、元の足先軌道から右前脚で最大1.75m、ホールドでも0.36mずれていました。脚ごとにブレンド方法を変える対策も検証しましたが、変換そのものの誤差が残るため、方式自体を変えています。
- あわせて見つけた複合要因: (1)鏡像した足の回転は、各脚の足裏ポイントに対して元の脚と違う効き方をします（脚のローカルフレームが定数回転ずれている: 右前49.2°／左後41.2°／右後36.7°）。このためIKの足首目標が転送した関節位置から大きく外れ、伸び切りでリーチ制限に引っかかっていました。(2)照準と再生軌道の両方が胸のヨー（後脚では最大±140°）を含んだ状態で合成されており、軌道が回転して左後脚の照準要求が上限を超えていました（進行方向のずれ56°）。

## 修正
- リグに `sample_authored_kick_source` を追加: 左前脚の著者チェーンを、胸ヨーを除いた胴体トラックの下でサンプルし、足裏・足首・膝を腰相対で鏡像転送（右脚は左右反転、後脚は前後反転）、足の回転は平面鏡像で返します。照準の基準方向もこの軌道から取り、弾きの照準上限を130°に広げました（軌道はIKが再解決するので物理的な肩の限界は適用されません。なぎ払いは100°のまま）。
- 接地オフセットの校正を、再生される軌道の折り畳み（クリップ0）に合わせました（`kick_source_contact_height`）。
- IKは弾きの全区間（予備動作〜ホールド）で、転送された軌道へ脚を解きます（予備動作中は接地した足裏からブレンド）。v406の至近距離短縮もそのまま合成されます。足裏ポイントは、鏡像回転が転送オフセットへ正確に一致するようティックごとに適合させたものを使い、戻り区間で元へブレンドして戻します（足首の跳ね防止）。
- 足メッシュの接地補正: 元の脚とのメッシュ張り出し差を目標の高さへ補正し（折り畳みで浮く左後脚などは床方向へ）、打撃中の床めり込みは腰と目標を一緒に持ち上げて処理するようにしました（元のモーションの「地面を這う」這いずりが、腰相対の軌道を歪めずに再現されます）。

## 計測結果
- ゲームが実際に選ぶ配置での足首の高さプロファイル（元脚との差）: 右前 0.00〜0.13m（v407では1.47m）、右後 0.11m、左後 0.17〜0.45m（左後はv406のリーチ係数差による経路の伸縮分）。
- 全脚とも折り畳みの足メッシュが床に接地（斜め配置で右前+0.39m／左後+0.93m浮いていたものが解消）、伸び区間も地面低く這い、床めり込みなし。方向のずれ（v403）は解消。

## チェック
- 新規 `tools/v408_bittaran_kick_source_trajectory_runtime_check.gd`: 全脚×自然配置で、折り畳みの接地／足首プロファイル（区間別の許容差）／床めり込みなし／伸び区間の低さを検査。v407ツリーでは FAIL（右前1.47m／左後2.12m／右後2.47m）、本版で PASS。
- 既存チェックの変更（意図と理由は各ファイル冒頭とDEVELOPMENT.mdに明記）: v391（予備動作の膝判定をローカル回転から膝の折れ角〈腰-膝-足首〉へ変更）、v400（予備動作の接地判定を足裏マーカーから足メッシュ最下点へ変更、許容0.20m、初期配置を決定的に変更）、v404（足先の突き抜け上限を3.2→3.6mへ。足首の上限1.8mは不変で実測1.57m）、v405（弾きの胴体沈み込み帯域を軌道校正に合わせて [0.75, 1.16]＋前脚ペア差0.25へ。なぎ払いと基準サンプルは不変）。
- 関連チェック（v389/v396/v399〜v407）はすべて PASS。ローカル全件スイートも PASS（PRのCIでも確認）。

## 既知の制限（従来から）
- 後脚の弾きを正面のプレイヤーへ強制的に発動するような、通常の技選択では選ばれない配置では、照準の都合で着弾方向がずれる場合があります（v403で明記した制限。本版で照準上限を広げたため、自然配置では発生しません）。

## 既知の未適用事項
- `.github/workflows/sera-bittaran-focused.yml` への v408 チェック登録行は、GitHub App に workflows 権限がないため未投入です（全件 CI マニフェストへの登録は投入済みで、PR の CI で全件実行されます）。
