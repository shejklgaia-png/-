# SERA v226 — 描画順を汎用の「描画契約」に抽象化

## 目的
v225で発見した「機体オーバーレイがスラスターを後描画で覆う」不具合を、今後の銃口炎・バリア・斬撃・弾道・装備モデルにも適用できる設計ルールと検証へ一般化しました。

## 実装
- 共通の `scripts/render_order_policy.gd` が透明3D描画の役割別優先度を所有します。
- セラの本体オーバーレイ・残像・斬撃・スラスターの各実装は優先度の数値直書きをやめ、同じ定数を参照します。
- 3つの主要シェーダーに、レンダリング役割と深度テストの契約を宣言しました。
- `docs/RENDER_PIPELINE_POLICY_ja.md` に、座標系・可視状態・深度・透明描画の4軸と、モーション遷移を含む検証表を追加しました。
- `AGENTS.md` とモデル統合ガイドから描画設計文書の参照を必須化しました。
- `tools/render_policy_self_check.py` をGitHub Actionsへ追加しました。優先度のハードコード、定数未登録、深度契約不整合、新規半透明シェーダーの宣言漏れを検出します。

## 変更しないもの
実際の描画優先度（-20/100/105/110/126/127）、シェーダーの色・深度・混合方式、スラスターと残光のアルゴリズム、3Dモデル、各種アニメーション、ゲーム操作・戦闘処理。表示名は `SERA v226` とします。

## 注意
この仕組みは今後のコーディング規約と静的検査です。Android上のリアルタイム描画、半透明重ね合わせ、モデルとの干渉を完全自動で判定するシステムではありません。新しいエフェクトを制作した際は、特に斬撃中と姿勢切り替え時の画面確認が必要です。
