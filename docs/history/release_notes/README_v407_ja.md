# SERA v407

## 概要
実機フィードバック「たまに弾きのモーションが回転してしまって、上から振りかぶってムチを打つような動きになることがある」への対応です。発生条件と原因を計測で特定し、弾きの脚の合成方法を差し替えました。

## 何が起きていたか
- 左後脚の弾きで、プレイヤーが右前方の斜め（5m）にいる場合に再現しました。打撃の瞬間、足が股関節より 1.96m 上空を越えて反対側へ振り抜けていました（ムチの正体）。
- 弾きは左前脚のモーションを他脚へ変換したもので、脚の関節角度を「差分方式」から「鏡像方式」へ打撃開始の 0.3 秒でブレンドしています（v400 の足先角度対策）。ところが後脚ではこの2つの方式の姿勢がほぼ正反対で（折り畳んだ足裏同士が 4.2m 離れている）、関節角度の最短経路ブレンドが頭上を回る軌道になり、脚が上から振りかぶる形になっていました。
- 前脚では2方式の差が小さいため起きず、後脚でも狙いの角度が飽和する局面でだけ起きるため「たまに」発生していました。

## 修正
- ブレンド区間（打撃開始 0.3 秒）だけ、脚の合成を足先空間で行うようにしました（scripts/bittaran_foot_ik.gd、補助サンプルを scripts/bittaran_rig.gd に追加）。2方式それぞれの足先位置を直線で結び、膝は両方式の膝の中間を目印に解くため、足は頭上を回らず低い軌道でまっすぐ伸びます。ブレンドの両端（開始=差分方式、終了=鏡像方式）では従来の著者ポーズと一致するので、前後のつながりも保たれます。
- 実測: 同条件で足のピークは股関節の 1.96m 上 → 1.11m（残りは予備動作の折り畳み自体の高さで、打撃開始時点から連続）になり、ホールド位置・到達は従来と一致（小数第6位まで同一のケースを確認）。全脚×全方向のグリッド計測でも頭上を越えるケースはなくなりました。
- v406 の至近距離の短縮（幾何学的な引き戻し）とは同じ解法の仕組みを共有し、両立しています。なぎ払い・踏みつけは変更していません。

## チェック
- 新規 `tools/v407_bittaran_kick_whip_runtime_check.gd`: 上記の再現条件で、打撃〜ホールド中の「足先の股関節からの高さ」が 1.35m 以下であることを検査。修正前 FAIL（1.96m）／修正後 PASS。
- 既存の関連チェック（v396/v399/v400/v401/v402/v403/v404/v405/v406）はすべて PASS のまま。ローカル全件: 静的 182/182・Godot 143/143 PASS（PR の CI でも確認）。

## 既知の制限（従来から）
- 後脚の弾きを正面のプレイヤーへ強制的に発動するような、通常の技選択では選ばれない配置では、肩の照準上限（±100°）のため着弾方向が最大で数十度ずれる場合があります（v403 で明記した制限）。今回の修正で軌道の異常（頭上を回る動き）はそのような配置でも解消しています。
