# SERA v272 — 専用モーションデータから左右蹴りを復元

## 実機で確認した事実
ユーザーのSERA v271のスクリーンショットには **`KICK: CLIP MISSING R EMBEDDED FAILED`** が表示されています。つまり、**右方向の蹴り操作は入力処理を通過していますが、Godot上のリグが右蹴りの再生可能なキーフレームを見つけられず、さらにv271の大きな埋込データからの復元も失敗**しました。

GitHub上の正本 `assets/sera_source.json` には `Kick_l` と `Kick_r` がそれぞれ**22関節、109キー／72キー**で実在し、`assets/sera_data.gd`もGitHub上では同じデータを含みます。したがって「モーション未制作」ではありません。ただし端末上の元データやGodotの内部リグは直接取得できないため、**なぜ旧埋込復元が失敗したかはまだ完全に断定できません**。可能性は、実行時のデータが古い、読み取りに失敗、または読み込み済みモデルの関節UUIDとアニメーションのUUIDが一致しないことです。

## 修正方法
- 新規 `assets/sera_kick_clips.gd`（約46KBのGodotスクリプト）を追加。GitHub正本にある`Kick_l`／`Kick_r`の**元のキーフレームと22関節の名称・UUID**のみを分離して収録します。以前の数百KBの `sera_data.gd` や `sera_source.json` が端末で古くても、**別の新規スクリプト資源から直接読み込める**ようにします。
- `scripts/sera_rig.gd` の起動処理では、通常アニメーションを読み込んだ後、左右蹴りの不足を検査し、この**専用モーション資源を最優先**して補完します。旧埋込データの復元処理は追加の保険として残します。
- 元のUUIDと実行中の骨格UUIDが一致しない場合は、**関節名が一意に一致する場合に限って**モーションキーの対象を合わせます。不明な関節に推測で適用せず、最低8個のキー付き関節が対応することを条件にしています。原本のキーフレーム数値とメッシュ/Pivotは変更しません。
- 正常に再生できるクリップは上書きせず、その他すべてのモーションや装備・通常STEP・バッシュ・格闘3段・入力判定・移動距離・カメラ等も変更しません。
- 読み込めなかった場合は、右蹴りなら `KICK: CLIP MISSING R PACK PARSE ERROR` または `KICK: CLIP MISSING R BONES n/m` のように、**専用資源の復号失敗か関節対応失敗か**をHUD／Godotログで区別します。テキストは今までより短い状態コードを先頭に置きます。
- `main.gd` の再生成功判定（v271）は引き続き維持し、実際のモーションが開始しなければ「蹴り成功」と表示しません。

## 検証
- `tools/v272_dedicated_kick_pack_self_check.py`で、**新しいGodotデータ自体を復号**し、GitHub上の正本クリップと全キーフレーム・関節名・UUIDの完全一致を検査します。
- **旧 `sera_source.json` と旧 `sera_data.gd` の両方にKickが存在しない**仮想ケースを作り、新しい独立資源だけからモーションを復元できることを検証します。
- 実行時関節UUIDが22個すべて異なっても、関節名の一意な一致によって対応できるケース、逆に不適合な骨格への誤適用を拒否するケースを検証します。
- 起動時の読込順序・蹴り要求時の再検査・画面への原因表示をコード検証します。

GitHub Actionsによるこの検証は**静的・データ整合性・模擬検証**です。Android版Godotで実際に描画・再生されたことは、現時点では確認していません。
