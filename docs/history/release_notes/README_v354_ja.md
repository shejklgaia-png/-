# SERA v354 — 見えている脛に前後ロック境界を合わせる

## 原因
v353は初期姿勢の前後脛の中点をモデル座標に保存し、胴体の旋回に合わせて境界を回していました。接地IKは脚を床に残しながら遅れて踏み替えるため、胴体の向きと実際の脛の並びに差が生じます。旧テストも同じ保存座標から期待値を作っており、このずれを検出できませんでした。
また、AUTOはアニメーションで脚を初期姿勢へ戻した後、接地IKを適用する前に選定していました。

## 修正
- 前後それぞれ2本の脛の現在のXZ中点を計測し、両中点の中間面を前後共通の切替境界にします。Yは選定に使用しません。
- 敵の移動・上下揺れ → 接地IK・部位同期 → プレイヤー移動・AUTOの順に揃え、表示と同じ脛の位置で判定します。
- BODY中心へ向く水平2本線、2倍/Y固定の脛選定ボックス、手動ロック、コンボ中のロック保持、ダウン中の頭/胴体解禁を維持します。

## 検証
- `tools/v354_bittaran_live_boundary_runtime_check.gd`は実際の脛Areaから独立に境界を求め、左右両側・往復・旋回・歩行・mainの選定経路と180フレームの実シーン物理更新を検査します。
- v353の角度掃引も、保存姿勢ではなく実際の脛Areaを基準に変更しました。
- Android実機での操作感は未確認です。全件CIの結果はPRに記録します。
