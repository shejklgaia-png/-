# SERA v271 — 「KICK: CLIP MISSING」の実行時クリップ復元

## 確認された不具合
v270の実機HUDで**`KICK: CLIP MISSING`**が表示されました。この表示は、タッチ入力の蹴り方向判定を通過し、`_request_combo_side_kick` から `rig.has_side_kick(side)` を呼んだ結果、**実行中のリグが再生可能な左右蹴りクリップを認識できていない**ことを示します。

GitHub上の `assets/sera_source.json` には、正式名称 `Kick_l`（109キー）、`Kick_r`（72キー）、それぞれ22関節のアニメーションデータが存在します。生成された `assets/sera_data.gd` の埋込JSONも同一で、原本 `models/storage/SERA_BOOSTER_allテスト (9).bbmodel` のキーフレームとの一致は既存テストで確認済みです。

v270以前の `sera_rig.gd` には**別々のモーションデータ取得経路**が存在しました。

1. 起動時に `res://assets/sera_source.json` が存在すると、そこからモデルとアニメーションをロードする。
2. ファイルが存在しない場合に限り、`assets/sera_data.gd` の埋込データをロードする。
3. 原本 `.bbmodel` が端末上に存在すれば追加キックをマージするが、存在しなければ何も補完しない。
4. `has_side_kick()` はクリップ名・長さ・トラックをチェックするのみで、不足した場合も復元を試みない。

したがって、**端末側の `sera_source.json` が古い、またはクリップの実体が空のままの可能性**を従来の静的検査では除外できません。ただし、端末のJSONの実データは直接読めていないため、欠落の直接原因は未確定です。

## v271の修正
- `_build_animations(data)`、必要ならローカルBlockbench `_merge_authored_side_kick_clips()` の後に、**起動時に必ず左右の蹴りクリップを検査**します。元データの名前が存在するだけでなく、**実際にロードされた関節UUIDへ対応するrotation/position/scaleのキーフレームがあるか**まで確認します。
- `Kick_l`／`Kick_r` が無い、長さが異常、または関節キーが空の場合のみ、既存の**生成済みGDScript埋込モデル**（`EMBEDDED.get_json()`）からその左右蹴りデータを再登録します。
- 蹴り実行時の `has_side_kick(side)` も、一度だけ埋込データからの復元を試みます（起動時に検査済みなら追加の解析はしません）。
- 正常なキックは上書きせず、**通常格闘・走り・バッシュ・STEP・鳥足アニメーション・モデルのPivot・装備や他の全モーションは変更しません**。元の左右蹴りキーも編集しません。
- 復元できない場合は既存HUDに `KICK: CLIP MISSING L/R EMBEDDED FAILED` など、左右と埋込復元失敗を識別するメッセージを表示します。Godotログにも警告が残ります。
- **見せかけの蹴り状態を防止**するため、`start_side_kick()` が false を返した場合はSTEP状態を解除し、成功扱いにしません。

## 検証
`tools/v271_embedded_kick_runtime_recovery_self_check.py` では、実際の生成済みbase64からデコードした左右蹴りを解析し、outlinerに属する実在関節と109/72キーの対応を検査します。さらに、**端末側JSONから左右クリップが完全に欠落した例**、および**クリップ名はあるがキーフレームが空の例**を模擬し、埋込データで復元可能であること、他のアニメーションを置換しないことを検証します。

CIで検査するのはソースコード・モデルデータ・分岐の静的整合性です。**v271をGodot Android上で起動した実機でのクリップ復元と描画は未検証**です。
