# SERA v450 — ビットタランが攻撃モーションを1回しか再生しない問題を修正

## 原因
ビットタランの自動戦闘で、初回なぎ払い後に「同じ攻撃種別を連続しない」という制約が有効になると、AIは別の攻撃を出せる位置へ移動するはずでした。しかし従来の回り込みはプレイヤーとの距離を変えず、6.8mでなぎ払いの射程に留まり続けました。歩行条件は満たしていても、次に選ばれる技は直前と同じなぎ払いのため、無限に却下されていました。

## 修正内容
- **同じ攻撃を連続させず、異なる攻撃が実際に可能な射程へ移動**します。最後がなぎ払いなら近づいて弾き／踏みつけ、最後が弾き・踏みつけなら距離を取ってなぎ払い／弾きの判定に移ります。攻撃判定の距離・角度は変更していません。
- **攻撃後に最低3歩を歩く条件を維持**します。反撃可能な位置になっても3歩未満なら攻撃しません。
- **なぎ払い終了時の4脚復帰**：新しいBlockbench原本は足戻しをモーション内で完了するため、その最後の時点でIKにも完了を通知します。直後の2対角脚による踏み直しを、緊急中断処理で飛ばさないようにしました。
- 攻撃最終フレームと歩行への復帰の1フレーム間で、床への接地位置を保存するため胴体を停止します。
- 原本モーション、なぎ払いの再生速度、攻撃判定範囲、回復中の関節長・接地制限は変更していません。

## 自動戦闘の回帰テスト
`tools/bittaran_repeat_live_battle_runtime_check.gd` を追加。強制攻撃命令（`force_start`）を使わず、実際のGodot戦闘シーンを60Hzで進めます。プレイヤーが静止している環境で、最低3歩・攻撃種別の連続禁止・2対角脚の復帰・複数回攻撃を検証します。なぎ払い射程6.8mに加え、近距離1.65mからの遭遇も対象です。

## 検証上の区別
Godot headlessの回帰テストは、攻撃の発生回数と骨格の演算を検証します。Android実機の描画、タッチ入力、FPS、動作の自然さは実機での別確認が必要です。
