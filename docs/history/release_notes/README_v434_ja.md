# SERA v434 — ビットタラン原本再生の基礎を修正・IKを一時停止

## 実装済み

- **原本の回転キーフレームを時刻順にソート**：`scripts/bittaran_rig.gd` の回転・位置チャンネルを独立して整理してからサンプリングします。Blockbenchの「弾き」「踏みつけ」左右でキーフレームが保存順≠時刻順になっており、従来コードは実際の0秒姿勢を誤読していました。
- **原本の線形Euler角補間を再現**：従来のQuaternion最短経路slerpを廃止し、回転X/Y/Zを線形補間してからQuaternionへ変換します。248°以上を使うなぎ払いでも短い裏回り経路を選択しません。
- **原本クリップを直接再生**：`apply_source_clip_exact(name, seconds)` を追加。Bodyと四脚の13関節へ、各クリップの原本位置・回転キーをそのまま適用します。端時刻もループせず評価します。
- **検証モードを標準ON**：`scripts/bittaran_battle.gd` の `BLOCKBENCH_SOURCE_REPLAY_ONLY = true`。攻撃脚・支持脚のIK、IK準備姿勢、追尾による頭部回転、メッシュ個別接地、通常のボディ補正を**再生中は停止**します。ゲーム内にてアニメーションと原本の一致を確かめるための一時的な設定です。
- **モデル全体の初期床配置を一度だけ決定**：セットアップ時はIKによる胴体押し下げ・位置補正を省略。Wait姿勢の足先メッシュの最低点からモデルのルートだけを一度配置し、以後のアニメーションでルートの高さを勝手に変更しません。
- **メッシュを個別にずらさない**：v433で復帰した親子階層を保持。位置・回転は原本の関節から算出されます。

## 検証方法と制限

- `tools/v434_bittaran_blockbench_exact_playback_runtime_check.gd` は、17:21:58同期の `models/storage/ビットタラン (1).bbmodel` を直接読み、別実装のソート・Euler線形補間で参照姿勢を生成。**7クリップすべてについて13関節のキー時刻＋中間時刻**を照合し、攻撃が実シーンでIKに上書きされないことをチェックします。
- `.github/workflows/sera-bittaran-original-replay.yml` は main への push／PR／手動で原本再生テストを実行します。旧IKテストは現段階と互換性がないため、`sera-bittaran-focused.yml` を手動実行専用として残しています。
- 原本にはWaitのBody位置Y=+6.9と、位置キーがない「なぎ払い」「弾き」、踏みつけのY=+5.4が**実際に別々に指定**されています。この状態で原本どおりに再生すれば、**クリップ切り替え時の胴体の高さの差**が残ります。これは再生コードがつくる誤補正ではなく、原本のクリップ間で姿勢・高さが異なるためです。次段階でブレンド・姿勢遷移を設計する前に、各クリップを単独で検証します。
- 今回の原本検証対象はBodyと脚13関節です。原本のRailgun/Rail/Eyeはゲーム内で1つのHeadグループに再構成されているため、頭部はWaitの姿勢に固定しています。これら3グループの厳密な個別再生は、まず13関節の原本再生が正しくなってから扱います。
