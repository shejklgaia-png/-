# SERA v267 — 蹴りの角度をセラ正面基準に修正

## 原因
v266の入力判定は、コントローラーの画面座標に合わせて、**画面上方向を正面**として左右蹴りのセクターを判定していました。ユーザー指定は「**セラ自身の正面を0°として、左右を中心に各90°幅**」なので、セラが画面上方向以外を向くと、体に対して左右の入力が蹴りではなく通常STEPになることがありました。

## v267 操作仕様
- **蹴り方向の基準**：セラが現に向いている正面を画面上に投影した `gesture_screen_forward`。フリック開始時に一度だけ取得し、終了まで同じ軸を保持します。
- **右蹴り `Kick_r`**：セラ正面から時計回り45°～135°の90°セクター。
- **左蹴り `Kick_l`**：セラ正面から反時計回り45°～135°の90°セクター。
- **前方Bash**：従来どおりセラ正面±45°。**後方や他方向**は従来の360°通常STEPとして扱います。
- **コントローラー入力**：画面座標です。上・下・左・右のスワイプは画面上での方向を表し、RUN/BOOST/通常STEPは引き続き `_screen_drag_to_ground` で画面方向をワールド方向へ変換します。蹴りの移動にも同じ計算を用います。
- **蹴りが有効な期間**：3段目完全終了後の0.65秒のコンボ派生受付。短い左右フリックは既存STEP距離（2～4m）・速度・EN・衝突計算を使用。蹴り対象セクターは通常STEPへフォールバックしません。格闘3段目の完走前のSTEPキャンセルも維持します。

## モーションと検証
- v265で統合済みのユーザー制作 `Kick_l`（109キー）・`Kick_r`（72キー）をそのまま再生します。メッシュ・Pivot・元キーフレームは変更せず、判定軸のみを変更します。
- `tools/v267_actor_facing_side_kick_self_check.py` で、セラが画面上下左右へ向いた4例で±45°の左右範囲、実際のリリース時と発動時の同一セラ軸、画面基準のコントローラー／STEP移動、既存Bash・蹴り排他性を静的・数値検査します。
- Android実機の入力操作とモーション表示は未検証です。
