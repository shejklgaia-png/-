# SERA v310 — 右ステップで前ステップの姿勢が再生される問題を修正

## 原因（添付Android動画を参照）
- v309は9.2.2に保存された`Step_R`のキーフレームを正確に取り込んでいましたが、`main.gd`のSTEP開始時/物理フレームで、**画面右入力をセラが敵へ向いている方向に対する相対方向へ変換**していました。セラが敵の側面にいると右フリックが`Frontstep`や`Backstep`との姿勢補間として扱われ、右用モーションが表示されませんでした。
- さらに従来の`_face_locked_boss_with_waist`が、右ステップ用`Step_R`の原本Waist Y回転（約-70°）を打ち消し、**正面を向いた腰姿勢へ変更**していました。

## 修正
- 通常ステップの姿勢判定を**フリックした画面方向**へ統一。画面右では、敵に対する位置/機体の方向にかかわらず`Step_R`を使います。移動中も同一画面方向を維持し、前＝`Frontstep`、左＝`Step_L`、後＝`Backstep`はそのままです。
- 右ステップのWaist回転は原本どおり残し、画面右斜めでは4方向ポーズ補間と同じsmoothstep角度比で徐々に保持します。左・前・後とBOOSTの既存ロック向けWaist補正は維持。
- **プレイヤーの物理ルート`CharacterBody3D`はロック対象へ向いたまま**です。変更するのは表示上のステップ姿勢です。
- 9.2.2原本`Step_R`（19キーフレーム）、他の元モーションや3Dモデルは無変更です。通常STEPのスクリーン基準の3m/5m実移動、EN、蹴り派生、コンボ、衝突、カメラは維持。

## 検査
- 新規Python検査は画面入力→4方向姿勢ルートと原本の維持を監査。
- 新規Godot実行検査はプレイヤーを敵の正面/左右/側面へ配置して右フリック、`Step_R`と原本Waistの姿勢を確認。物理更新後に前姿勢へ切り替わらないこと、ロック・3m進行が維持されることをチェックします。前左右後・斜めの既存テストも実施します。
- Android実機の修正後映像/フリック操作感は未確認です。
