# SERA v353 — ビットタランの前後脚ロック切替を均等化

## 問題と原因

ビットタランの脛4か所を自動ロックする際、前脚から後脚へ切り替わる間隔と、逆に後脚から前脚へ切り替わる間隔が著しく違っていました。SERA v352の2本のロック線は実BODYメッシュの中心を水平に向いていましたが、**候補を選ぶときに手前側の交差点までの距離で全4脚を競わせていたため、前後脚の切替境界は中心になっていませんでした**。

## 対応

- 初期立位の脛選択ボックス4か所から、左右の**前脚2本の中点**と**後脚2本の中点**を計算し、両者のちょうど中間を前後ロック切替の境界にします。
- モデル（BittaranRig）のローカル座標に前後2つの基準点を保存。歩行IK、姿勢変化、ボスの旋回では、前後境界が誤って片方へ移動しません。
- セラが前半分にいるときは前脚2本、後半分なら後脚2本から選定します。前/後どちらへ移動しても**同じ角度・同じ切替位置・切替遅延なし**です。
- 選んだ前後2本の左右判定には既存の2本平行線の選択ボックス交差を引き続き使います。どちらのボックスにも交差しない場合も、同じ前後半面から近い脛を補完します。
- **ビットタランのロック線の終点は変えません。** SERA v352どおりBODYメッシュ中心のX/Zへ向け、Yはセラの高さ固定、2本の間隔は0.5mのままです。
- 4脛の2倍・上下固定ロック選択ボックス、脚の物理・攻撃判定、ダウン中のみ頭/胴体をロック可能な仕様、マニュアルロック、トレーニングルームの共通ロック処理は変更していません。

## 変更箇所

- scripts/bittaran_parts.gd：初期4脛の中点キャリブレーション、ローカル空間の均等な前後半面判定、AUTO前後ペア選択と同一半面フォールバック。
- tools/v352_bittaran_body_center_self_check.py：前バージョンのBODY中心契約を保ちながら現行の選択器へ対応。
- tools/v353_bittaran_symmetric_lock_runtime_check.gd：Godot 4.7.2で左右2側から前/後・後/前を逆方向掃引し、切替角度の一致・境界の等距離・90フレーム歩行と旋回・BODY中心2線とロックボックス維持を検査。
- tools/v353_bittaran_symmetric_lock_self_check.py：中心点と選択ペアに関するコード検査。
- Android実機での動作確認は別途必要です。
