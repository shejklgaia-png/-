# SERA v269 — 画面左右フリックが通常STEPになる問題を修正

## 新しい実機動画による原因確認
Android実機の動画 `1000034692.mp4`（SERA v268、約15秒）をコマ単位で確認しました。**約1.3秒のSTEP RIGHT、5.6秒のSTEP DIAGONAL、10.3秒のSTEP RIGHT** が確認でき、3段コンボ中または直後に `KICK QUEUED`／`KICK RIGHT`／`KICK LEFT` は表示されません。

本作のカメラは横側からセラとボスを映す場面があります。セラが画面左の敵へ向いていると、**画面右へのフリックはセラ自身の「真後ろ」**に分類されます。v267／268は「セラの正面基準の左右90°」にのみ蹴りを割り当てたため、画面左右のコントローラー操作が左右蹴りへ届かず、そのまま通常STEPに流れることがありました。v268で3段目中の予約を導入しても、そもそも蹴り方向と認識されない入力は予約できません。

また、`_update_boost_gesture` はバッシュ候補だけをBOOST抑制条件に入れており、蹴り候補を保持中もBOOST確認が進み得ました。

## 修正
1. `_combo_kick_side_for_flick` を新設し、**蹴りの受付ゲートと実行時の左右選定を同一判定へ統合**。
   - セラ正面から時計回り90°±45°は `Kick_r`、反時計回り90°±45°は `Kick_l`（従来仕様を最優先）。
   - さらに**セラ後方90°セクター**に分類される入力でも、画面左右90°セクターであれば対応する画面右 `Kick_r`／画面左 `Kick_l` を発動します。画面横向きのボス戦で動画の通常STEPへの誤振り分けを解消するための互換受付です。
   - セラ正面の90°セクターは**前方Bashを優先**し、蹴りで奪いません。通常コンボ受付外は画面360°STEPのままで、コントローラーの方向・RUN/BOOST移動ベクトルも変えていません。
2. `_update_boost_gesture` に `side_kick_flick_candidate` を追加。3段目中または完走後の短い蹴りジェスチャー中に、BOOST判定が割り込まないようにします。受付期限後は通常RUN/BOOSTを再開できます。
3. 既存v268の **Melee3最後まで再生→蹴り予約を実行**、0.42秒蹴りフリック、通常STEP同等の2～4m移動、元Blockbench `Kick_l`／`Kick_r` モーション・EN・衝突・カメラを維持します。

## 再発防止
- `tools/v269_screen_kick_video_self_check.py` に今回の動画と同じ **「セラ正面＝画面左、画面右の入力＝セラ後方、ただし画面右の蹴りを希望」** を数値再現し、ほぼ水平の斜めフリックにも対応することを検証します。
- バッシュ・既存のセラ基準蹴り・通常STEPを壊さず、入力開始/リリースで**同じ判定**を使用し、蹴り候補中のBOOSTを抑止することも検証します。
- v264～v268の回帰テストは現在の追加受付を反映させ、従来契約は維持します。

GitHub Actionsの静的／数値テストと、実際のGodot Androidアプリでのタッチ操作・レンダリング検証は別です。**v269の実機テストは未実施**です。
