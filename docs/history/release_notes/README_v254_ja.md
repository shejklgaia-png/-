# SERA v254 — フリック方向を8方向×45°に統一

## 判定区画
画面上の角度を1周360°で**45°×8方向**に分割します。各区画の中心から**±22.5°**が有効範囲です。

| 区画 | 方向 | 中心角度（画面上=0°） | 入力受付 |
| --- | --- | --- | --- |
| 0 | 前 | 0° | 337.5°〜22.5° |
| 1 | 前右 | 45° | 22.5°〜67.5° |
| 2 | 右 | 90° | 67.5°〜112.5° |
| 3 | 後右 | 135° | 112.5°〜157.5° |
| 4 | 後 | 180° | 157.5°〜202.5° |
| 5 | 後左 | 225° | 202.5°〜247.5° |
| 6 | 左 | 270° | 247.5°〜292.5° |
| 7 | 前左 | 315° | 292.5°〜337.5° |

- STEPでは画面上を0°とし、入力角度を区画中心へ**スナップ**してから既存のv252直線移動・モーション再生に渡します。前3m、後4m、横2〜4m、EN/速度、衝突・アニメーションと既存入力優先順位は維持します。
- Bashは画面に映るセラの正面方向を0°として、**前方の45°区画（±22.5°）のみ**有効です。Guard派生・3段コンボ派生ともに共通分類で判定します。ジェスチャー開始時に保存したセラ画面上の正面を使います。
- 今後の方向フリックは必ず `scripts/flick_direction_policy.gd` の区画判定を使用します。行動の基準を画面絶対かキャラ正面か選びますが、45°×8区画という法則は共通です。
- 手動AUTO/MANUALロック切替はボタン方式を維持し、連続RUN/BOOSTドラッグは8方向に制限しません。攻撃・ガード・デバッグジャンプの優先順位も維持します。

## 検証
既存のフリック基礎検査を更新し、8区画・各境界・セラ画面上正面の回転時・Bash正面のみ許容・ステップ方向入力連携の静的／数値テストをGitHub Actionsに追加します。Godot実行とAndroid実機の操作感は未検証です。
