# SERA v255 — Bashの「前」判定をSTEPと一致させる修正

## 原因
v254では、STEPが画面の上方向を前(区画0)、Bashが画面に投影したセラ正面方向を前(区画0)としており、**両操作が違う基準で45°×8区画を判定**していました。セラの向きが画面上で斜め・横・下を向くと、同じ指操作なのにステップとバッシュの「前」が食い違います。

## 修正
- 全てのフリック入力方向を、`_begin_drag`で保存する**画面上のセラ正面**を共通0°として判定します。
- `_classify_step_flick` は `eight_way_direction(displacement, gesture_screen_forward)` を呼ぶよう変更。返却する8方向ベクトルは従来と同じ正規化形式で、実際の前後の移動・モーションはv252仕様を維持します。
- Bashのガード派生・コンボ派生も共通の0番区画を使用し、前方の±22.5°で発動します。速度・距離・時間・キャンセル優先度は変更しません。
- **GUARD長押し**では、タッチ開始からカメラが旋回した後も方向が古いまま残らないように、最後のフリックが始まった時点で表示上の正面を記録し直します。指移動の中間イベントを省略する機種では離指時に記録します。
- 前ステップ3m、後4m、左右2〜4m、装備速度/EN、衝突、3段格闘、カメラ、ロック切替、RUN/BOOST、デバッグジャンプ、モデル・UIには変更ありません。

## 今後の基準
同じ画面に表示されるセラ正面を0°とする45°×8区画を、STEP・Bash・今後追加するすべてのキャラ基準フリック操作に共通使用してください。 `scripts/flick_direction_policy.gd` を唯一の方向判定として利用します。

## 検証
- 画面上でセラが上下左右・斜めを向く場合の各45°区画、ステップ／バッシュの前判定一致、ガード長押しの方向再取得、Android離指イベント省略対応の静的／数値回帰をCIに追加。
- Godot/Android実機での操作挙動は未検証です。
