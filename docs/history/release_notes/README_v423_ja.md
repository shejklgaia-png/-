# SERA v423 — 弾きの照準ヨーが±180°の継ぎ目で反転して脚が裏返る不具合を修正

## 変更方針

脚の照準ヨー（`aim_authored_attack_leg`）の目標値計算を、ラップ済みの要求角をそのままクランプする方式から、**現在のヨーに対して要求角をアンラップしてからクランプする**方式へ変更します。これにより、要求角が±180°の継ぎ目付近にあるとき、tickごとの符号反転でクランプ側が跳ぶことがなくなります。クランプ値（弾き85°／なぎ払い75°）とスルー速度（300°/秒）は従来どおりです。

## 理由と実測

- 後足の弾きで、プレイヤーが脚の付け根の角と反対側のセクターにいる配置（実戦では、構え〜予備動作の間にセラがボスの反対側へ回り込んだ場合に起こり得る）では、照準の要求角が約±175°に張り付きます。伸びていくクリップが基準方向を継ぎ目の向こうへ回し続けるため、ラップ済み要求角の符号がtickごとに反転し、クランプ目標が −85° から +85° へ跳んでいました。ヨーは打撃と保持の最中に170°回転し、脚全体が裏返っていました。
- 実演計測（プレイヤー方位330°で左後脚の弾き／方位30°で右後脚の弾き、左前脚の鏡像と比較）: 修正前は保持時の足裏偏差 6.43m・足の角度誤差 170°。修正後は足裏偏差 0.64m・角度誤差 0°（後足の通常レベル＝fit足裏に対する実メッシュ足裏の既知のオフセット）まで収まりました。他の全方位・全脚の計測結果は修正前と一致しており、影響は継ぎ目付近の配置だけに限られます。
- この配置ではプレイヤーへ脚を向けること自体が幾何学的に不可能（残差はどちら側でも約90°）ですが、少なくとも脚が打撃中に裏返ることはなくなります。

## 検証

- 新規 `tools/v423_bittaran_aim_seam_runtime_check.gd` で、上記の継ぎ目配置3件（左後脚・方位330°／右後脚・方位30°／左後脚・方位300°）を実演し、左前脚の鏡像との足裏偏差1.0m以内・足の角度誤差30°以内を検証します。修正前のコードでは全件失敗することを確認済みです。
- 全件スイート（静的・Godot）で回帰がないことを確認します。Android実機での見た目の確認は未実施です。

## 残る既知の差異（v422から継続・今回は変更しない）

- 後足の伸び切り時の実メッシュ足裏は、鏡像の到達点から約1.29mずれます（判定用にfitされる足裏は正確）。足の角度を曲げて合わせる案は伸び切り傾きが約33.7°（原本約9°）になるため、設計判断として残します。
- 予備動作の折り畳み形状は前後反転した胴体ピッチから吊られるため、折り畳んだ足裏が約0.94m浮く差が残ります。
