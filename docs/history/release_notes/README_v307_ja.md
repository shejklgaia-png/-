# SERA v307 — ステップ方向の姿勢判定をロック方向と一致させる

## 原因
- 右ステップの原本`Step_R`は存在し、`Step_L`、`Frontstep`、`Backstep`と同じ4方向補間処理へ登録済みです。
- しかし、ステップ開始時のポーズ方向は**前フレームの`player.global_transform`**で判定していました。一方、物理フレームでは直後に現行ロック対象へ`player.look_at`し、モーション方向も改めて計算していました。新しいロック対象へ向き直る前にタップされた場合、右フリックに左・後ろ方向のポーズが一瞬選ばれ、その後反転することがありました。

## 修正
- `_step_local_pose_direction`の姿勢方向取得を`_locked_target_facing_direction()`へ変更し、v305のセラのロック向きと統一しました。ロック方向が退避不能な場合に限り、旧`player`の向きを使用します。
- モーション元データと4方向ポーズ、360°補間、入退場時の姿勢ブレンドは変更しません。
- STEPの実移動方向・距離（前左右3m、後5m）、速度・当たり判定・操作、攻撃派生・カメラ・ロック切替挙動も変更しません。

## 検証
- 新規Python静的検査：4種類の原本キーフレームが存在し、ロック基準へ切替わった経路を監査。
- 新規Godot実行検査：あえてセラ本体を逆向きにしてから4方向/斜めを開始。カタナ・通常装備に依存せず、純方向の骨格ポーズが原本クリップと一致するか検査。右STEP開始中の向きの反転と移動ベクトルの保存を確認。
- Android実機での見た目・タッチ操作は未検証です。
