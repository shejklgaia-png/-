# BASE ビジュアル変更 — 実画面レビュー必須（2026-11-22）

> ユーザー指定：「常に画面上の見た目を確認して修正すること」。
> 対象：BASEの施設、床、夜間照明、小物、画面内名称表示、カメラ・配置などの見た目に影響する変更すべて。

## 検査の基本
- **実プレイ画面の基準**：`scenes/base_exploration.tscn` を起動し、デフォルトのBASEカメラ（平行投影38.0、位置 `(21,19.5,25)`、注視点 `(0,2.1,-2.2)`）で、起動オーバーレイが消えた後の720×1280画面を使用する。撮影のためにカメラ、ライト、施設配置を変更しない。
- **変更前に画像を確認**：現行mainのCIスクリーンショットを開き、文字、照明、施設の大きな形、前後の重なり、主役となる機能部、他施設との区別を評価する。見栄えを想像で判断しない。
- **意図した大きな形を優先**：画面縮小時に1施設を1つの特徴で認識できるか。細部を積み増して形が曖昧になる場合は、先に既存パーツを移動・縮小・削除して前景の余白を確保する。
- **必ず実レンダリングで撮り直す**：PRの`.github/workflows/base-roof-visual-preview.yml` が`tools/base_isometric_visual_capture.gd`を実行し、`sera_base_orthographic.png`を成果物に残す。スクショ前に起動完了、BASEカメラ、非GRIDであることを検証する。
- **比較は同一視点・同一サイズで実施**：変更前と変更後の720×1280画像を並べ、必要に応じて8施設を切り抜いたシートを確認する。UI名札・大きな屋根・奥の梁・周囲の小物の重なりをチェックする。初回の再撮影で読みづらければ、マージせず再度モデル修正・撮影を繰り返す。
- **CIは画面を見る代わりにならない**：投影座標や数値テストが通っても奥の物体による遮蔽・細部のつぶれ・色の混同は起こり得る。実画面の目視レビューを別工程として実施する。
- **完了報告**：ゲームの実スクリーンショット、前後比較、具体的な改善点、PR、BASE局所検査とmain全件CIの結果を含める。Android端末上での見え方は実機未確認なら明記する。

## 設計上の不変条件
- 施設8棟の位置・タップ領域・各1枚の床パネル、LABOとNEXUSのモデル倍率、CRATE導線、GRID遷移、既存UIナビゲーションとモバイルGL Compatibilityのバッチ構造を変更しない（別途指定がある場合を除く）。
- デバッグ用UIは表示状態に応じて撮影に含める。正式プレイでは無効となる要素と混同しない。
- UIの名称を正しい位置に出すだけでなく、その背景にある主要機械を実際に目視できること。

この規約は将来のBASE外観変更でも必須。テストでの画面投影値確認に加え、実画像の人間レビューは省略不可。
