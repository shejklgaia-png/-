# SERA NEXUS 全身枠線：エッジ中点判定と細い角度補助線（2026-11-23）

## 背景

PR #808で全消失は解消した。直後のAndroid実機3枚（正面寄り・側面・背面）では、胴体と装甲の黒い線は表示される一方、頭部上辺・左右、肩外側、前腕、武器、背面の腰回り、脚先に輪郭欠けが残っている。正面でうまく出ている線を失ったり、PR #805のような奥側の大量の線を復活させたりしないことを優先する。

## 変更

- `scripts/sera_nexus_outline_geometry.gd`: 既存GPUリボンの各エッジの **メッシュローカル座標での中点**を計算し、`CUSTOM1.xyz` に格納する。1エッジを構成する6頂点に同じ中点を設定する。
- `shaders/sera_nexus_stencil_edge_outline.gdshader`: 隣接面の向き判定に使うカメラベクトルを、各頂点の位置ではなく `CUSTOM1` で渡した**同じエッジ中点**から求める。長いエッジの端点間で輪郭として採用するかが揺れることを軽減する。
- 従来の第一判定（隣接面の前後切り替わり・開放境界）は維持。片面がほぼ横向き（`min(abs(dot)) < 0.12`）、もう片面は十分カメラ方向に傾いている（`max(abs(dot)) > 0.40`）、かつ面同士の角度が鋭い（`dot(nA,nB) < 0.55`）場合のみ、補助輪郭として追加候補にする。これは表裏法線の符号が揺れる装備を局所的に拾うための制限付き判定で、全エッジの復活ではない。
- 補助判定でのみ採用した線は通常3px幅の **62%** の細い線とし、内側の不要なエッジが太く出るリスクを抑える。
- 角の端点補完を最大1.65pxから1.95pxへわずかに延長。補助線は線幅に連動した短い端点補完とする。

## 維持事項

- 正面の通常可視輪郭は従来の3px・色`#0B1118`を維持。
- **GPU標準深度テストを維持**し、奥にある線の遮蔽を優先する。深度テクスチャの手動読み取り・ステンシル合成・追加Viewport・毎フレームCPUの輪郭再計算は導入しない。
- 全29件の表示メッシュ自動登録、装備交換と回転への同一フレーム追従、NEXUS診断19モードの構成は維持。
- NEXUS全身プレビューの本番GPUリボン用シェーダーと専用ジオメトリだけ変更。BASE施設、装備単体、戦闘、クレート、敵は変更しない。共通BASEエッジ抽出コードは編集しない。

## 制約と実機確認

今回の画像から分かるのは、外周の欠けが残っていることまでであり、頭部の欠けがエッジ登録自体によるものか、視点法線・深度によるものかはまだ確定していない。今回の変更は中点の一貫性と狭い角度の補助で改善できる部分を対象とする。実機での表示成功とFPSは未確認。

次の実機確認は (1) 同じ正面・側面・背面で頭部、肩、前腕、武器、脚先の欠けが減ったか、(2) 奥の不要線が復活していないか、(3) 回転時に線が瞬断・遅延しないか。改善がない部位については次回、装備名と角度からジオメトリ抽出対象の漏れを優先して調べる。

ユーザー指定どおり、CI項目の確認・修正・適用、およびCI・動作テストの実行は行わない。

Godot 4.7の Spatial shaders は `CUSTOM1` を受け取る。SurfaceToolは `set_custom_format(1, CUSTOM_RGBA_FLOAT)` の後に `set_custom(1,...)` を設定できる。
