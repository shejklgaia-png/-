# SERA HEAD D / IRIS — 可視独立メッシュ輪郭ID描画 試作

日付：2026-11-22 ／ 状態：**NEXUS単体プレビュー試作（PR #724は統合済み、後続バグ修正あり）**（CI使用不可）

## 目的と適用範囲

CPU比較画像で成立した「外周と独立メッシュ境界のみ／内部の急斜面の角線なし」を、Godot 4.7 GL Compatibility向けに実装する。対象は**NEXUSのアイリス（設計図H02）単体プレビューのみ**。セラ全身、ターゲット、ビットタラン、LAB/倉庫、BASE/NEXUS施設、既存の3px・6pxシェーダーは変更しない。

## 実装

- `scripts/command_nexus.gd`: `CustomizeSinglePartPreview` だけ `enable_nexus_iris_id_contour=true`。他画面の `PartViewer` は既定値false。
- `scripts/sera_part_preview_widget.gd`: `H02`表示時だけ `IrisIDContour` を遅延生成し、画面終了・別パーツ選択時には停止する。共通の3Dプレビュー自体の元材質・カメラ・テクスチャは変更しない。
- `scripts/sera_iris_id_silhouette_preview.gd`: 別`SubViewport`（`own_world_3d`）に**同じメッシュ参照**を持つ6つの簡易`MeshInstance3D`だけを置く。元の各パーツ`global_transform`、表示可否、カメラの投影と位置を同期する。閉メッシュは`cull_front`、開放メッシュは`cull_disabled`で元装甲と一致させる。通常の不透明深度バッファが隠れたメッシュを除外する。
- IDは赤チャンネル`1/8～6/8`、背景0。メッシュ同士の深度・遮蔽はGodotのGPUに任せる。偽の深度や画面上の投影推測は使わない。
- `shaders/sera_iris_mesh_id_outline.gdshader`: 可視IDの差分を**画面上のユークリッド距離**で評価。外周はモデルの内側に3px、メッシュ境界はIDが大きい部品の片側だけ3pxで描画し、6pxの二重線を防ぐ。斜め境界は3pxの不透明芯＋最大0.5pxの微弱なアルファ縁で階段の連続性を改善。元面の急角度や法線には反応しない。
- 旧`SeraEdgeInk`は対象アイリス6メッシュだけ一時的に非表示（Nodeは削除しない）。プレビュー終了で元の表示設定を復元。ゲーム本体の`sera_view_edges.gd`と`sera_face_culling.gd`は変更しない。

## 負荷方針

- 画面上にはH02のプレビューが**1枚だけ**存在。既存のモデル表示はそのまま。追加のGPU ID描画は6メッシュ分のみ。
- カメラ・メッシュの座標・可視状態が変わったときだけ `SubViewport.UPDATE_ONCE` でID画像を更新。静止中はIDの3Dレンダリングを停止。プレビューを閉じると `SubViewport.UPDATE_DISABLED`。
- 追加の輪郭CanvasItemパスはID画像をサンプリング（IDのある画素で理論上最大37テクスチャ参照。背景画素は1回。境界付近は不透明が確定した時点で早期打ち切り）。CPUの画像読み戻しやフレーム毎の幾何エッジ再構築は行わない。
- 別メッシュの数が増えたときは赤チャンネルIDの間隔を再検討する。今回はアイリスの6メッシュ専用であり、汎用パーツ適用は禁止。

## CIなしの検査・制限

1. 手動静的検査：`python3 tools/iris_id_visible_outline_local_check.py`。6メッシュ・2種類の面カリング・3px境界・NEXUS限定・オンデマンド更新・既存シェーダー非改変を確認。
2. オフラインの原本形状レンダラーで、同じ6 ID、深度遮蔽、四方向×3px、片側境界を再現して画像比較。視点2種類とも6メッシュの可視画素を確認した（前者168643画素、後者175410画素）。
3. **Godot 4.7の実レンダリングとAndroid GPU計測は未実施**。この実行環境にGodot本体がなく、ダウンロードもできない。CIが使えない期間はテストを実行できたと誤記しない。
4. マージ前にAndroidのNEXUSでアイリス単体を左右回転し、輪郭の途切れ・描画遅れ・テクスチャの維持・フレームレート・表示終了時の復元を確認する。ゲーム全体への展開はその後に判断する。

**注意：CPU参考画像のブルーグレー面色は比較用の仮配色。ゲーム内では正本16×16の茶色いアイリステクスチャを維持する。**

## 次段階

実機で確認した比較画像により、閾値や色ではなく輪郭の欠落の有無を判断する。GL実描画で6メッシュのうち不可視パーツがある、あるいはカメラ同期が崩れる場合は、この試作ブランチだけを修正し、既存のゲーム表示を巻き戻さない。


## 2026-11-22 実機画面の赤/黒ID露出の修正

- AndroidのNEXUS単体アイリス画面で、赤いデバッグ用メッシュIDと黒背景が表示画面を覆う問題を確認。画面上の元モデル色・グリッドが隠れていた。
- 以前の表示側`TextureRect.texture = id_viewport.get_texture()`は、輪郭CanvasItemのコンパイルに失敗すると、赤/黒の生ID画像をそのまま見せてしまう危険な構成だった。さらに`fragment()`で早期`return;`を使用していたが、Godotシェーダーの組み込みエントリからのreturnは未定義動作/エラーの対象となる。
- 新構成は表示`TextureRect`に**透明な1x1画像だけ**を割り当てる。ID用SubViewportTextureはCanvasItemシェーダーの`uniform sampler2D mesh_id_texture`にのみ渡し、内部では輪郭画素にだけ不透明な`#17212F`を出力する。輪郭以外は常にalpha=0。万一シェーダーが使えなくても、表示側は透明1x1のまま、元の3Dプレビューを覆わない。
- `fragment()`の早期`return;`を廃止し、常に`COLOR`を一度だけ確定させる。サンプル間隔は表示用1x1画像ではなく、ID用`SubViewport.size`から算出する。カメラ回転・モデル/画面サイズ変更時のみIDを更新する設計を維持。
- 適用範囲：NEXUSのHEAD D単体だけ。原本16x16テクスチャ、セラ本体・敵・BASE施設・LAB/倉庫の表示とシェーダーは変更なし。
- **検証：CIなし。** GitHubコード上の手動静的検査10項目は通過したが、Godot実機で新シェーダーのコンパイルと輪郭表示は未確認。次のAndroid試験で赤/黒背景の不在、茶色いアイリス、細い可視輪郭、ドラッグ回転時の追従を確認する。

## 2026-11-22：NEXUSアイリス3px幅の再調整・負荷診断

- 旧方式：上下左右の距離1/2/3を調べる菱形（マンハッタン距離）の境界膨張。斜めの部分で3px相当の距離を確保できず、段差が途切れたように見える場合があった。
- 改善方式：ID画像の**異なる可視メッシュID／背景**までの2Dユークリッド距離を調べ、距離3.0px以下を不透明、3.0～3.5pxはアルファで補間。外周は部品の内側だけ、内部接合線は高ID側だけに適用。レンズの3D法線や元の茶色い材質は変更しない。
- 画像サンプリングは `filter_nearest` のまま。IDテクスチャをぼかしたり補間で別IDを生成しない。IDターゲットの縦横は表示プレビューControlのピクセル寸法へ合わせ、モーダルのサイズ変更後も3pxの基準を維持（アスペクト比が一時的に不一致の場合のみ、投影を優先してソースサイズへフォールバック）。
- パフォーマンス：追加の3Dパスはプレビュー変更時のみ、メッシュ最大6個。CanvasItemは1パス／フレームのまま。境界シェーダーの理論上のIDサンプル数は背景1回・モデル内部最大37回（旧は背景1回・モデル内部最大13回）へ増加。境界付近は3px不透明芯に達した時点で打ち切る。これは**理論値**で、Android実測GPU時間ではない。
- `get_outline_metrics()` で `visible_mesh_id_draws_per_refresh`、`id_target_pixels`、`id_redraw_requests`、`estimated_max_id_samples_per_ink_pixel`、`last_cpu_sync_us`を取得できる。CPU同期時間とGPU描画時間は別指標。静止時にはID再描画が増えないことを確認する。
- **GitHub Actions/CI不使用**。数値参照テストでは、垂直境界の3px、隣接メッシュ境界の片側のみの3px、45°線の途切れなしを確認。Godot 4.7シェーダーコンパイル／Android実画面・FPSは未確認のため、NEXUSでアイリスを回転して実機確認が必要。
