# SERA HEAD D / IRIS — 可視独立メッシュ輪郭ID描画 試作

日付：2026-11-22 ／ 状態：**未マージのNEXUS単体プレビュー試作**（CI使用不可）

## 目的と適用範囲

CPU比較画像で成立した「外周と独立メッシュ境界のみ／内部の急斜面の角線なし」を、Godot 4.7 GL Compatibility向けに実装する。対象は**NEXUSのアイリス（設計図H02）単体プレビューのみ**。セラ全身、ターゲット、ビットタラン、LAB/倉庫、BASE/NEXUS施設、既存の3px・6pxシェーダーは変更しない。

## 実装

- `scripts/command_nexus.gd`: `CustomizeSinglePartPreview` だけ `enable_nexus_iris_id_contour=true`。他画面の `PartViewer` は既定値false。
- `scripts/sera_part_preview_widget.gd`: `H02`表示時だけ `IrisIDContour` を遅延生成し、画面終了・別パーツ選択時には停止する。共通の3Dプレビュー自体の元材質・カメラ・テクスチャは変更しない。
- `scripts/sera_iris_id_silhouette_preview.gd`: 別`SubViewport`（`own_world_3d`）に**同じメッシュ参照**を持つ6つの簡易`MeshInstance3D`だけを置く。元の各パーツ`global_transform`、表示可否、カメラの投影と位置を同期する。閉メッシュは`cull_front`、開放メッシュは`cull_disabled`で元装甲と一致させる。通常の不透明深度バッファが隠れたメッシュを除外する。
- IDは赤チャンネル`1/8～6/8`、背景0。メッシュ同士の深度・遮蔽はGodotのGPUに任せる。偽の深度や画面上の投影推測は使わない。
- `shaders/sera_iris_mesh_id_outline.gdshader`: 色IDの差分を四方向×1～3pxで比較。外周は**モデルの内側に3px**、メッシュ境界は片側だけ3pxとし、両側6pxになることを防ぐ。色は既定の`#17212F`。元面内部の凸角・凹角・法線角度には反応しない。
- 旧`SeraEdgeInk`は対象アイリス6メッシュだけ一時的に非表示（Nodeは削除しない）。プレビュー終了で元の表示設定を復元。ゲーム本体の`sera_view_edges.gd`と`sera_face_culling.gd`は変更しない。

## 負荷方針

- 画面上にはH02のプレビューが**1枚だけ**存在。既存のモデル表示はそのまま。追加のGPU ID描画は6メッシュ分のみ。
- カメラ・メッシュの座標・可視状態が変わったときだけ `SubViewport.UPDATE_ONCE` でID画像を更新。静止中はIDの3Dレンダリングを停止。プレビューを閉じると `SubViewport.UPDATE_DISABLED`。
- 追加の輪郭CanvasItemパスはID画像をサンプリング（各可視画素最大13テクスチャ参照）。CPUの画像読み戻しやフレーム毎の幾何エッジ再構築は行わない。
- 別メッシュの数が増えたときは赤チャンネルIDの間隔を再検討する。今回はアイリスの6メッシュ専用であり、汎用パーツ適用は禁止。

## CIなしの検査・制限

1. 手動静的検査：`python3 tools/iris_id_visible_outline_local_check.py`。6メッシュ・2種類の面カリング・3px境界・NEXUS限定・オンデマンド更新・既存シェーダー非改変を確認。
2. オフラインの原本形状レンダラーで、同じ6 ID、深度遮蔽、四方向×3px、片側境界を再現して画像比較。視点2種類とも6メッシュの可視画素を確認した（前者168643画素、後者175410画素）。
3. **Godot 4.7の実レンダリングとAndroid GPU計測は未実施**。この実行環境にGodot本体がなく、ダウンロードもできない。CIが使えない期間はテストを実行できたと誤記しない。
4. マージ前にAndroidのNEXUSでアイリス単体を左右回転し、輪郭の途切れ・描画遅れ・テクスチャの維持・フレームレート・表示終了時の復元を確認する。ゲーム全体への展開はその後に判断する。

**注意：CPU参考画像のブルーグレー面色は比較用の仮配色。ゲーム内では正本16×16の茶色いアイリステクスチャを維持する。**

## 次段階

実機で確認した比較画像により、閾値や色ではなく輪郭の欠落の有無を判断する。GL実描画で6メッシュのうち不可視パーツがある、あるいはカメラ同期が崩れる場合は、この試作ブランチだけを修正し、既存のゲーム表示を巻き戻さない。
