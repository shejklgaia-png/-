# NEXUS新GPUエッジ：ステンシル有無の比較診断（2026-11-23）

## 背景

PR #802 のAndroid実機画面では、新しい **全身マスク＋GPUエッジ** 方式でも通常のNEXUS全身輪郭がほぼ消失していた。従来の「法線＋8px」「法線－8px」は反転ハルの診断であり、**新GPUエッジシェーダーそのものが正しく描画されているか**は未確認だった。

## 今回の変更

- 既存の `sera_nexus_stencil_edge_outline.gdshader` を複製し、`stencil_mode read, compare_not_equal, 17;` の行**だけを削除**した `sera_nexus_stencil_edge_outline_no_mask.gdshader` を追加する。頂点投影、3pxのエッジリボン、端点処理、render_mode、透過描画は元のシェーダーと同じ。
- NEXUSの「輪郭診断」にモード **16「マスクなし外周」** を追加。エッジ用Controllerはこのモードでマスクなしシェーダーの専用Materialへ切り替え、**同じ青緑色・3px**で表示。
- ステンシル用Controllerはモード16で**ステンシル書き込み用メッシュも、旧反転ハルも非表示**とする。これで今回の診断中は新シェーダーの投影リボンのみが残る。
- 現在のモード9「合成確認」と、同一姿勢で比較する。モード9は全身ステンシル17の書込み＋ `compare_not_equal` で内部画素を消し、モード16ではその処理を完全に外す。
- 診断を閉じると従来どおりモード0へ戻り、本番の外周描画（ステンシルあり）を維持する。キャラクター枠線ON/OFF設定と既存16モードは維持する。

## 比較と解釈

| 結果 | 優先的に疑う箇所 |
|---|---|
| モード16で青緑の全エッジが出る／9で消える | ステンシルのマスク範囲・比較・描画順 |
| モード16でも全エッジが消える | 新リボンシェーダー、投影・表示設定、マテリアル |
| 16と9の両方で見えるが輪郭不正確 | マスク範囲とエッジ候補の位置関係、外周3px生成 |

モード16で出るのは**マスクを外した全トポロジエッジ**であり、完成した外周シルエットではない。内部線が大量に出ても診断としては正常。両モードの表示差がなくても、ステンシル処理の機能不全と断定できず、描画パスをさらに調べる必要がある。

## 変更範囲・制約

NEXUS全身プレビューの診断UIとシェーダー切替のみ。通常外周の生成方式、色 `#0B1118`、3px、装備自動登録、単体プレビュー、戦闘、BASE施設などは変更しない。

Android実機での新診断表示・パフォーマンスは未確認。ユーザーの運用ルールに従い、CI項目の確認・変更・適用およびテスト実行は行わない。
