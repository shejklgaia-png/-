# SERA NEXUS：ステンシルから不透明深度による外周クリップへ切替（2026-11-23）

## 実機診断結果と問題

PR #803 で「マスクなし外周」にGPUエッジの全線が青緑で描画されたのに対し、「合成確認」ではほぼ消失していた。PR #804 の追加実機画像では **17一致（マスク書込ON）は全身エッジが緑、書込停止≠17は全身エッジが紫** となり、リボン生成やGPUの追従自体ではなく、ステンシルの内外判定後に外側の線が残らないことが明確になった。

単純な輪郭線の幅や法線の符号・カリングの再調整は繰り返さない。SERAはGodot 4.7 GL Compatibilityで実行される。Compatibilityレンダラーは **深度テクスチャをサポート**するため、透明パスで原本の不透明装甲の深度情報とGPUエッジリボンの深度を比較し、全身マスクに頼らず可視最外周へ絞り込む。

## 新しい通常表示（モード0/1/9）

- 従来と同じ `SeraLiveMeshEdges` のGPUエッジリボン（画面上3px、端点補正あり）を使用し、**別カメラ／別Viewport／GPU→CPU読み出しは追加しない**。元メッシュの子なので装備・関節・回転に同一フレームで追従する。
- `sera_nexus_stencil_edge_outline.gdshader` の通常描画から `stencil_mode read, compare_not_equal, 17` を除去。代わりに `uniform sampler2D scene_depth : hint_depth_texture, repeat_disable, filter_nearest;` を使い、透明パスの各エッジ画素から一回だけ深度をサンプリングする。
- **互換（OpenGL）**では深度が遠いほど大きいので、`opaque_depth <= FRAGCOORD.z + 0.00004` の画素を棄却する。つまり、装甲の内側・別パーツの前面に隠れた線・表面の線は除外し、モデルの不透明面より手前へ出た外周候補だけを描く。
- **Forward+/Mobile**の逆Z深度を考慮し、`CLIP_SPACE_FAR` から比較方向を切り替える。現行の対象環境はCompatibility。
- 通常の色は `#0B1118`、外側線幅は3px目標。モード1「外周候補」と9「合成確認」は同じ深度方式を青緑で描画する。
- 不透明装甲・武器だけを対象とする。煙・レーザーなどの透明FXは既存の自動除外条件を維持する。奥に別の3D物体があると深度比較の対象に含まれるため、常にその背後でも線が見えるX-ray表現ではない。

## GPU負荷・旧コード管理

- **通常表示ではステンシルマスクも平滑化反転ハルも不要**。旧 `SeraStencilHull` は、旧方式の診断対象（6/7/8/12〜15/17）をユーザーが選んだときだけ装備メッシュを複製・キャッシュし、通常へ戻る際は解放する。
- これにより通常時の旧ステンシル／ハル計58複製メッシュの保持・更新（うち描画されていたのはマスク側）を避ける。GPUの深度参照が必要となるため、実機FPSを未測定のまま速度改善を断定しない。
- 既存の19診断モードを残す。モード16は「深度なし全エッジ」（青緑・3px）として残し、通常の深度外周との同じ姿勢での比較に使える。モード17/18は**旧ステンシル方式の検証専用**と明示。
- 通常表示の診断統計は「不透明深度」、旧マスク統計は「診断専用」と表示。通常時は旧複製メッシュを生成していないため旧マスク数が0でも正常。

## 制約・引き続き確認する内容

この方式は **全身3D不透明深度に対するエッジ候補の画素単位判定**であり、全身シルエット画像を厳密に3px膨張する2Dモルフォロジー処理ではない。密着する面、極薄メッシュ、近い奥行きの装甲、背景3D物体との距離、MSAA、GPUの深度精度では局所的な線の欠落や表示誤差の可能性がある。深度の微小許容値は `depth_bias = 0.00004` から調整可能なUniformとする。

Godot 4.7・Xperia 1 Vの実機での表示と負荷は**未確認**。これまでの「正常」と断言した報告を踏まえ、実機確認前に直ったと判断しない。NEXUS全身プレビューのみを変更し、単体パーツ、戦闘、BASE、クレート、敵の描画は変更しない。

ユーザーの指定に従い、CI項目の確認・修正・適用、およびテスト実施を行わない。
