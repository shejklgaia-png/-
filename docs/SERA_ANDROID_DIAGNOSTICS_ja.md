# SERA v317 — Xperia実機診断の手順

## トレーニングでの操作
1. 画面上部のデバッグボタン列にある **DIAG: OFF** をタップしてONにします。診断パネルが表示されます。
2. カメラのカクつき、ステップ方向、モーションの誤り、ロック切替などを再現します。約0.12秒ごとの短い記録を最大500件保持します。
3. **COPY LOG** をタップします。端末のクリップボードへタブ区切りログをコピーします。ChatGPTに貼り付けて原因調査を依頼できます。必要に応じて再現動画やスクリーンショットも添付してください。
4. **DIAG: ON** をもう一度タップするとOFFになり、サンプリングとパネル描画が止まります。

収集項目: 時刻、FPS、現在のアニメーション名、戦闘状態番号、ロック部位ID、カメラYaw・追従半径・位置追従遅延m、STEP実走行距離m、方向入力X/Y、BOOST状態、EN量。

**プライバシーと安全:** 記録は端末内メモリのみ。COPY操作を行わなければクリップボードへ渡しません。ログファイル、外部送信、自動アップロードは行いません。診断ONはトレーニング画面を開き直すとOFFに戻ります。普段のプレイはOFFを推奨します。

## 開発者用CI棚卸し
`python3 tools/sera_ci_inventory.py --json`: 登録数、完全一致するテストソース、未登録候補、過去計測データを表示。重複候補の**推測による削除はしません**。ランタイム実機テストはCIと別です。

## LABフォント診断（v545）

**開き方（Android実機／Godotエディタ内のいずれも対応）**
1. 拠点のLABからEQUIPMENT／REFINERY／STORAGEのいずれかを開きます。
2. 画面見出し（例：「装備製作」）を1.7秒以内に5回タップすると、見出し横に従来の「診断」と「FONT」ボタンが出ます。
3. 「FONT」で専用の診断パネルを開きます。RESCANで再計測し、COPY LOGでログ全文をコピーできます。CLOSEで閉じます。
4. 表示されたLIVE SAMPLESの6行が同じ太さ・書体に見えるか、日本語が□になるかを確認し、スクリーンショットとCOPY LOGのテキストを共有します。Godotの出力ログにも SERA_FONT_DIAG_BEGIN／END で診断結果が出ます。
5. 見出しを再度5回タップすると診断用ボタンを非表示にできます。

**計測内容**
- Godotバージョン、OS、言語、DisplayServer、システムフォント名一覧の抜粋。
- 日本語本文・見出し・操作文字・ステータス・英語タブ・等幅IDの6系統について、指定候補、ウェイト、OS候補パス、TextServer RIDのフォント名。
- 英字A・日・漢・カの Font.has_char 対応情報と、6系統の日本語／英語／数字の表示サンプル。
- フォントパスはOSの候補であり、実際にレンダリングされた書体と同一とは限りません。文字対応もピクセル描画成功を保証しません。必ずLIVE SAMPLESと突き合わせてください。
- Godot 4.7のSystemFont公式ドキュメントではAndroidは実装対象外で、デフォルトテーマ書体へのフォールバックとなることが記載されています。現時点ではAndroid実機で何が選ばれたかは未確認です。
- 診断パネルはタップ時に一度だけ生成し、再スキャンも手動操作時だけ行います。フォント用の外部ファイルは追加していません。
