# SERA — ChatGPT単独開発のための安全な高速化（2026-11-11）

## 今回の範囲
ユーザーが求める「ChatGPTが調査、実装、テスト、GitHub管理を一貫して担当する」方式に合わせて、**実行時の振る舞いを変えない開発用自動監査**を追加しました。現行コード・実機の挙動を正として、事実と推測を分けます。

### 追加した自動ツール

| ツール | 目的 | 使い方 |
| --- | --- | --- |
| `tools/sera_parameter_audit.py` | RUN/BOOSTの入力判定とHUD表示にある重複定数の一致、ヒステリシスの順序、実際の使用箇所を検査 | `python3 tools/sera_parameter_audit.py --json` |
| `tools/sera_change_impact.py` | GDScriptの静的な読込依存、被参照元、関連する既存テストを一覧化 | `python3 tools/sera_change_impact.py --changed scripts/main.gd --json` |
| `tools/sera_agent_audits_self_check.py` | 上の監査が不一致を検出すること自体を検証 | CIから実行 |

既存の `sera_code_map.py` は「関数・定数の場所」を検索し、`sera_change_impact.py` は「参照先・影響範囲・候補テスト」を補足します。

### ChatGPTが指示を受けた時の実施順
1. 最新 `main` と公開中のPRを確認して、対象機能の状態を調べる。
2. `sera_code_map.py` と `sera_change_impact.py` で変更範囲を限定。機械的に特定できない動的な呼び出しは別途追う。
3. RUN/BOOST寸法関連なら `sera_parameter_audit.py` を必ず実行する。
4. 対象機能の既存回帰テスト・全体CIを通してからマージ。**CI成功＝Android実機で正常**とは扱わない。
5. 作業の終わりに変更点・未検証事項を記録する。テスト失敗、未解決競合、予期しない差分の時はマージしない。

### 大きいスクリプトの扱い
スクリプトの行数だけを理由に全面分割しません。依存が明確な純粋計算や定数を個別に分けるとしても、変更前後の検査が作成できた箇所から1単位ずつ移行します。`main.gd`、カメラ、入力、リグはランタイムの結合が強いため、この監査レポートだけで独立性を断定しません。

### パラメーター共通化の段階
現段階では **RUN/BOOSTの定数を移動せず、一致を自動検査**します。これにより、表示と判定の値が片方だけ変更された状態でCIを通すことを防ぎます。実際の単一設定ファイルへの移行は、既存のバージョン別検査が定数宣言の文字列を参照しているため、ゲーム側の挙動と検査を同時に保護できる段階で行います。

### デバッグ診断の段階
現時点ではゲーム内に常時表示される新規デバッグUI、ログ書き込み、背景処理は入れません。原因不明のカメラ振動・モーション異常については、将来 **開発時のみ有効な軽量ログ**（カメラ位置・目標位置・補間率・モーション名・FPSなど）を用意し、Android実機で表示と入力が変わらないことを確認してから導入する方針です。

### 安全の境界
- この変更では `scripts/`、`project.godot`、`scenes/`、`assets/`、モデル、シェーダー、音声は編集しません。ゲーム版は進めません。
- 外部サービス・別ジョブ・有料の監視機能は増設しません。
- CIに検査時間は少量追加されます。固定数値をゲームバランスの「望ましい値」として扱わず、**既存の入力/表示の整合**のみ検査します。
