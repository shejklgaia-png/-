# NEXUS ステンシル反転ハルの深度・押し出し修正（2026-11-23）

## 背景

ユーザーのAndroid GL Compatibility実機の14種類の輪郭診断では、NEXUSの対象メッシュ29/29の登録は成立し、「マスク表示」では全身の書込みパスが表示された。一方、従来の「ハル単独」ではほぼ全面が紫色で、合成後の輪郭はほとんど見えなかった。「全身＝」モードでは複数部位の一致が確認された。「立方体＝」「立方体≠」の両方で対象画素が出たが、参照値比較がすべての画素で正しいことまでは未確認。

Godotのspatialシェーダーの通常の深度テストは、既に描画された装甲の**奥側にある反転ハル裏面を捨てる**。この深度テストと `cull_front` の組み合わせが、通常表示におけるほぼ全面の枠線消失を説明できる。反転ハルの描画では、モデル全身の共通ステンシル値17で本体内側を除去するので、同じ不透明深度を重ねて使う必要はない。

## 対応

1. 全身ステンシル書込みシェーダーを `depth_test_disabled` にし、他パーツの既存不透明深度に関係なく、**画面上の全身の投影領域（共通マスク）**へ値17を書き込む。透明パス、描画優先度-22、`cull_disabled`、元装甲非改変を維持。
2. 反転ハル側も `depth_test_disabled` とし、元装甲の深度で裏面を棄却しないように変更する。代わりに透明パスのステンシル `compare_not_equal, 17` で全身マスクと重なる領域を消す。優先度-21、`cull_front`、3px、`#0B1118`を維持。
3. 反転ハルの法線は以前から生成されていた平滑化専用法線を使用。押し出しの画面方向を実際の `VIEWPORT_SIZE` で正規化してから、NDCへ戻す。縦長画面で角度ごとの線幅が不均等になる要因を減らす。
4. 「マスク表示」「全身＝」「ハル単独」「面反転」の診断シェーダーも通常描画と同じ深度条件・投影方法に揃える。診断モードの意味はそのまま維持する。

## 制約と確認事項

- Godot 4.7 のステンシル機能は実験的。シェーダー設定は実装したが、Xperia 1 V実機で3pxの最外周が正常描画されるかは未確認。
- この方式は画面内で全身を1つのステンシル領域にまとめ、後ろ向きの膨張メッシュの外側だけを残す。**通常の深度テストを無効化したため、別の前景オブジェクトがセラを隠す場面では輪郭がその前景より手前に出ることがある。** 今回はNEXUSの独立プレビューにのみ適用し、戦闘には展開しない。
- シルエットが歪む場合には、平滑化法線が各装甲の外向きか、薄い板の表裏法線が打ち消し合わないか、マスク／ハルの描画順が安定しているかを次に確認する。
- ステンシル比較が成立せず内側が塗られる場合、今回の対処のみでは完成にならない。その場合は実機の再診断結果からレンダリング制約を切り分ける。
- 輪郭以外のNEXUS UIや装備設定、単体プレビュー、BASE施設、戦闘は変更しない。
- ユーザー指示に従いCI項目確認・修正・適用およびテスト実行は行わない。

参考: Godot公式 Spatial shaders (`depth_test_default` / `depth_test_disabled`, stencil readは透明パス限定), StandardMaterial3DのStencil/Next Pass項、Godot ShadersのStencil-based silhouette。
