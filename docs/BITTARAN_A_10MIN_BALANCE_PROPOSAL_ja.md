## 2. 実モーション時間とダウンの有限性

### セラ全A

- Blockbench `models/core/Standard.bbmodel` のクリップ長：`melee1=0.50s`、`Melee2=0.50s`、`Melee3=0.83333s`。初段と2段目はユーザー入力が間に合えば各`7/24=約0.292s`で次段へ移行できる。
- ヒットストップは命中ごと`0.060s`。3段目は通常最後まで再生する。初段の接近予備と追尾・入力待ちを含めた、実用的な3段攻撃サイクルは**約1.7～2.0秒**を見込むが、実機計測値ではない。
- 通常3段とカタナ2段は別モーション。ここでの10分試算は**Aの標準3段武器**に限定する。

### ビットタラン

- 通常の脚破壊：前置き`0.60s`＋ダウン内`2.10s`時点で起き上がり開始＋起き上がり`1.00s`＝**約3.70s**。
- 4本目を破壊：前置き`0.60s`＋ダウン内`5.40s`時点で起き上がり開始＋起き上がり`1.30s`＝**約7.30s**。
- 実際に地面に頭部が下がり、近接攻撃が届く時間は短い。参考値として**通常約1.9秒、4本目約5.2秒**を用いるが、歩行位置・追尾・モデル接触によって短くなる。
- したがって**通常ダウンでは頭部3段コンボ約1回、4本目は約2～3回が現実的な上限候補**。4本の脚破壊は各1回限りなので、頭部への高倍率攻撃のチャンスも限定される。
- 現在のビットタランは下がった頭部をAUTOロックするが、ダウン開始直後は頭が高い。ロック可能時間と実際に近接攻撃できる時間を同一視しない。

## 3. 検証用の部位・本体ダメージモデル

`raw_attack` を武器＋装備補正で算出し、敵予測シールドで減衰した後に、部位ごとの防御と以下の**本体HP専用倍率**を適用する構想。

- **脚（破壊前も破壊後も）0.75倍**
- **頭部2.50倍**（頭部の部位耐久を破壊した後も、ダウン中は攻撃対象として残し倍率を維持）
- **胴体1.00倍**
- 部位耐久への破壊値は本体HP倍率と完全に分離し、現行の部位破壊防御のみ適用する。
- 各脚の `broken` は一度`true`になったら討伐まで解除しない。耐久0のまま、**同一脚から再度の破壊イベント・ダウン・報酬は発生しない**。再標的化可能かどうかと再破壊可能かどうかは別の条件で管理する。
- 頭部を破壊しても本体HPが残っている間はダウン中の高倍率部位として攻撃可能にする。現行の `is_targetable` は`broken`時に部位ロックを外すので、**そのままでは実現しない**。
- 全4脚破壊後に足への攻撃を続けなくて済むよう、**胴体を常時ロック・攻撃可能**にする（ただし第5の破壊ゲージは新設しない）。現行の胴体ロックはダウン中に限定されるので、これも実装変更が必要。

### Aの部位耐久が成立する理由

A標準武器の3段の破壊値は`14+14+32=60`。

- 前脚：破壊防御0%、`720÷60=12`コンボ。
- 後脚：破壊防御12%、`620÷(60×0.88)≒11.74` → **12コンボ**。
- 頭部：破壊防御10%、`150÷(60×0.90)≒2.78` → **3コンボ**。

**注意：最後の長時間ダウンだけで頭部3コンボを必ず入れられるとは限りません。** 前回の会話にあった「最後のダウンだけで頭を破壊できる」という説明は、頭部耐久150・有効時間約5.2秒の前提では保証できないため採用しません。最終ダウン単独でも頭部破壊を保証したい場合は、`頭部耐久100前後`または頭部攻撃可能時間の延長を別案として検証すること。

## 4. 約10分を狙うための時間配分（計算上の仮説）

**仮定：** 平常時の3段コンボ成功間隔を平均約8秒とし、脚4本の破壊に合計48コンボを要する。ダウン中の頭部攻撃はその空き時間に最大5コンボ程度成功し、残りは胴体攻撃へ移行する。

| 段階 | 目標時刻・目安 | 意味 |
| --- | --- | --- |
| 1本目破壊 | 約1分30秒 | 初回ダウンで頭部攻撃 |
| 2本目破壊 | 約3分 | 頭部攻撃2回目の機会 |
| 3本目破壊 | 約4分40秒 | 頭部攻撃3回目の機会 |
| 4本目破壊 | 約6分20秒 | 長時間ダウン、頭部を集中的に攻撃 |
| 最終討伐 | **約10分** | 常時解放された胴体に残HP分を与える |

この時間は**モーションを含めた仮説上のペース配分**であり、Godot実戦のシミュレーション結果ではない。直前の会話で示した「約10分02秒」「頭部ヒット0回で約11分46秒」などは、簡易モデルに依存する**参考試算**としてのみ扱い、独立した再現ログ・実機ログがない限り確定仕様／CIの期待値にしない。

本体HP`2600`はこの約8秒成功間隔・約5回の頭部コンボを前提にした暫定値。プレイヤーの成功間隔が7秒／9秒なら討伐時間も変わる。**本体HPは実測の成功間隔と実際の頭部命中数から最後に決定する**。

## 5. 10分戦での生存バランス

Aの最大HPを320、防御16%とした際の候補値：
- 踏みつけ30 → 実ダメージ25.2
- なぎ払い28 → 実ダメージ23.52
- 弾き22 → 実ダメージ18.48
- 腹部砲5.04 → 実ダメージ約4.23
- レールガン8.1 → 実ダメージ約6.80/接触。現行の**0.20秒ごとの再命中**ルールと、守備・ノックバック処理の実際の影響を別途検証する。

HP320、回復手段なしで10分戦うため、基礎ダメージだけで難度を確定しない。**攻撃回数、被弾率、ガードでのEN/SH消費、レールガンの連続ヒット、KO率**を測る。ガードを悪用した無限防御や被弾による操作不能の連続も確認する。

## 6. 要実装・要検証のタスク順序

1. **計測先行（実装前）：** 現行Aの「3段開始→全段命中→次の攻撃開始」の実時間、命中率、部位ごとの命中可否、ビットタラン各攻撃の実際の隙、ダウン1回当たり頭部コンボ数、10分間の被弾率をGodotで計測。
2. **仕様期待値とテストを先行編集：** ユーザーが数値を正式採用した時点で既存の部位破壊・ダウン・武器・装備・攻撃ダメージCIと仕様正本を確認し、**本体実装前に**新期待値をテストへ反映。破壊済み脚の再破壊禁止、頭部破壊後の再ロック許可、4脚後の胴体ロックを個別に検査。
3. **戦闘ロジック：** 頭/脚/胴体の本体HP倍率、脚破壊の1回性、頭部ロック・既破壊脚ロック・4脚後の胴体ロックを整理。新規破壊イベント／報酬は初回のみ。既存のダウンIK・ユーザー作成アニメーション原本を勝手に修正しない。
4. **実戦試験：** A全身・標準ブレード・GRID戦闘補正なし。討伐時間の中央値10分を目標に、複数回の試行・脚4本と頭部の破壊成功率・実被弾数・ガード使用量を確認。平均だけでなく範囲も記録。
5. **再バランス：** B・D・軽量頭部/鳥脚・カタナ2段を同じビットタランに当て、特に重装の高火力による部位破壊前討伐や、カタナの実DPS不足を修正。
6. **GRID最後：** 戦闘基準が固まってから出撃中補正（攻撃＋6%、破壊＋10%、HP＋8%、装甲−6%、機動＋5%、EN回復＋10%）を再査定。計算だけでなく「何コンボ短縮するか」で確認。
