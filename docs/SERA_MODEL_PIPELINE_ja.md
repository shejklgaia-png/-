# SERA — v316 自動生成・CI計測運用（2026-11-13）

## Blockbenchデータの更新
正式な編集元は `models/manifest.json` 内の6つの.bbmodelです。

```sh
python3 tools/sera_model_build.py --check
python3 tools/sera_model_build.py --write
```

- `--check`: 一時作業ディレクトリで全6ジェネレータを動かし、実際の生成物を原則バイト単位で比較（初期版Head Cのみ浮動小数点の表現差を許容し、生成データとGDScript実行ラッパーを構造比較）。**ソース/生成データを一切変更しない**。失敗したらCIを止める。
- `--write`: 全工程が成功した場合に限り、変更のある生成ファイルだけ一時ファイル経由で更新。変更されていない出力を触らない。過去のブロックベンチモデルは変更しない。
- 通常リグ、鳥脚、カタナ、装備A/B、頭C、下半身DのAndroid用データを対象とする。独立のKickパックは独自の履歴元を持つため今回の生成パイプライン対象外とし、従来の専用テストで保護。
- 同一モデル内のUUID重複を検出する。骨格とモーションの互換性は既存の実Godot CIで確認する。端末実機描画は別検証。

## CI計測と検査順
- `tools/sera_ci_timings.json` は実際のGitHub Actions実行ログから作成した初期テスト所要時間。既知の遅いテストを先に開始する並び替えにだけ使用。
- 全件を省略せず、プロセスとuser://を分離して実行。新規テストは従来どおりmanifestへ登録。
- `tools/sera_ci_suite.py ... --report-json /tmp/report.json` で全テストの実行結果・秒数・遅い検査をJSON出力。CIはレポートをアーティファクトに保存し、後から実測時間を更新できる。
- 保存した実行時間は検査の選択を決めず、**並び順だけ**を調整する。結果の評価は従来どおり全件成功が条件。
