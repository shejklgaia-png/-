# SERA 倉庫UI・製作個体追加性能 — 確定要求仕様（2026-11-20）

> 本書はユーザーの直近指示を優先する実装契約です。既存UI・過去テストの見た目に合わせて新仕様を骨抜きにしないでください。**本書の追加だけでは実装済みとはしません。**

## 1. 画面構成

1. **倉庫の装備表示**は2列固定・縦スクロール。設計図単位の「所持 ×N」「未所持 0」など集約アイテム一覧は廃止し、**装備個体1個をカード1枚**として描画します。個体IDを保持し、同じ設計図の装備も異なる追加性能を表示します。製作画面の装備選択肢でも集約所持数を不要な項目として表示しません。
2. **倉庫の素材表示**は同じ系統の低・中・高ランク3種類を、**一行に横3枚**で並べます。4系統は各々独立した行を縦に並べます。画面は縦スクロール可能。素材個数表示は維持します（撤廃対象は装備の「×N」項目です）。
3. **素材・装備のカード見た目**は共通。濃いブルーグレーの長方形・四隅を斜めに切り欠いたシルエット、内部は暗く、文字は高コントラストの白系。選択状態・無効状態・空枠も同じ形状と配色体系を使います。既存の丸角ボタンのスタイルはその他のLABO操作／タブでは維持して構いませんが、倉庫カードだけは欠け角にしてください。
4. 日本語も読める**M PLUS 1 Code**（日本語・英数字対応の等幅書体、SIL OFL）の利用を第一候補とします。ゲーム本体で必要な文字を同梱して適切なライセンスを添付し、無償で利用できる構成にしてください。小さく潰れる字体やOS依存の置換が生じるなら実機で読みやすい日本語フォントを優先します。ライセンスの確認なしにフォントファイルを追加しないでください。
5. **装備カード:** アイコンは**縦横比1:1の正方形**で左側に配置し、右側にその個体の**追加性能5個を縦方向に1行ずつ**表示します。装備名・UIDを識別可能にし、長い文字列が重なる場合は省略表示と詳細表示を併用。2列のままAndroid縦画面で読めるレイアウト（固定極小文字は不可）を実測検証します。アイコンの一辺はカードの高さを越えず、右側文字の最低幅を優先してください。
6. **空欄:** 装備が0個でも空の欠け角カード枠を表示し、最後の行が1個なら右側の空枠を表示します。装備アイコン・追加性能・所持数は空欄に偽表示しません。容量999個を表すために999個のControlを生成することは禁止します。
7. 各装備カテゴリは独立ハンガーで**999個上限**。装備個体数を数え、満杯の場合は新製作を保存する前に拒否します。別カテゴリの容量に影響しません。カテゴリーの名称・分類は現行 `sera_prototype_catalog.gd` のslot情報を使用します。容量表示は `現在数/999` とし、装備の集約「×N」表示とは区別します。

## 1.1 状態アイコンと無通知保存（2026-11-21追記）

- 装備個体のお気に入り／不用品指定が成功したとき、詳細画面の「SYSTEM / 分類を保存しました。」は表示しない。ディスク保存に失敗した場合のエラー表示は残す。
- 装備詳細の最上部タイトル行の右上に、**現在の個体に保存された状態のみ**黄色の星／赤色の不用品アイコンとして表示する。名前の行高に近い約34pxを使用し、ほかのページへ遷移したら非表示に戻す。両状態はセーブ仕様に従い排他的。
- 倉庫の装備2列リストでは、状態アイコンを18px固定・カード右端固定にせず、カード幅に応じて最大28pxへ拡大する。アイコンは**実際に描画される装備名の直後**に約7pxの隙間を空け、名前やカード外枠に重ねない。名前の幅を必要に応じて計測し、最小17pxまで自動調整する。
- 既存の欠け角カード、追加性能5件の2列配置、各ハンガー999件の仮想スクロール、操作ボタン、UIDセーブは維持する。スクロールごとに新規Controlを作成しない。

## 2. 製作時ランダム追加性能

1. **新たに装備個体が製作成功したときに、追加性能をランダムで厳密に5個付与します。** 基本装備定義ではなく、個体UIDにひもづくデータとして永続保存します。同じ設計図でも個体ごとに抽選は独立します。
2. 追加性能は効果ID・数値・表示名を一元的なカタログで管理してください。数値の具体的な抽選範囲・戦闘反映先は既存の実装済みステータスと整合させ、未承認の強力な効果を勝手に設定しないこと。表示専用の架空ステータスで「性能が適用済み」と偽らないこと。
3. **NEXUSで着脱する追加効果モジュールは別システムとして維持**します。製作時のランダム追加性能5個をスロット5枠と解釈しないでください。モジュール装備によってランダム性能を消去・再抽選しません。
4. 製作が失敗・キャンセル・保存失敗した場合はUIDも追加性能も発行しません。ロード・装備変更・画面再表示・UI描画で再抽選せず、保存した5個をそのまま復元します。
5. 古いセーブの装備個体には後付け再抽選を行いません。既存個体はUID等を保持したまま旧データとして安全に読み込み、追加性能未設定を明示するか安全な移行を別途検討します。既存データを消さないこと。
6. 5個の効果は一覧と装備詳細から確認でき、選択中の個体UIDと対応することを保証してください。異なる個体の追加性能の取り違えは禁止します。

## 3. 最軽量の実装条件

- 1ハンガー999個は**データ上の上限**であり、同数のUIノードを生成する根拠にはしません。スクロール位置に応じて表示セルを仮想化・再利用し、必要なセル数だけ生成します（Godotの標準ScrollContainerと可視セルプールなど）。素材は固定12種なので必要最小限の再利用・固定生成で十分です。
- 共通モデル・テクスチャ・アイコン・フォントは共有キャッシュを参照。装備個体ごとのNode/Texture/Resource常駐、毎フレームのリスト再構築、スクロール1pxごとの全個体再描画、製作ごとの全カテゴリ再集計は避けます。
- 既存Android Godotエディタで「カスタムPanelContainerが空白になる」不具合があったため、目に見えるカードの描画とタップを実機で検証してください。単一描画Controlが端末で表示できなければ、**少数のNative Buttonのプール再利用**を使ってください。軽量性より「見えない・押せない」実装を優先してはいけません。
- LABO画面上部30%の共通3Dステージは維持。倉庫スクロールは3D描画・アニメーションと独立し、戻るボタン・タブを画面外へ押し出さないこと。
- 装備数0、1、2、998、999でUIとデータを確認。長文ラベル・日本語・選択枠・指スクロール・保存再読込も確認。

## 4. 既存CIを更新するための注意

変更前に `tools/sera_ci_manifest.txt`、`docs/SERA_ACTIVE_CI_POLICY_ja.md`、`.github/workflows/sera-model-policy.yml`、`tools/v511_matte_icons_*`、`v519_card_grid_*`、`v521_full_card_touch_*`、`v522_native_cards_*`、`v523_overlay_cards_*`、`v524_layout_tabs_*`、`labo_lightweight_ui_*` を確認します。

特に旧CIの「倉庫装備7設計図カード」「全一覧3列」「倉庫装備ボタンに所有数」「ScrollContainer禁止」「丸角は全カードに必須」は今回の新仕様と競合します。**実装前にこれらの期待値を倉庫に限って修正**してください。製作・素材変換タブの既存機能は、仕様変更がない限りテストを維持します。新たにUI構成・空枠・999上限・製作時5性能・ロード不変・スクロールの仮想化上限・実機可視性を検証するテストを追加します。

開発手順は `AGENTS.md` に従い、事前CI確認→期待値更新→実装→局所検証→PRとレビュー→マージ→`main` フルCI→Androidで目視確認の順です。CI合格と実機視認性は別に報告します。
