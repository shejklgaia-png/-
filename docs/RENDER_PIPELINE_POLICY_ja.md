# SERA 3D描画契約 — 表示順・深度・モデル追従の共通規約
<!-- RENDER_POLICY_ID: SERA_RENDER_CONTRACT_V1 -->

この文書は、スラスターに限らず、斬撃・銃撃・残像・シールド・UI空間演出・追加パーツなど、**3D上に新しい描画要素を追加する際の必須確認事項**を定義します。最終的な画面の見え方はAndroid上で別途検証します。

## 1. 役割を先に定義する

3Dエフェクトを「新しい順番に上書き表示」するのではなく、次の4つを独立して決めます。

1. **所有座標系**：ワールド固定／機体ルート／アニメーションボーン／武器／ノズル先端。過去の軌跡はワールドに固定し、新しい発生点だけノズルを追跡します。
2. **生存条件**：入力・戦闘状態・アニメーション・ヒットストップ・EN・可視性に応じたON/OFF。ノードの `visible`、材質のalpha、親ノードの可視性をそれぞれ確認します。
3. **遮蔽規則（深度）**：装甲や地面の向こう側を透けてよいか。物理的な噴射・武器軌跡は原則として深度テストON。意図的な前面オーバーレイは例外として深度テストOFFを明記します。
4. **合成順序（描画優先度）**：同一フレーム内の他の半透明パス（斬撃、残像、機体オーバーレイ）との重なり。これは3D座標や深度テストと**別の問題**です。

### 登録済みの透明3Dパス

優先度の値は `scripts/render_order_policy.gd` の定数だけを正とします。以下は2026-11-10時点の役割です。

| 定数 | 値 | 役割 | 深度テスト |
|---|---:|---|---|
| `AFTERIMAGE` | -20 | 残像 | 個別シェーダーの仕様に従う |
| `NEXUS_SURFACE_EDGES` | -10 | NEXUS室内の非発光ポリゴン角・2pxグレー線 | ON（不透明面に遮蔽） |
| `SLASH_VOLUME` | 100 | 斬撃ボリューム | OFF（現行演出） |
| `SLASH_SURFACE` | 105 | 斬撃メイン弧 | OFF（現行演出） |
| `SLASH_PARTICLES` | 110 | 斬撃微粒子 | OFF（現行演出） |
| `SHIELD_IMPACT` | 115 | 命中部位のシールド防御光・亀裂・放射状破壊 | ON（装甲/地面に遮られる） |
| `HIT_SPARKS` | 120 | 命中時の四角い火花 | ON（機体・標的に遮られる） |
| `CHARACTER_FOREGROUND` | 126 | 意図的な前面演出（旧セラ前面コピーは無効、v501の発射時十字フラッシュは有効） | OFF（例外的な演出のみ） |
| `DEPTH_TESTED_EMISSIVE` | 127 | ノズル噴射・帯状軌跡などの発光 | **ON** |

不透明の標準3Dモデルは通常の深度バッファに従い、透明パスの優先度を機械的に付けません。Godotの `render_priority` 上限は +127 です。**新しい機能のたびに値を1増やす設計は禁止**します。既存の役割を再利用するか、必要に応じて描画パス全体を再設計します。

## 2. 実装前の調査手順（新規モデル／新規エフェクトに共通）

1. `scripts/render_order_policy.gd`、該当する `shaders/`、`scripts/sera_rig.gd` の `material_overlay`、`scripts/sword_trail.gd`、追加対象の親階層を確認します。
2. 既存の半透明パスを列挙し、それぞれの `render_priority`、`blend_*`、`depth_draw_*`、`depth_test_disabled` または `no_depth_test` を記録します。
3. 「不透明に遮られる」「半透明パスに上書きされる」「そもそもOFF」「位置・角度がズレる」を区別し、原因と無関係なノズル長・モーションを先に変更しません。
4. 元モデルのPivot、アニメーションの累積回転、噴射先端の座標、補間後の最終姿勢を確認します。安全補正を追加する場合は最後の補正が機械的可動域を逸脱しないようにします。
5. 定数を `RENDER_ORDER = preload("res://scripts/render_order_policy.gd")` で参照し、`material.render_priority = RENDER_ORDER.DEPTH_TESTED_EMISSIVE` のように指定します。ハードコードされた優先度値や不明な初期値0への依存を避けます。
6. 新しい半透明spatialシェーダーでは先頭に `// RENDER_POLICY: <登録済み定数名>; depth_test=on|off` を追加します（例：`// RENDER_POLICY: DEPTH_TESTED_EMISSIVE; depth_test=on`）。追加シェーダーの申告漏れはCIで検出します。
7. 既存の透明パスと優先度を変更する場合は、関連する回帰テストとこの文書も同時に更新します。

## 3. 遷移を含む検証マトリクス

| 状況 | 確認すること |
|---|---|
| 何もない待機 | 本体・残像・エフェクトの初期表示と不要な重なり |
| BOOST/STEP前後 | 噴射の出始めと停止、ボーン姿勢変化、残光 |
| 斬撃開始・終了 | 元の全パーツ不透明材質とテクスチャを常時維持し、別パスの斬撃・噴射との前後関係を確認 |
| 1段目→2段目→3段目 | 胸部の大きなひねり、ノズル角度、描画優先度と可視性 |
| ヒットストップ | モーション停止中もエフェクトが消えず、過去の軌跡は減衰 |
| 左右・後方ステップ | 噴射方向・可動域・左右ノズルの独立性 |
| カメラ角度／近接 | 前にあるものだけ見えるか、背後の噴射が透過しないか |
| 装備変更 | 別モデルでも座標系・マテリアル契約を引き継ぐか |

静的検査は`tools/render_policy_self_check.py`、旧描画不具合の検査は`tools/v225_thruster_draw_order_self_check.py`を使用します。最終確認はGodot/Android実機で行います。

## 4. 将来の開発への適用例

- **新型ブースター**：ノズル先端への追従はモデル階層、描画は `DEPTH_TESTED_EMISSIVE`、過去の軌跡はワールド座標固定。
- **銃口炎や弾道**：実物体の前後関係は深度テストON、同じ発光パスが適切なら `DEPTH_TESTED_EMISSIVE` を共有。
- **シールド／爆発**：発光と半透明シェルの遮蔽規則が異なる場合は単純流用せず、必要に応じて新しい合成ロールとテストを設計。
- **UIや照準マーカー**：本来の2D `CanvasLayer` と3D `render_priority` を混同しない。画面最前面にしたいだけで3Dの深度テストを無効化しない。

### v321 追加：キャラクター材質の不変条件

- 通常斬撃ではキャラクター全パーツに `material_overlay` の半透明前面コピーを被せません。GPU透明ソートに伴う欠落・斬撃終了時のテクスチャ突然復帰を防ぐためです。
- 標準A・BのUVアトラス、C頭・D下半身・ブースター等の固有無地マテリアルは、装備選択／攻撃遷移の前後で `material_override` に維持します。
- エネルギー警告とKOは例外の一時的オーバーレイであり、原本の材質は変更しません。
- `CHARACTER_FOREGROUND` は旧シェーダーの参照を残す互換定数であり、通常攻撃中の表示には使用しません。再有効化する場合はAndroid GL Compatibility上の全材質・奥行き・描画順を新たに検証します。

## 5. 自動化の限界

CIは、共通優先度の参照、既存描画順、主要シェーダーの深度設定、数値直書き、新規半透明spatialシェーダーの契約コメントを検査します。しかし、**実際のフレーム上の遮蔽、機体内干渉、Android GL Compatibilityの透明描画結果を保証するものではありません**。ユーザー提供の動画は引き続き重要な動作検証資料です。

## v501：ビットタラン銃口の一瞬の前面発光（意図的な深度例外）

- ビットタランの腹下砲台が発射した瞬間だけ出る十字フラッシュには、登録済みの `RENDER_ORDER.CHARACTER_FOREGROUND` (126) を使用。セラの旧前面複製メッシュは引き続き無効。
- 十字の内側と外側の光は `BaseMaterial3D.TRANSPARENCY_ALPHA`＋加算合成`BLEND_MODE_ADD`＋`no_depth_test=true` に統一。**機体や障害物による遮蔽を受けない**ことは、銃口の閃光を特に目立たせる要求に基づく**発射時だけの意図的な例外**であり、ほかの砲弾・脚・胴体・スラスター・レーザーの深度処理には波及させない。
- 砲口座標の前方20cmに描画し、カメラ向きのビルボードで縦横3.10m（従来0.62mの5倍）、中心が白く外周が青い二重十字とする。発射時0.12秒で消し、攻撃・ダウン停止では即非表示。
- 銃口照準、弾道、ヒットボックスにはこの前面描画を使用しない。これらは通常の3D深度・座標系を維持する。強い閃光が画面の一部を一瞬覆う可能性があるため、Android実機での視認性を別途確認する。

## v503：単発レーザー弾と「実際に周囲を照らす」発光の規約

- 砲台発射時の十字と半透明`RadialRadiance`は既存の短命な前面合成（`CHARACTER_FOREGROUND`）を使用。追加した`GradientTexture2D.FILL_RADIAL`は中心明るく、縁が透明になるよう生成した光輪。十字も光輪も短命で、攻撃・ダウン時は即消灯する。
- 銃口に連動する`OmniLight3D`は**実際の3D照明**として発射瞬間だけ有効にする。光量10→0まで0.12秒以内に二乗減衰。Android GL Compatibilityに配慮し`shadow_enabled=false`。常時点灯や毎弾新規Lightノード作成はしない。
- 細長い飛翔弾は`CapsuleMesh`の芯＋一体の半透明外光で**単発**とする。砲弾側は`DEPTH_TESTED_EMISSIVE`（127）を使い、`no_depth_test=false`でモデル・地面を透過しない。前面深度無視は短時間の銃口フラッシュに限定する。
- 発射時間/形状の変化は既存`tools/bittaran_leg_turrets_runtime_check.gd`で実Godot CIチェックする。発光が視覚的に十分自然かはAndroid実機映像で検証する。


## v510：敵の予測シールド防御と破壊の描画

- 敵本体の不透明面より前、通常ヒットスパークより後ろに描画する**独立した深度付き半透明3Dパス**として `SHIELD_IMPACT=115` を追加。描画順と深度テストは独立した契約。
- カメラ正対の放射状頂点アルファグラデーションを、実際の衝突点の深度からカメラ側へ0.032mオフセットして描画。スパークの0.06mオフセットより奥に置き、部位ごとの接触を維持。
- 通常時は残SP比率100〜60%青、59〜30%黄、29%以下赤。縁は透明。SPを0へ落とす最後のヒットのみ、中心から左右へ伸びる青白い稲妻の亀裂と、短命な放射状の青白い拡散光および破壊SEを発生。独立したHP/シールドゲージは追加しない。
- 本体のシールド計算は`scripts/enemy_predictive_shield.gd`、描画とSEは`scripts/enemy_shield_hit_fx.gd`。共通`main.gd`の命中処理をビットタランが継承し、部位/モデルの既存HitFlashや火花は改変しない。
- `SHIELD_IMPACT`と`HIT_SPARKS`の深度と描画順は`tools/render_policy_self_check.py`およびv510の実Godotテストで確認。Android GL Compatibilityでの色・透明度・機体との重なり・SEの聞こえ方は別途確認。

## v511：敵シールドの実機視認性改善

- Androidで通常ヒットの防御光がほぼ見えないという実機報告により、`SHIELD_IMPACT=115`・深度テストON・`HIT_SPARKS=120`との順序を**維持したまま**面積と光度を大幅拡大。
- カメラ正対の通常防御円：半径27→74px相当だったものを100→260px相当に変更（720px基準、スケール下限0.85）。縁はアルファ0、芯は白寄りの高輝度、青/黄/赤の色分けは維持。寿命0.28→0.44秒。
- 破壊時の青白い横亀裂：左右各35→180px相当から、各90→470px相当へ拡大。線の発光幅5→13px相当、芯1→2.6px相当。放射状破裂の最大半径は約186→470px、持続0.44→0.65秒。
- 被弾点の表面が浅い角度で装甲に埋もれないよう、深度上のカメラ側オフセットを0.032→0.14mに拡大。これは描画専用であり判定/カメラ/部位位置を変更しない。**深度テストOFFにはしない**。非シールド部分と他機体がエフェクトを遮る従来の規則は維持。
- 仕様検査は既存`tools/v510_predictive_shield_self_check.py`・`tools/v510_predictive_shield_runtime_check.gd`の新サイズ/持続/深度の期待値を本体変更より先に更新。HPバー重ねなし、予測軽減率・回復・攻撃判定・SEは不変。

## v512：予測シールドの彩度とキレ（Androidでの視覚改善）

- **色が白く飛ぶ対策**：シールド専用の`StandardMaterial3D`を`BLEND_MODE_ADD`から`BLEND_MODE_MIX`に変更。青`#007AFF`／黄`#FFE100`／赤`#FF2140`の彩度を背景の明るさに左右されず維持。深度テストON、描画優先度115、透明外縁、既存火花120より奥の位置は維持。
- **命中のキレ**：強い初撃の白芯は短時間だけとし、直後は色が飽和した輪郭（半径の67〜81%の帯を高不透明度）と半透明の色面で防御を示す。攻撃の始点は即表示、約0.03秒で最大強度、0.35秒程度で素早く減衰。エフェクトの管理時間0.44秒は維持。
- **剥離時**：横方向の青白い亀裂の伸長時間を0.20→0.13秒、発光が消える時刻を約0.44→0.32秒に短縮。放射状の青白い破裂に明るい色の輪郭を付ける。破裂の管理時間0.65秒と最大半径470px、破壊SEは変更しない。
- **保護する仕様**：ボスHPバー非重畳、最大100SP、近接/射撃軽減、4秒回復ディレイ、部位破壊・モーション・当たり判定は変更しない。色合成・不透明度時間曲線と色閾値は既存v510テストを本体編集前に更新して検証する。
## v515：予測シールドの膜表現と破壊時のみの中央空洞

- 通常の近接命中で予測シールドが防いでいる間、命中中心は**常に充填された色付きの半透明膜**。短い白芯が消えた後も膜の中心の色/不透明度は外周の防御光と同じ時間曲線で減衰し、外周リングだけが浮く空洞表示を禁止。中心0〜20%半径を均一に塗り、外へ面状グラデーション、外周に高彩度の狭い縁（73〜82%）を描画する。
- シールド耐久が0になった**破壊エフェクトのみ**内側半径を0でなく半径の14→23%とし、中央が実際に描かれない穴になる。穴を囲む青白い硬い境界、10片の尖った破片、横方向の青白い亀裂、既存の短い破裂SEを併用。
- サイズはv511、彩度/透明混合はv512を保持。SHIELD_IMPACT=115・深度テストON・本体とヒット火花の間という描画契約、HPバー非重畳、部位判定・予測シールド耐久/回復は変更しない。
- **事前CI**：v515専用の静的テストと実Godotテストを本体変更前に登録。実際のImmediateMeshの頂点色と座標から、通常時の中心が不透明度0.5以上で埋まること、破壊演出で横亀裂消灯後に中心へ半透明ポリゴンが描画されていないことを検証する。最終Android画面は実機で確認。


## v516：六層八角形の防御面・角張ったガラス破片（v515の丸い膜描画を更新）

- **通常防御**：同じ命中点から**同心円状ではなく、同心の正八角形の厚い輪郭6層**を内側から段階的に展開する。内側の小八角形は薄く色のある面で埋め、通常命中で中央に穴を空けない。輪郭は8本の直線で成形した一様アルファの多角形メッシュ。ぼかし・円形放射グラデーション・半透明フェード帯を使用しない。
- **外周への透過**：1層目から6層目へアルファを段階的に0.95→0.35へ減衰。各層内は均一な不透明度を保ち、八角形のエッジをシャープに表示。高彩度の青/黄/赤のSP残量閾値は維持。
- **時間**：内側から6輪を順次出現させる展開0.20秒、全輪表示0.20秒、全輪消去0.20秒（合計0.60秒）。輪ごとの出現には短いsmoothstep、消滅は透明度の時間補間のみを使用する。輪郭を空間ぼかししない。
- **破壊**：旧v515の円形の輪と放射状グラデーションを削除。再描画で位置が飛び変わらないよう破壊ヒット時に14片の角度・速度・形状・回転を一度だけ乱数決定し、長さ55〜110px相当の青白いガラス形状の大きな四角形/不規則多角形片を放射方向に飛ばす。2つの硬い面を持つポリゴンで、ぼかし・中心の塗りつぶしはない。
- **横亀裂**：左右へ高速0.065秒で展開し、0.16秒で消える。中心部は白青の硬い2層線、左右端へ向かって線に沿ったアルファのみ減衰し末端は完全透明。横方向のグラデーションは先端を消すためのもので、輪郭のぼかしではない。
- **描画契約**：既存のSHIELD_IMPACT 115 / HIT_SPARKS 120 / 深度テストON・0.14mのカメラ側描画オフセット、HPバーへの非重畳、破壊SE、シールド100SP・被ダメージ軽減・4秒待機と20SP/秒回復、ビットタラン/テストターゲットの共通実装を維持。
- **事前CI変更**：旧v510の0.44秒表示・遅い亀裂の期待値、旧v515の円形リング描画の文字列期待値を本体編集前に新仕様へ更新。v515の実Godot「通常命中中心が埋まる／破壊後のみ穴」検査は維持。新規v516 staticとGodotテストで8辺×6層×2面三角形、0.2/0.2/0.2秒、内→外の不透明度、ガラス片個数、稲妻先端の透明性を検査。

## v520：敵シールド八角形フレームを横方向に15%拡張

- 通常命中の6層の正八角形フレームと中央の色付き八角形のみ、命中点を中心に画面上の横幅を1.15倍に変更。縦の寸法・輪郭の角数・各層の透過率と展開/保持/消去の0.2秒ずつの時間設定は不変。
- 共通の八角形頂点方向でx成分だけを1.15倍。ガラス片14個・短い横稲妻・破壊SE・シールド100SPと被ダメージ軽減/回復には変更なし。
