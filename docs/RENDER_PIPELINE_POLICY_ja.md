# SERA 3D描画契約 — 表示順・深度・モデル追従の共通規約
<!-- RENDER_POLICY_ID: SERA_RENDER_CONTRACT_V1 -->

この文書は、スラスターに限らず、斬撃・銃撃・残像・シールド・UI空間演出・追加パーツなど、**3D上に新しい描画要素を追加する際の必須確認事項**を定義します。最終的な画面の見え方はAndroid上で別途検証します。

## 1. 役割を先に定義する

3Dエフェクトを「新しい順番に上書き表示」するのではなく、次の4つを独立して決めます。

1. **所有座標系**：ワールド固定／機体ルート／アニメーションボーン／武器／ノズル先端。過去の軌跡はワールドに固定し、新しい発生点だけノズルを追跡します。
2. **生存条件**：入力・戦闘状態・アニメーション・ヒットストップ・EN・可視性に応じたON/OFF。ノードの `visible`、材質のalpha、親ノードの可視性をそれぞれ確認します。
3. **遮蔽規則（深度）**：装甲や地面の向こう側を透けてよいか。物理的な噴射・武器軌跡は原則として深度テストON。意図的な前面オーバーレイは例外として深度テストOFFを明記します。
4. **合成順序（描画優先度）**：同一フレーム内の他の半透明パス（斬撃、残像、機体オーバーレイ）との重なり。これは3D座標や深度テストと**別の問題**です。

### 登録済みの透明3Dパス

優先度の値は `scripts/render_order_policy.gd` の定数だけを正とします。以下は2026-11-10時点の役割です。

| 定数 | 値 | 役割 | 深度テスト |
|---|---:|---|---|
| `AFTERIMAGE` | -20 | 残像 | 個別シェーダーの仕様に従う |
| `SLASH_VOLUME` | 100 | 斬撃ボリューム | OFF（現行演出） |
| `SLASH_SURFACE` | 105 | 斬撃メイン弧 | OFF（現行演出） |
| `SLASH_PARTICLES` | 110 | 斬撃微粒子 | OFF（現行演出） |
| `HIT_SPARKS` | 120 | 命中時の四角い火花 | ON（機体・標的に遮られる） |
| `CHARACTER_FOREGROUND` | 126 | 斬撃中のセラ本体前面オーバーレイ | OFF（特殊描画） |
| `DEPTH_TESTED_EMISSIVE` | 127 | ノズル噴射・帯状軌跡などの発光 | **ON** |

不透明の標準3Dモデルは通常の深度バッファに従い、透明パスの優先度を機械的に付けません。Godotの `render_priority` 上限は +127 です。**新しい機能のたびに値を1増やす設計は禁止**します。既存の役割を再利用するか、必要に応じて描画パス全体を再設計します。

## 2. 実装前の調査手順（新規モデル／新規エフェクトに共通）

1. `scripts/render_order_policy.gd`、該当する `shaders/`、`scripts/sera_rig.gd` の `material_overlay`、`scripts/sword_trail.gd`、追加対象の親階層を確認します。
2. 既存の半透明パスを列挙し、それぞれの `render_priority`、`blend_*`、`depth_draw_*`、`depth_test_disabled` または `no_depth_test` を記録します。
3. 「不透明に遮られる」「半透明パスに上書きされる」「そもそもOFF」「位置・角度がズレる」を区別し、原因と無関係なノズル長・モーションを先に変更しません。
4. 元モデルのPivot、アニメーションの累積回転、噴射先端の座標、補間後の最終姿勢を確認します。安全補正を追加する場合は最後の補正が機械的可動域を逸脱しないようにします。
5. 定数を `RENDER_ORDER = preload("res://scripts/render_order_policy.gd")` で参照し、`material.render_priority = RENDER_ORDER.DEPTH_TESTED_EMISSIVE` のように指定します。ハードコードされた優先度値や不明な初期値0への依存を避けます。
6. 新しい半透明spatialシェーダーでは先頭に `// RENDER_POLICY: <登録済み定数名>; depth_test=on|off` を追加します（例：`// RENDER_POLICY: DEPTH_TESTED_EMISSIVE; depth_test=on`）。追加シェーダーの申告漏れはCIで検出します。
7. 既存の透明パスと優先度を変更する場合は、関連する回帰テストとこの文書も同時に更新します。

## 3. 遷移を含む検証マトリクス

| 状況 | 確認すること |
|---|---|
| 何もない待機 | 本体・残像・エフェクトの初期表示と不要な重なり |
| BOOST/STEP前後 | 噴射の出始めと停止、ボーン姿勢変化、残光 |
| 斬撃開始・終了 | 前面オーバーレイの有効化／無効化と噴射の前後関係 |
| 1段目→2段目→3段目 | 胸部の大きなひねり、ノズル角度、描画優先度と可視性 |
| ヒットストップ | モーション停止中もエフェクトが消えず、過去の軌跡は減衰 |
| 左右・後方ステップ | 噴射方向・可動域・左右ノズルの独立性 |
| カメラ角度／近接 | 前にあるものだけ見えるか、背後の噴射が透過しないか |
| 装備変更 | 別モデルでも座標系・マテリアル契約を引き継ぐか |

静的検査は`tools/render_policy_self_check.py`、旧描画不具合の検査は`tools/v225_thruster_draw_order_self_check.py`を使用します。最終確認はGodot/Android実機で行います。

## 4. 将来の開発への適用例

- **新型ブースター**：ノズル先端への追従はモデル階層、描画は `DEPTH_TESTED_EMISSIVE`、過去の軌跡はワールド座標固定。
- **銃口炎や弾道**：実物体の前後関係は深度テストON、同じ発光パスが適切なら `DEPTH_TESTED_EMISSIVE` を共有。
- **シールド／爆発**：発光と半透明シェルの遮蔽規則が異なる場合は単純流用せず、必要に応じて新しい合成ロールとテストを設計。
- **UIや照準マーカー**：本来の2D `CanvasLayer` と3D `render_priority` を混同しない。画面最前面にしたいだけで3Dの深度テストを無効化しない。

## 5. 自動化の限界

CIは、共通優先度の参照、既存描画順、主要シェーダーの深度設定、数値直書き、新規半透明spatialシェーダーの契約コメントを検査します。しかし、**実際のフレーム上の遮蔽、機体内干渉、Android GL Compatibilityの透明描画結果を保証するものではありません**。ユーザー提供の動画は引き続き重要な動作検証資料です。
