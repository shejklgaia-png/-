# SERA 開発運用：CI・テスト実施禁止（2026-11-22 改訂）

**最優先規則**：ユーザー指示によりCIテストを実施しない。旧版の「変更別ローカル検査に移行」「CI期待値を先に更新」「リスク別最低テスト」「手動でCIを起動する」等の手順はすべて停止する。

## 禁止
- CIテストの項目・期待値・ケース・登録内容・実行結果を確認しない。
- CIテスト項目を追加、修正、削除、適用しない。テストファイル、CI manifest、CI設定・ワークフローに変更を加えない。
- GitHub Actions、Python、Godot、Android等でCI/ローカル/実機のテストやテスト目的の動作検証を実行しない。再実行・ベンチマークも行わない。
- `sera_workplan.py --execute`、`sera_quick_check.py`、`sera_ci_suite.py` 等、テストの調査・実行に繋がる手順を使用しない。

## テストを伴わない開発フロー
1. 最新の実装コード、モデル原本、仕様書から必要な変更内容を把握する。ただしテスト項目を調べない。
2. 要求された実装、表示、素材、仕様書を最小限の変更で更新する。テスト項目と関連CI設定は維持し、編集しない。
3. 変更内容と残存する未確認事項を報告する。テストPASS・合格などとは表現しない。
4. 「実装」はテストなしでマージ前の状態で待機。「マージ」はテストなしで統合する。テスト未実施はユーザー指示によるもので、単独ではマージ停止理由としない。

## 適用範囲
本規則はゲーム開発に関係するすべての今後の変更に適用する。従来の`AGENTS.md`、`docs/agent/CI_WORKFLOW.md`、`docs/SERA_ACTIVE_CI_POLICY_ja.md`のテスト必須事項より新しいユーザー指示が優先する。明示的な解除・変更があるまで継続する。

既存テスト・GitHub Actionsのファイル、設定、トリガー、履歴は**この改訂では変更しない**。既に自動で動く可能性のあるワークフローの停止・設定変更を、この文書改訂だけで行ったとは扱わない。
