# NEXUS 反転ハルの面カリング方向修正（2026-11-23）

## 背景

PR #799で全身マスクと反転ハルを深度テストから独立させても、実機画像では輪郭がほぼ出なかった。原因候補を見直し、`scripts/sera_rig.gd` の `_make_mesh()` が **Blockbenchの閉じた装甲に `BaseMaterial3D.CULL_FRONT` を明示的に設定**している点を確認した。

現行の共通反転ハルシェーダーは `render_mode cull_front`。閉じたSERA装甲では本体と同じ側の三角形を描いてしまい、本来は背面側として必要な輪郭用の反対面が除外される。前回の診断で「面反転」を使うと表示箇所が変わる現象とも整合する。

## 修正内容

- `SeraRig`が各メッシュに既に付けているメタデータ `sera_single_sided` から、原本の面カリング方式を判別する。
- `sera_single_sided=true`（閉じたBlockbench装甲）：原本はCULL_FRONTなので、反転ハル側は**CULL_BACK**を採用する。シェーダー `sera_nexus_stencil_hull_blockbench.gdshader`。
- `sera_single_sided=false`（開放・両面の装甲）：反転ハルは**cull_disabled**にして面の片側が欠けるのを避ける。シェーダー `sera_nexus_stencil_hull_open.gdshader`。
- メタデータを持たない一般メッシュ：従来のGodot標準 `cull_front` のハルを維持する。
- NEXUSの共通ステンシル値17、書き込み優先度-22／読み取り優先度-21、画面上3pxの押し出し、黒寄り`#0B1118`の色、描画対象29メッシュの登録、装備交換追従は変えない。
- 診断の通常・外周候補・合成確認（0、1、9）で今回の新しいカリングを使う。「ハル単独」（8）と「面反転」（13）は現行の前面／背面カリング比較として残し、マスク診断との比較に使う。
- パーツ単体・戦闘・拠点施設の描画や材質設定は変更しない。旧ID方式には戻さない。

## 設計上の注意

同一の閉じた装甲でも、Blockbenchの面順とシェーダーのカリング規則が反対になることがある。見かけの形状ではなく **SeraRigが実際に使用する面カリング設定**を輪郭用パスへ伝える必要がある。単に全てを `cull_back` に変更すると、その他の一般メッシュや両面装備に新たな欠落を発生させる可能性がある。

全身外周はステンシル＋頂点平滑化ハルで生成するため、特殊な凹形状・極薄形状・アニメーションの姿勢で完全な3pxを保証するものではない。**Androidの実機で表示回復できるかは未確認**。失敗した場合には、全身＝（12）、ハル単独（8）、面反転（13）、合成確認（9）の画像で残りの問題を切り分ける。

運用ルールに従い、CIテスト項目の確認・修正・適用、テスト実施は行わない。
