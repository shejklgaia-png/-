# SERA 共通ロード画面ルール（2026-11-22）

## コンセプト
機械生命体のCORE / Shell / OS（Omni Synchronizer）の起動テレメトリを流すSFコマンド端末風の全画面ローディングコンソール。既存UI規則に合わせたブルーグレー（輪郭 #55798A）の切り欠きフレーム、冷色の強い現在行、暗色で小さな過去行、左下に直近工程と大きな実数%を表示。

## 表示
- 背景 #1B303E、手続き生成した電子スクリーンの反復ノイズテクスチャ、固定の細かい横走査線、粒状のちらつきノイズを重ねる。画面を横切る移動線・流れるノイズバーは描画しない。エフェクトと進捗値は独立。
- 上部 SERA // OMNI SYNCHRONIZER、過去ログは最新ログより上側に配置し、新着ごとに上へ送る。過去行は段階的に減光・縮小。
- ブルーグレーの切り欠き線、細い補助レール、角部マーカー、最新行の青白いグローを共通仕様とする。Android縦画面720×1280と狭幅を考慮。
- 下段に100目盛の目盛線を表示。数値は0〜100%。進捗の光は完了値以下の目盛にのみ入れる。左右に動く青白いスイープ線は使用しない。
- 可能なら既存Moralerspace Neonを読み込み、起動最初の1フレームは標準フォントで負荷を抑える。ノイズ用シェーダーや重い外部テクスチャは使わない。

## 実ロードとプレビューを厳密に分離
- 実ロードの進捗は完了済み工程に基づいて更新する。工程開始時に架空の時間で数値を増やさない。現時点では基盤18、NEXUS33、施設49、GRID61/67、廃材79、SHELL86、CRATE92、HUD99、セーブ完了100。これらは工程別の重みづけマイルストーンであり、転送バイトの計測値ではない。
- 100%はBASEシーンの構築とセーブ先記録が実際に完了してから表示。描画後に画面を閉じる。
- BASE HUD内「ロード演出」ボタンからのみ疑似プレビューを呼ぶ。データロードやステート変更は行わない。5秒間を100等分し、50msあたり1%・1ログずつ生成。到達値100%を短時間表示後に閉じる。プレビュー中のタップはゲーム世界に通さない。
- ロード文言はSERAの世界設定（CORE、SHELL、OS、NEXUS、GRID、LAB、CRATE、ARCHIVE）から選び、現実のOSや外部ネットワークへの接続を暗示しない。

## 既存機能・CI
- 既存の sera_loading_sweep.gd はデザイン履歴と独立ランタイムテスト用に保持するが、実起動画面の主体は sera_loading_console.gd。
- 新規 sera_loading_console の静的/実Godotランタイムテストが工程完了時更新、進捗単調性、5秒の100段階、ログ履歴、描画実体を検証する。
- 既存 base_startup_first_frame と base_loading_sweep のUI期待値だけを新しい共通コンソールへ更新。旧スイープの独立ランタイム検査は存続。
- 実機のフォントサイズ、線幅、残像、5秒間の滑らかさはAndroidで別途確認する。
