# SERA 共通ロード画面ルール（2026-11-22）

## コンセプト
機械生命体のCORE / Shell / OS（Omni Synchronizer）の起動テレメトリを流すSFコマンド端末風の全画面ローディングコンソール。既存UI規則に合わせたブルーグレー（輪郭 #55798A）の切り欠きフレーム、冷色の強い現在行、暗色で小さな過去行、左下に直近工程と大きな実数%を表示。

## 表示
- 背景 #1B303E、手続き生成した電子スクリーンの反復ノイズテクスチャ、固定の細かい横走査線、粒状のちらつきノイズを重ねる。画面を横切る移動線・流れるノイズバーは描画しない。エフェクトと進捗値は独立。
- 上部 SERA // OMNI SYNCHRONIZER、過去ログは最新ログより上側に配置し、新着ごとに上へ送る。過去行は段階的に減光・縮小。
- ブルーグレーの切り欠き線、細い補助レール、角部マーカー、最新行の青白いグローを共通仕様とする。Android縦画面720×1280と狭幅を考慮。
- 下段に100目盛の目盛線を表示。数値は0〜100%。進捗の光は完了値以下の目盛にのみ入れる。左右に動く青白いスイープ線は使用しない。
- 字体は旧仕様ではMoralerspace Neonを許容していたが、下記のドット文字規則を優先する。ノイズ用シェーダーや重い外部テクスチャは使わない。

## 実ロードとプレビューを厳密に分離
- 実ロードの進捗は完了済み工程に基づいて更新する。工程開始時に架空の時間で数値を増やさない。現時点では基盤18、NEXUS33、施設49、GRID61/67、廃材79、SHELL86、CRATE92、HUD99、セーブ完了100。これらは工程別の重みづけマイルストーンであり、転送バイトの計測値ではない。
- 100%はBASEシーンの構築とセーブ先記録が実際に完了してから表示。描画後に画面を閉じる。
- BASE HUD内「ロード演出」ボタンからのみ疑似プレビューを呼ぶ。データロードやステート変更は行わない。5秒間を100等分し、50msあたり1%・1ログずつ生成。到達値100%を短時間表示後に閉じる。プレビュー中のタップはゲーム世界に通さない。
- ロード文言はSERAの世界設定（CORE、SHELL、OS、NEXUS、GRID、LAB、CRATE、ARCHIVE）から選び、現実のOSや外部ネットワークへの接続を暗示しない。

## 中央システム診断ビジュアル（2026-11-22）
- ロードゲージ以外の中央表示に、2Dキャンバス描画による脈動する六角CORE、独立速度で逆回転する3層の欠けた円弧リングを表示する。GPU負荷を抑えるため3Dモデル・新規シェーダー・外部画像は使用せず、描画更新は最大30fpsを目安とする。
- CORE周辺には8つのシステム接続ノード（CORE/SHELL/OS/NEXUS/GRID/LAB/ARCHIVE/CRATE）を配置。ノードの青白い点灯と接続線の明度は実ロードの完了率だけから求め、装飾アニメーションの経過時間では増やさない。
- 点灯閾値は、BASEの実工程に合わせてCORE18、NEXUS33、LAB49（施設生成）、GRID67、ARCHIVE79、SHELL86、CRATE92、OS99。デモモードも同じ閾値を使用するが、あくまでデモの擬似進捗。
- 左右に小型の診断パネルを配置し、信号棒グラフと波形がそれぞれ異なる周期で動く。これは装飾的な視覚化であり、ロード率や実CPU温度を示すものではない。
- 縦長720×1280と狭幅450×800を想定して中央表示領域を算出。過去ログの表示行数を可変にし、リング・パネル・接続図がログや下部100段階ゲージへ重ならないようにする。
- 横へ走る光スイープ・画面全体を横切る移動ノイズ帯は引き続き禁止。細い固定走査線と粒状のノイズは維持する。
- 実ロード用のset_stage、BASEの5秒/100段階プレビュー、数値％、100目盛進捗はそのまま維持する。

## ロード端末のみ低解像度描画（2026-11-22）
- ゲーム本体の Godot プロジェクト解像度 `720×1280` とUI表示領域は変更しない。
- `sera_loading_console.gd` の見た目だけを `SubViewport` に切り出し、実表示寸法の縦横50%（720×1280表示なら内部360×640、450×800表示なら225×400）で実際にラスタライズする。
- 生成した `ViewportTexture` を `TextureRect` で元の表示領域に敷き、`TEXTURE_FILTER_NEAREST` で拡大する。テキスト・進捗ゲージ・COREリング・システム接続図・左右の診断波形を一括して低解像度化する。文字サイズ・表示字数は後述の解像度別ドット文字規則を優先する。
- 外側のロード制御は既存どおり進捗・100段階プレビュー・アニメーション時間の唯一の管理者。内側の低解像度描画インスタンスは独立してロード処理を進めない。内側の描画専用インスタンスが再帰してSubViewportを作らないようにする。
- ゲームシーンそのもの、NEXUS、GRID、LAB、戦闘画面、全体のディスプレイ設定、既存のモデルやシェーダーへは適用しない。
- 横に流れる光線は禁止のまま。ヘッドレスCIでは内部レンダーサイズ、表示フィルタ、実進捗の同期、画面回転やサイズ変更への追従を検証する。Android実機の可読性は別途確認。

## 既存機能・CI
- 既存の sera_loading_sweep.gd はデザイン履歴と独立ランタイムテスト用に保持するが、実起動画面の主体は sera_loading_console.gd。
- 新規 sera_loading_console の静的/実Godotランタイムテストが工程完了時更新、進捗単調性、5秒の100段階、ログ履歴、描画実体を検証する。
- 既存 base_startup_first_frame と base_loading_sweep のUI期待値だけを新しい共通コンソールへ更新。旧スイープの独立ランタイム検査は存続。
- 実機のフォントサイズ、線幅、残像、5秒間の滑らかさはAndroidで別途確認する。

## BASE解像度比較プレビュー（2026-11-22）
- 拠点右上のロード演出ボタンを「ロード演出 50%」「ロード演出 37.5%」「ロード演出 25%」の3本にし、各ボタンで同じ5秒・100段階のデモを再生できる。プレビューは保存データや実ロードを変更しない。
- 720×1280表示時の内部ラスタサイズはそれぞれ360×640（現行）、270×480、180×320。450×800表示時は225×400、169×300、113×200（各辺切り上げ）。出力はNEARESTで表示領域へ拡大し、端末と画面の基本レイアウトを維持する。各文字のドット太さ・論理サイズは後述の最適化で可変とする。
- 起動時の実ロードは従来の50%描画を維持する。低解像度2種はBASEから呼び出したプレビュー専用であり、ゲーム全体の画質設定や他画面へ適用しない。
- ヘッドレス検査では各表示寸法の実内部レンダーサイズと描画元の縮小率、現行50%への復帰を確認する。Android実機の文字可読性は別途確認する。

## ロード専用5×7ドット文字最適化（2026-11-22）
- ロード端末の全英数字・記号を `scripts/sera_terminal_pixel_font.gd` の固定5×7グリフから生成した小型1枚のテクスチャアトラスで描画する。ゲーム本体のフォントと他画面には影響させない。原点・ベースライン・字送り・文字幅を各SubViewport内部ピクセルの整数境界に揃える。拡大時もNEAREST。
- 通常フォントを縮小したアンチエイリアス付き描画は使用しない。従来の`set_cyber_font`の呼び出しインターフェースは互換性のため保持するが、ロード画面の見た目は専用ドット字体を優先する。
- 50%では大きい進捗率に3px/ドット、見出しと主要ログに2px/ドット、小さな診断・過去ログに1px/ドットを使用。37.5%では進捗率と短縮した上部見出しを2px/ドット、それ以外は1px/ドット。25%でも進捗率を原則2px/ドットとし、幅510論理px未満の狭幅時のみ1px/ドットへ切替。いずれも1ドット幅に半端なスケールを使用しない。
- 進捗率を右基準で置き、実際のグリフ幅を計測して最新ログの表示可能字数を決める。過去ログと下部STATUSも表示幅内で省略表示し、率と重ねない。狭幅時はヘッダーと診断ノードだけ短縮ラベルを使用する（COREやSYSTEMの実進捗データは変更しない）。
- 内部ラスタサイズは50%=360×640、37.5%=270×480、25%=180×320（720×1280表示基準）を維持。通常起動は50%のみ、BASEのプレビューで3段階比較できる。動き、ロード進捗、5秒・100目盛プレビューには変更しない。
- 既存の`tools/sera_loading_console_self_check.py`と`tools/sera_loading_console_runtime_check.gd`でアトラス、整数ドット太さ、縮小倍率同期、既存進捗の保護を確認。Androidでの実際のコントラスト・可読性と表示欠けは別途確認する。
