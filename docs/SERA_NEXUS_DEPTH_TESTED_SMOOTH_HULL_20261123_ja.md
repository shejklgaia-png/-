# SERA NEXUS 全身枠線：ステンシルなし平滑化反転ハル（2026-11-23）

## 背景

- PR #810までのGPUエッジ＋表裏・凸角判定は、Android実機で手前の稜線が強調され、頭部などの外周が欠ける状態が続いた。
- PR #811の全身8方向オフセット＋ステンシル17は通常表示で全消失した。
- PR #812の各装備AABBを2Dに投影して結合する方式は、実機で余分な大きい輪郭・内部線が目立ち不採用となった。PR #813で通常表示を無効化。
- 新たなSubViewportは追従の遅延リスクがあり、ユーザーの要件と合わない。
- 既存 `sera_nexus_smooth_hull_geometry.gd` はすでに重複位置の頂点法線を平均化し、元のUV・面構造・ボーン情報を保持して輪郭専用メッシュを生成できる。以前はそのハルをステンシル17と深度テスト無効の描画パスで扱っていた。今回は**深度テストと透明パスだけで最小限の描画を成立させる**。

## 本番の新しい構成

対象：**NEXUSのSERA全身表示のみ**。

1. `scripts/sera_nexus_depth_hull_outline.gd` をSERAの全身rigに1個追加。キャラクター枠線設定がONの通常診断モード0、青緑比較のモード1・9だけ動作する。OFFや旧診断モードでは、輪郭用ノードを解放し通常レンダリングに触れない。
2. 0.35秒周期で表示中の頭・胴体・腕・脚・装備・武器メッシュを検出。FXや通常の輪郭生成物を除外する。メッシュが置き換わったら当該ハルを作り直し、未使用のベイクキャッシュを削除する。
3. 既存の `HullGeometry.build(mesh)` を再利用して、**フラットなBlockbenchの分離頂点を位置単位で平滑化した複製Mesh**を構築する。元の描画モデルの材質・法線・UVは変更しない。描画用MeshInstance3Dを各**元MeshInstance3Dの子**とし、姿勢・装備交換・拡縮・回転を同一フレームで継承する。Skeleton3Dがある場合は関連SkinとNodePathを引き継ぐ。
4. シェーダー `sera_nexus_depth_hull_blockbench.gdshader` は閉じたBlockbench装甲向け。SERAの元装甲は`CULL_FRONT`で表示しているため、反転ハルは**`cull_back`**を使う。開放または両面描画のモデルでは `sera_nexus_depth_hull_open.gdshader` の`cull_disabled`を使い、ハルを失わないことを優先する。
5. 描画パスは `unshaded`、`depth_draw_never`、`blend_mix`、**GPU標準の深度テストON**、`stencil_mode`なし。元装甲が不透明パスで深度を書いた後、透明パスのハルを描画する（`ALPHA`書込みによって透明パスへ送る）。元装甲の手前の面が、装甲の内側にあるハルを遮蔽する。輪郭専用メッシュの頂点は平滑化法線を投影した画面方向へ3pxずらす。別カメラ、深度テクスチャ読出し、独立Viewport、CPU毎フレームの輪郭抽出は追加しない。
6. 通常色は`#0B1118`、画面上3px目標。診断モード1・9は**同じ描画パスを青緑**に切り替える。以前の19種類の診断UIを維持し、旧ステンシルやGPUエッジは**通常表示では引き続き描画しない**。
7. PR #812の不正確な2D-AABB輪郭用ControlはNEXUSに**生成しない**。ソースコードは参照用として残すが、本番に戻さない。

## 今回の重点

- 標準深度テストを使い、ステンシル17の不一致判定を**完全に廃止**する。
- 前面の凸角を直接「エッジ」として抽出しない。
- 追加Viewportや画素読み戻しによる追従遅延を避ける。
- すでにある平滑化メッシュ生成を使うため、新たな複雑な解析・処理負荷を増やさない。
- カリング方向を実際のSeraRig Blockbenchソースに合わせる。

## 未解決のリスク

**このPRは実機での正常表示を保証しない。**

- 全身は複数メッシュなので、個々のハルの深度・外周が交わる部分で線が残ったり欠けたりする可能性がある。GPU深度テストだけでは厳密な全身一体の2Dマスクとはならない。
- カメラ方向へ向く平滑化法線では画面投影方向が小さくなり、局所的な輪郭欠けが起こり得る。装備の薄さや開放形状は例外となる。
- 元の装甲が完全な不透明深度を書かない場合（特別な透明素材、FX）には内部ハルを遮蔽できない。
- 完全な3pxの画素精度、Android GL Compatibilityにおける表示品質・FPSは未確認。初回実機では**通常表示（黒）と診断1（青緑）の正面・斜め写真**を取得して判断する。
- 過去の「平滑化ハル」の評価はステンシル併用状態での結果であり、この**深度専用構成の実機結果ではない**。
