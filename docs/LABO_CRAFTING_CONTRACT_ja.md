# SERA LABO 試作製作・アイコン・倉庫の契約

## 対象
- 基本素材は `sera_base_materials.gd` の4系統×3ランク＝12種類。内部IDは固定し、表示名は `sera_base_materials.gd` の現行定義に統一します。品質の自動代替はしません。
- 実装済み装備は `sera_prototype_catalog.gd` の19設計図（頭4・胴2・腕2・脚4・推進2・右武器3・左武器2）に個別登録。H01/H02/T01/A01/L01/B01/WR01/WL01は旧セーブのUID互換性のため設計図IDを維持し、仮画像だけを使った装備記録・仮称は正式な実3Dモデル参照へ置換します。
- 素材12種類は `assets/ui/sera_pixel_material_atlas.webp`（3列×4行、各72×72、背景透過）のドット絵へ差し替えます。並びは上からスクラップ・金属複合材（内部IDは `alloy`）・電子部品・有機素材、各行左から低・中・高。文字・枠は画像に含めません。
- 装備19種類のアイコンは`assets/ui/sera_equipment_icons/<設計図ID>.png`のモデル実写512×512透過PNGを使用します。`sera_matte_icon_atlas.webp` は後方互換調査用に残してもゲーム内装備の画像ソースとしては参照しません。素材12種のドットアトラスは変更しません。
- 倉庫の素材カード、LABOの素材選択・素材変換プレビューには nearest-neighbor 描画を使用し、ドットの輪郭を保ちます。GitSync直後にGodotのimportキャッシュがない場合はWebPの元バイト列から読み込みます。
- アイコンは回収した資材の保管庫、精製・分解の投入/生成プレビュー、LABOの試作リストと詳細、製作後の倉庫、NEXUSのカスタマイズ（選択中）に表示します。

## 製作操作・保存
1. 拠点の LABO → Shell開発 → 試作装備（7種類）から製作対象を選択します。
2. 現段階では**操作検証専用の無償試作**です。実際の素材消費・性能・希少度・追加効果の設計が確定するまでは、仮の必要素材を設定して消費させません。
3. 製作が成功したときだけ、アクティブなセーブスロットの `crafted_items` に装備個体を追加し、`craft_serials` を更新して原子的に保存します。セーブがない場合や保存に失敗した場合は新しい個体を発行しません。
4. 倉庫には素材12種と製作済個体を分けて表示します。NEXUS→CUSTOMIZEの各パーツ欄で既存のセットと製作個体を切り替え、スロットの適合を検証して `equipped_crafted` に保存します。
5. **試作装備の3D表示は既存Aモデルを一時的に利用します。** アイコンと個体IDをモデルデータと取り違えず、独自の3Dメッシュや性能を作成済みとは扱いません。

## 一意な製作個体名
- 安定した内部ID：`<設計図ID>-<4桁以上の十進連番>`。例：`H01-0001`、`H01-0002`、`T01-0001`。
- 表示名：`スカウトバイザー  H01-0002` のように日本語名と**省略しない内部ID**を併記します。翻訳名・レアリティ変更とは独立しています。
- 連番は**各セーブスロット、設計図IDごと**に管理し、製作済個体の最大番号と保存済カウンタを比較して次番号を割り当てます。装備切替で番号を変更せず、将来の分解・削除でも番号を再利用しません。
- 保存データ読込時は、正規フォーマット・有効な設計図・重複しないUID・スロット適合を検査します。旧版の正規UIDはそのまま維持します。

## 2026-11-21：有機素材の等級名を確定

- 有機素材は低級から **微弱有機素材 → 活性有機素材 → 旺盛有機素材** とする。精製・分解・倉庫・装備制作の表示は `BaseMaterials.display_name` / `display_lines` の共通定義を参照する。
- 有機素材の2行ラベルは上段に「微弱／活性／旺盛」、下段に「有機素材」を表示する。内部ID `organic_low / organic_mid / organic_high`、所持数・レシピ比率・画像アトラス・新規プロフィールのスクラップ5個は変更しない。
- `tools/v552_material_names_gamewide_self_check.py` と Godot実行時テストの期待値を実装前に更新し、旧名称の残存検査を加えた。
