# SERA Blockbenchモデル制作・統合運用規約
<!-- WORKFLOW_ID: SERA_MODEL_PARTS_V1 -->

**適用対象**：ChatGPT / Codexが3Dモデル・装備・骨格・モーションを追加、編集、削除、ゲーム内統合するとき。ここでの「担当」は**今後の作業分担**であり、未実装の自動取り込み機能が既にあるという意味ではありません。

## 0. 作業を始める前に（必須）
1. **本書全体とルート `AGENTS.md` を毎回参照**し、GitHub `shejklgaia-png/-` の最新 `main`、現行のモデルと `sera_rig.gd` / `sera_equipment.gd` を調べる。古い添付ZIPだけを基準にしない。
2. 3Dモデル関連PRの本文に、**本書を実際に読んだ後で** `MODEL_GUIDE_READ: YES` と明記する。CIで存在を検査するが、内容理解そのものは保証できない。
3. A骨格と既存アニメーション、他セット、操作・戦闘ロジックを維持。新しく必要な機能だけ実装する。確認不能な左/右やジョイントを無断で推測決定しない。
4. 作業は専用ブランチ→検査→PR→安全なら `main` へマージまで行う。実機で未確認の項目を記録する。

## 1. ユーザーが用意するもの
- **パーツ単体のBlockbench `.bbmodel`**。あらかじめ統合用ファイルにコピーする必要はない。
- **骨格タイプ**（例 `HUMANOID` 標準人型、`BIRD_LEG` 鳥脚）と **部位**（例 右腿、左膝、右腕、頭）。
- 必要な場合だけ **Aセットの標準部位に対する希望サイズ差**（例 幅120%・高さ100%・奥行110%、全体1.3倍程度）。大まかな指定でよい。
- **正しいフォルダの親子構造、関節Pivot（回転原点）、メッシュのローカル座標・向き**。日本語や任意のフォルダ名でよい。名前の最終変更は実装側が行う。
- **フォルダ内のメッシュの数・名前は自由**。複数の装甲や内部フレームが同じ関節の子にあれば一緒に動く。ただしAndroidの描画性能に応じて最適化する。
- **見た目の接合・装甲同士の干渉・意匠・色の最終調整はユーザーが担当**。実装側は正しい部位への登録、追従、ロード、表示を担当。
- Pivotが違えば階層が合っていても不自然に回転する。複数関節で動くパーツは、可動部ごとに子グループと正しいPivotが必要。

入力例：
```text
ファイル: HEAVY_LEG.bbmodel
骨格: HUMANOID
部位: 右腿
サイズ: A比で幅130%、高さ100%、奥行110%
備考: 装甲が大きく張り出しているのは仕様
```

制作者の階層例（名前は自由）：
```text
右脚
└─ 太もも（股関節Pivot）
   ├─ 装甲1
   ├─ 装甲2
   └─ フレーム
```
膝とすねを別々に動かすなら、膝/すね用のPivotを持つ別グループを作る。メッシュが何個あるかは可動の可否に影響しない。

## 2. ChatGPT / Codex が行う処理
1. 提供された元 `.bbmodel` を解析し、グループ階層・Pivot・UUID・メッシュ・UV・マテリアル・左右・接続位置を調べる。
2. **ユーザーが作ったフォルダをGitHub上の対象骨格/セットのBlockbenchファイルへコピーし、実装用の正しい親子階層・名前へこちらでリネームする**。元ファイルの制作名が違っていても再制作を求めない。
3. 関節照合は **親子階層、左右、対象部位、Pivotの位置、空間的位置、形状、名称の類似性**を総合する。確信できないものは勝手に別の関節へ装着せず、警告・必要な確認を行う。
4. コピー後のグループ・メッシュ・アニメーションの**UUID重複を解消**して参照を更新する。オリジナルのA骨格・Aモーション・旧モデルを破壊しない。
5. 指定倍率を反映して、接続位置・座標・向き・Pivotを合わせる。意図した大型装甲まで標準Aの見た目に押し込まない。違和感の最終調整はユーザーが行う。
6. メッシュの形式、UV、テクスチャ、材質が現行Godot読込器と互換になるよう必要なら変換する。**フォルダ内のメッシュ数に一律の上限は設けない**。
7. 使用骨格の既存モーションに追従させ、カスタマイズの装備選択・セーブ・表示・必要なステータスへ登録する。
8. 必要なデータの埋め込み再生成、階層/左右/Pivot/UUID/UV/アニメーション/装備候補の静的検査、可能なGodot検査を行う。Android実機未検証を明記する。
9. 何をどこへコピーし、どう改名・サイズ調整したか記録し、PRを `main` にマージする。

## 3. 骨格・モーション管理方針
- **同じ関節構造を使う装備同士は共通モーションを共有**する。装甲の大きさ・見た目が違っても新しいモーション一式を作る必要はない。
- 目標とする制作運用は **骨格タイプごとに1つの統合 `.bbmodel` ファイル**。骨格、共通アニメーション、その骨格を使う各セット/パーツをまとめる。ユーザーは単体の別ファイルで制作し、実装側が統合する。
- 初期姿勢だけ違う場合は可能なら初期姿勢/Pivot/接続オフセットで補正する。
- **鳥脚・四脚・ホバー・多関節腕など骨格構造そのものが異なる場合**、専用骨格と専用の必要モーションを制作する。その骨格を再利用する他の装備はモーションを共有可能。
- **v189で鳥脚専用6ボーンをA腰骨格の子として導入し、上半身Aと鳥脚の既存モーションを併用できるようにした**。カスタマイズは脚Dのみ特別対応で、他の任意骨格を全自動統合する汎用インポーターは未実装。**v190で静止バインド姿勢の靴底高を基準にモデルを上下補正し、足裏を用いた接地音を導入**。歩行中の足裏を床に固定するIKや段差への足合わせは未実装。
- 骨格の種類を増やす際はモーションセットの対応付けと装備インターフェースを実装側で行う。ユーザーにGodotの構造を調整させない。

## 4. 現行GitHub実装の基準（必ず最新のコードで再確認）
- **標準Aの本体/骨格/モーション**：`assets/sera_source.json`、読込器 `scripts/sera_rig.gd`、埋込生成 `tools/rebuild_model_data.py` → `assets/sera_data.gd`。
- **追加セットのメッシュ制作元**：`models/SERA_BOOSTER_allテスト.bbmodel`、読込器 `scripts/sera_equipment.gd`、埋込生成 `tools/rebuild_equipment_data.py` → `assets/sera_equipment_data.gd`。
- この現行構成はAの既存Pivotに追加セットの装甲を装着する設計。**1パーツファイルの完全自動コピー、任意の日本語名の完全解釈、自動スケーリング、新骨格の動的差替えはまだ実装済みではない**。
- 現行装備ローダーはグループ名とPivot位置も使うが、間違った関節を誤認識しない保証はない。実装時に明示的にグループを正規化する。
- 現行装備ローダーが使用するのは `vertices`/`faces` を持つメッシュ要素。Cubeのみの入力は変換または読込器の機能追加が必要。
- 現行装備スロットは `head`, `torso`, `legs`, `arms`, `booster`, `weapon_r`, `weapon_l`。腿や膝は**脚スロット内の関節**であり、まだ独立装備スロットではない。
- **v191標準骨格足C**：`models/storage/足C.bbmodel` の左右の靴メッシュを標準 `Foot_L/Foot_R` のピボットに変換して統合済み。`Waist3` 内の `Thigh_L3/LowerLeg_L3/Foot_L3`（右側も同様）を使い、カスタマイズ `LOWER BODY=C` で標準A腰・腿・膝下の複製メッシュと靴Cのみを表示する。D鳥足は別骨格。今後「足」だけの投入では他の腰/腿/膝メッシュを無条件に輸入しない。
- Bセットは現行コードで赤く着色される。新装備の配色とUVは現在のパレット方式と照合し、ユーザー意図と異なる着色を避ける。
- 生成データだけを手作業で編集しない。Aの既存キーフレームや原本を失わない。

## v192 足Cを独立装備として選択・カスタマイズ画面の接地補正停止
- 足Cの4メッシュは`LOWER BODY=C`ではなく、独立した`FEET=C`で交換する。LOWER BODYの通常脚A/B、逆脚Dは維持する。鳥足D装着中は鳥足付属の足を優先し、FEET A/Cの選択自体は保存する。
- ヘッドCは独立したHEAD=Cとして従来どおり共存する。過去の`legs=C`は標準脚A＋足Cへ安全に移行する。
- 訓練室のみ静止足裏から全身Y位置と当たり判定を補正。NEXUSのセラは展示用ルート姿勢・カメラフィットが位置を管理するので、`set_exhibition_mode(true)`で接地由来の全身位置調整を無効化する。

## v193 — 最新のLOWER BODY運用（v192のFEET規則より優先）
- **FEET独立スロットは廃止**。最新版の装備は下半身 `LOWER BODY=A/B/C/D` を使用する。
- `LOWER BODY C` = 以前Dに登録された鳥足（逆関節脚）。専用6ボーン・専用キーフレームを保持。
- `LOWER BODY D` = `足C.bbmodel` を基に追加した標準骨格の新規下半身セット。統合ファイルの `Waist3` 配下に腰・腿・膝下・足を配置したモデルをDとして登録。HEAD Cは独立して維持。
- v191/v192時代の保存済み装備選択はスキーマv2で一度だけ変換。v192の独立FEETは現在使わず、訓練時の接地補正は選択したLOWER BODYに基づく。NEXUSでの展示用モデル位置補正は引き続き無効。

- v193 Dは元の`足C.bbmodel`から **腰2・腿4・膝下2・足4の全12メッシュ**を取り込み、標準Aの関節Pivotに変換。Aのメッシュの単なる複製ではない。元モデルのfaces/UVとキー値は保持し、実行用スナップショットを再生成する。


## v194 — 標準骨格の下半身Dを専用実装ファイルから登録
- 更新原本 `models/storage/足C (1).bbmodel` の制作階層を整理した `models/storage/SERA_LEGS_C_AUTHOR_NORMALIZED.bbmodel` は制作用マスターです。
- Godotのカスタマイズ `LOWER BODY D` では、A骨格互換へ変換済みの `models/storage/SERA_LOWER_BODY_D_STANDARD_READY.bbmodel` を専用読込します。出力用埋込は `tools/rebuild_lower_body_d_data.py` → `assets/sera_lower_body_d_data.gd`。
- 旧統合モデルのWaist3からはHEAD Cのみ登録します。Dの下半身は腰2・腿4・膝下2・足4の12メッシュが揃った場合のみ選択可能にし、二重登録は避けます。鳥脚はLOWER BODY Cのまま、保存スキーマはv2を維持します。
- `tools/v194_lower_body_d_customization_self_check.py` を実行。元モデルの面・UVと標準骨格対応の静的検査であり、Godot Androidの実機表示保証ではありません。


## v195 — 原本の脚D形状・色の再現
- v193/v194では標準A骨格のパーツごとに別倍率で縮小しており、新しい脚の幅・シルエットが失われていました。腰・腿・膝下・足の12メッシュを原本の相対配置・縦横奥行比を維持する**同一倍率0.36**で変換する方式に変更しました。
- 変換元は SERA_LEGS_C_AUTHOR_NORMALIZED.bbmodel、ゲーム内Dは SERA_LOWER_BODY_D_STANDARD_READY.bbmodel。両方の埋め込みデータも再生成します。再生成は tools/rebuild_lower_body_d_from_author.py を先に実行します。
- 元のBlockbenchで色番号1, 3, 5を持つメッシュは、D限定でローズ系の装甲と薄青の靴に対応させます。旧モデルの16x16UVを標準セラの96x32テクスチャとして扱わないこと。
- 元デザインの外形を優先しているため、標準Aの膝・足首の位置との完全一致は保証しません。Godot Androidでのモーション時の追従・接地は確認が必要です。


## v196 — NEXUS展示姿勢と大型下半身の干渉回避
- モデルの形状を勝手に縮めず、NEXUSposeでの肩・上腕だけを、現在選択している下半身と腕のメッシュに応じて補正します。標準姿勢のQuaternionを保存してから補正するため、重ならないセットへ戻すと完全に原姿勢へ戻ります。
- 肩は0.3度刻み・最大8度、上腕は1.5度刻み・最大90度で左右独立に持ち上げます。表示中メッシュの回転後AABBで交差を検査し、最初に交差しない角度で止めます。
- 複数セットに固定値を割り当てないこと。NEXUS以外のモーション、元NEXUSpose、カスタマイズの保存選択、操作には影響させない。AABB判定は安全側ですが、凹型メッシュでは余分に回転する場合があります。

## v197 — NEXUSpose腕の過剰持ち上げを修正
- v196では腕の回転後AABBの空白まで接触判定となり、追加角度が最大90度に到達する場合がありました。
- メッシュの向きに追従するOBBの15軸分離判定で実際の干渉を判定し、AABBは一次判定のみとします。
- 追加角度は肩最大3.2度、上腕最大24度。元姿勢から開始し、最小の非接触角または最も干渉が減る最小角を選択。改善がない場合は元の角度に戻します。


## v199 — 訓練室のアニメーション追従接地
- 装備の下半身A/B/C/Dを切り替えた時だけ高さを合わせる方式では、歩行・待機中の腰の移動や靴の回転で足裏が床から浮く場合があります。
- 現在表示している左右の靴の三角形頂点から足裏の最低Yを毎ポーズ計測し、最も低い足裏を訓練室の可視グリッド上面Y=-0.0335へ合わせます。回転したAABBの空白を接地点と誤認しないこと。
- 変更するのは表示用SERAリグのY位置だけで、プレイヤーの位置・カプセル・移動・オリジナルのアニメーション・足音判定は維持。ジャンプ中は補正しない。NEXUSの展示では従来どおり無効。
- `python3 tools/v199_animated_sole_grounding_self_check.py` と実機での足元表示・ジャンプ・脚装備切替を確認します。

## v200 — RUNの接地タイミングと360°ステップ
- v199の全ポーズ毎フレーム補正を制限します。まず装備ごとの従来の固定Y位置へ復元し、WAITのみ継続接地、RUNのみ足音イベントが発生する瞬間に一時接地します。通常攻撃・バッシュ・ガード・被弾・ブースト・全方向ステップは追加接地を行いません。
- フリックは上下左右と斜めを含む360°の角度を連続入力として扱い、側面の周回、後方4m、前方暫定2mと中間方向を合成します。Step_L / Step_R / Backstep / Boost_frontのモーションを方向に合わせて補間し、入出時にフェードを使用します。
- 操作・移動の既存安全条件、モデル、原本アニメーション、保存、NEXUS表示を維持。検査は tools/v200_contact_omni_step_self_check.py。
