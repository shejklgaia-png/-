# NEXUS 全身シルエット：隠れた背面線を出さない描画修正（2026-11-23）

## 実機で確認された問題

PR #805でNEXUS通常枠線をステンシルから不透明深度テクスチャ参照へ切り替えたところ、従来の「ほとんど枠線が出ない」問題から、**手前の装甲で隠されるはずの背面の線や内部の不要な線が黒く描画される**問題に変わった。ユーザーから異なる回転角のAndroid画面2枚を受領した。

前回の本番シェーダーは `depth_test_disabled` のままで、深度テクスチャの手動比較が機能することだけを前提にしていた。GL Compatibility実機上で、その比較だけでは奥の線を抑制できなかった。また全トポロジエッジを一律に3pxの候補としていたため、そもそも最外周ではない線が多かった。

## 今回の通常表示修正（診断0、1、9）

- `sera_nexus_stencil_edge_outline.gdshader` の **`depth_test_disabled` を外し**、GPUの標準深度テストを有効にする。輪郭パス自体は `depth_draw_never` のため、線は深度バッファを書き換えない。
- 本番の `hint_depth_texture` サンプリングと `FRAGCOORD.z` の手動深度比較は削除。これまで実機で正しく隠れた線を除外できていないため、従来の「深度テクスチャだけに頼る」方法は廃止。
- 生成済みのリボンが保持する第一面法線（`COLOR.rgb`）と隣接面法線（`CUSTOM0.xyz`）をカメラ空間へ変換。**隣接面の前向き／後ろ向きが切り替わるエッジ**にのみ輪郭候補を絞り、通常の両前向きパネル境界は除外する。`CUSTOM0.w < 0.5` の開放境界は候補とする。既存 `sera_live_mesh_edges.gdshader` の判定仕様と同じ符号・閾値を使う。
- 背面で隠れた線はGPU深度テストで棄却する。画面上±3pxのリボン押し出しと短い端点補完は維持し、輪郭を持つメッシュの回転に同じフレームで追従させる。自己深度の揺れを軽減するため、目線方向に少量だけオフセットする。
- 全29可視パーツの自動登録、キャッシュ、通常色 `#0B1118`、NEXUS全身プレビュー限定という範囲を維持する。煙・FXの除外ルールや元装備材質を変更しない。

## 診断と制約

- 診断1「外周候補」、9「合成確認」では本番と同じ**GPU深度テスト＋面向き判定**の輪郭を青緑に色分けする。
- 診断16は従来のマスクなし全エッジ（深度と面向きによる選別をしない）を残す。旧ステンシル関連の診断17/18もそのまま残す。
- 通常時に旧ステンシル・反転ハル複製を描画・生成しない方針は維持する。
- メッシュ個別の表裏境界を候補にするため、パーツを跨ぐ正確な**全身一体の最外周**を数学的に保証するものではない。隠れた線は基本的にGPU深度テストで取り除くが、装甲同士の接触、非常に近い深度、薄い形状、境界のわずかな隙間では短い線が残る可能性がある。
- 画面上の実測3px、Xperia 1 Vにおける回転時の安定性・fpsは未確認。実機画像で通常表示と複数方向を確認するまで完成とは判断しない。
- UIとレンダラー以外（戦闘・単体プレビュー・BASE施設・クレート・敵）は変更していない。

## 運用

ユーザー指定によりCIテスト項目の確認・修正・適用およびテスト実行は行わない。

## 根拠

Godot 4.7 Spatial shaders の `depth_draw_never`・`depth_test_disabled`・`MODELVIEW_MATRIX` の仕様、既存の `sera_live_mesh_edges.gdshader` における表裏輪郭判定を参照。
