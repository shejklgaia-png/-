# SERA NEXUS：全身マスク＋画面空間エッジ外周（2026-11-23）

## 採用理由

NEXUS全身枠線の反転ハルは、全14種類のステンシル・カリング診断、＋8px／－8pxの法線押し出し比較でも、全身外周を安定して生成できなかった。画像では法線方向へ頂点を押す処理自体は反応していたが、モデル全体の外側へ一定幅の領域を作れるとは限らなかった。

頂点法線による外形推測を通常描画から外す。既に生成できているトポロジエッジと、全29件を一体のステンシル値17として扱うマスクを組み合わせ、**最終表示を画面上で切り分ける**。

## 通常の描画パイプライン

1. `SeraStencilHull` は表示中の不透明装備メッシュ（頭部・胴体・腕・脚・ブースター・武器）を自動登録する。原本は変更せず、モデルの子になるメッシュコピーでステンシル値17を書き込む。書込パスの優先度は **-22**。
2. `SeraLiveMeshEdges` は同じ表示中のメッシュから、GPUエッジリボンを生成してキャッシュする。**全トポロジエッジ**を候補とし、ポリゴン面の表裏を使うエッジ選別は行わない。
3. 新しい `sera_nexus_stencil_edge_outline.gdshader` は、各エッジの両側へ画面ピクセル基準で3px幅のリボンを伸ばす。端点も最大2.5px延長し、角の微小な隙間を減らす。
4. 輪郭描画は透明パス優先度 **-21**、`stencil_mode read, compare_not_equal, 17`。**全身の投影領域内の画素は描画されず、領域外の0〜3px幅のみ残る**。他のメッシュに遮蔽される内部エッジも、全身領域内なら消える。
5. `SeraStencilHull` の平滑化反転ハル描画は**通常表示では無効**。診断用の「ハル単独」「全身＝」「面反転」「法線±8px」では使用可能な状態で残す。
6. 同じNEXUSの3Dカメラ／Viewport上で、原本メッシュの子として描画する。別Viewport／CPUの毎フレーム輪郭計算を行わず、装備交換にも自動追従する。

## 表示仕様

- 通常外周：`#0B1118`、画面上3pxの外側ストロークを目標。
- モード1「外周候補」とモード9「合成確認」：**同じ新方式**を青緑色で強調表示。
- モード2〜5：従来の面向き判定・全エッジ・開放境界・接合線・深度無視診断を維持。
- モード6〜8／10〜15：対象メッシュ・マスク・旧ハル・較正立方体・法線比較の従来診断を維持。
- 通常の接合線計算は実施しない。装備間の交差線は診断でのみ生成。
- グラフィック設定の「キャラクター枠線ON/OFF」を尊重する。

## 制約

これは**全身の真の2Dマスク画像に半径3pxの円盤を畳み込む厳密なモルフォロジー処理ではない**。エッジの3px画面リボンを全身ステンシルでクリップする実装であり、稀にエッジ同士の角や極小形状で幅の誤差、短い欠落が起こり得る。外周の数学的厳密性を保証するものではない。

- マスクが正しくGPUに書き込まれない端末では、内部の全エッジが見える可能性がある。Godot 4.7のGL Compatibility／Android実機上での見た目は未確認。
- 元モデルの可視領域をマスクするため、透明レンズ・FXなどはこれまでどおり除外する。薄い開放メッシュ・特殊な非多様体は個別の確認が必要。
- `depth_test_disabled` のためNEXUSの独立プレビュー以外（戦闘／前景3D遮蔽）には直接流用しない。
- 30fps/60fpsの描画負荷や端末メモリ使用量は未測定。GPUエッジ・ステンシルマスクの組み合わせはCPUによる毎フレーム再生成を不要にするが、追加メッシュ描画を伴う。

## 変更範囲・運用

NEXUS全身プレビューのみ。単体プレビュー、戦闘、クレート、敵、BASE施設は変更しない。実装・マージ時のCI項目の確認・修正・適用およびテスト実行は行わない。
