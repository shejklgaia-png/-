# SERA 拠点：工業施設リファレンス再構築（2026-11-21）

## 目的と基準
提供された縦画面の俯瞰リファレンスに合わせて、床一面に細かい金属板を敷き、
NEXUSを上段中央、LABOを中段中央、6つの独立施設を外周に配置します。
既存の正投影カメラ（FOV=0相当）、画面内の施設配置、タップ判定、CRATE巡回、
NEXUS画面遷移、LABOの製作/素材変換/倉庫機能は保持します。

## 3Dモデル
- NEXUS：装甲外壁、棟屋根の個別継ぎ目、エントランスの重量扉、橙と青の照明、屋根室外機、配管、左側の布製張り出し、カーゴ箱、壁面エンブレム。
- LABO：半開放の作業場、布製天幕、支持柱、工具掛け、作業台、発光情報端末、貨物。
- 精製装置：燃焼炉、橙の溶融口、耐熱格子、排煙筒、熱配管と制御盤。
- 分解装置：投入口、5本の回転刃状ローラー、側面モーター、排出トレイ、黄の注意表示。
- 回収機：スクラップ槽、油圧ブーム、チェーン、左右の把持爪、機体の駆動部。
- 資材保管庫：重ね積みの鋼製コンテナ、積荷固定レール、布カバーと結束帯。
- 発電機：青い横置き発電コア、巻線と支持体、制御盤、電源配管。
- 建設端末：大型ディスプレイ、青い設計図グリッド、鍵盤、通信アンテナ。

設計は `scripts/sera_base_architecture.gd` に集約。
設備ごとに別々のモデル階層を持ち、共通外装パーツの造形はコードで
座標・サイズ・材料を指定します。個別パーツは `MultiMesh` による材質別バッチ描画です。
モデル元の正本 `.bbmodel` は変更しません（今回の拠点設備は新規プロシージャル建築）。

## 床
既存の256m鋼板敷設（`GridPlateBatch_*`）を維持し、
画面内を中心とする追加インスタンスとして、各パネルの縁、ボルト4本、
規則的な排水グレーチング、補修ハッチ、黄の破線、暗い配線とクランプ、
床面ステンシルを追加します。ローカル床専用に影生成を無効化し、
不要な動的オブジェクトを増やさずGL Compatibilityに対応させます。

**注意**：添付イラストに含まれる既存3Dモデルデータは利用できないため、

## 床パネルの不定形化（2026-11-21）
- 暗いチャコール6色、反射の低い金属材、天幕、設備モデルは不変。
- `scripts/sera_base_deck_layout.gd` で拠点床全域（85×85の3m論理セル）を、1.5m補修板・3m板・3×6m長方形・6×6m大型板・最大9mの細長い鋼板へ決定的に分割します。グリッド線を視覚的にランダム化するだけではなく、実際にMeshInstanceのサイズを変えて敷き詰めます。
- 各パネルの論理領域は重なりなく隙間なく面積を覆い、可視メッシュ間の継ぎ目のみ6cmです。継ぎ目から暗い連続床が見えます。
- 6系統の `MultiMeshInstance3D` の描画バッチを維持し、BoxMeshを1m正規化して各インスタンスのTransform3Dで幅/長さを指定します。
- `scripts/sera_base_floor_detail.gd` は同じ分割データを受け取り、実際の四辺に合わせて目地、ボルト、グレーチング、補修ハッチを敷設します。廃止された3m等間隔の偽の目地を重ねません。
- 既存の6色・外周カリング・カメラ・CRATE/施設配置・倉庫/装備/精製機能は維持。旧3m正方形だけを検査する回帰期待値を更新し、新たに全床の半セル単位で非重複・全面被覆を照合する静的/Godot検査を追加します。

## 2026-11-21：施設の足元は必ず一枚パネル
依頼：NEXUS・LABO・ほか6設備はそれぞれ余裕のある一枚の金属パネルの上に置き、床パネルの継ぎ目をまたがせない。

- 施設位置は現行 `NEXUS_BUILDING_ORIGIN` と `BaseFacilities.FACILITY_SPECS` を参照。座標を重複定義せず、カメラ・操作・施設位置を動かさない。
- `BaseDeckLayout.facility_sites()` で計8個の設置範囲を決め、`generate()` に渡す。最初に一枚板の領域を1.5m解像度の論理格子に確保し、残りの未使用格子だけを小中大型の不規則床パネルで埋める。
- 予約範囲はNEXUS最低10.5×10.5m（現行座標では12×12m）、LABO最低7×7m（現行座標では9×7.5m）、各設備は原則実機の外形寸法＋3m（概ね6〜7.5m級）。四辺で実機モデルから最低1m以上の空間を確保する。
- 全体の床面積は以前と同じ255×255m、隣接パネル間の幅は6cm、床6色のMultiMeshバッチを維持。板の重複・穴は許容しない。衝突した予約はエラーとして検出する。
- 専用大型板の内側にはランダムな補修継ぎ目・ハッチ・グレーチングを追加しない。四辺の目地と固定ボルトのみを配置する。施設は一枚板全体の内側に収まる。
- テスト先行で `base_facility_single_panel_self_check.py` / `base_facility_single_panel_runtime_check.gd` をCI登録。全8板のID一意性、物理的余白、全床の一度だけの被覆、描画バッチ・インスタンス数を検証する。従来の非等間隔床テストも施設配置を渡す方式へ更新する。

## 施設の抜け感と密度のリズム（2026-11-21）
施設周辺の小物を等間隔の左右3+3に均等配置する方式を改め、各施設で**密集側4個以上＋抜け側2〜3個**とする構図へ刷新しました。密集側は約1.1mピッチで4点を寄せ、対向側には3m以上のまとまった空白を残します。NEXUSとLABOは5+3、ほか6施設は4+2。後者は左右の密集側を3施設ずつ交互に割り振り、拠点全体で同じ方向に偏らない視覚リズムとしています。各施設には小スケールのアクセント1組を混ぜ、2段/3段積みの山と単品の低い小物を対比させます。
52組の総数と19組の積載指定、種類・材質・MultiMeshバッチ・専用1枚床板・設備中央保護領域を維持。追加テスト base_prop_density_rhythm_self_check.py／base_prop_density_rhythm_runtime_check.gd により密度の非対称性、4点の近接リズム、対岸の2.5m以上の空白、左右交互、全52組・積載数を検査します。入口方向には新規小物を増やしていません。


## 2026-11-21：コンテナのサイズ差とランダムな積載数
ユーザーの指定に基づき、コンテナを全部同じ大きさで垂直一列に積む方式を廃止します。
- 小物52グループの施設位置と「密集→余白」の構図は維持。コンテナ（cargo_box / fastener_box / power_box / battery）は、施設ID・種類・項目番号を基にした固定シードの疑似乱数で各グループにつき1〜4個の積載数を決定。その他の積載可能な資材は1〜3段でばらつかせます。再起動によって配置が変わらず、Android実機とCIで同じレイアウトになります。
- 1個なら単独の大中サイズ、2個は大型の下段＋小型上段、3個は下段2個を横に並べて上に小さな1個を橋渡し、4個は下段2個＋それぞれの上に小型2個。大中小のサイズを混ぜ、同じ箱の引き伸ばしではなく別々の3Dメッシュを一括バッチへ出力します。
- 各箱の幅・奥行きは既存52小物グループの占有矩形内に収まる寸法として計算。上段は支持下段の天面高さに揃え、支持関係（support index）をデータへ記録。浮遊、同じ高さの箱同士のめり込み、施設の入口や床パネル外への張り出しを禁止。スキッドは地面に接する1組だけ。
- 個別MeshInstance3D/Collider/Lightは追加せず、既存の材質別MultiMeshにBox/Crate等を集約。乱数処理はシーン初期構築時の決定的な整数演算のみで、毎フレーム実行しません。
- 新規 `base_container_stack_variation_self_check.py` と `base_container_stack_variation_runtime_check.gd` をCI登録。1〜4個全種類、2+1の三角積み、大小の支持、容積重複なし、床境界内、固定シードの再現性、実描画出力と一致することを検査します。以前の「2段13件、3段6件」を固定した履歴テストはユーザーの新仕様を照合するよう更新します。
