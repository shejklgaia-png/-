# ビットタラン戦：GPUのみの3種類の稜線とゼロフレーム追従（2026-11-23）

## 対象と目的
ユーザー指示により、**ビットタラン戦だけ**、可視RGB ID式の「外周・分離メッシュ境界」をGPU式に置換する。後続の仕様変更でキャラクターの凸角は廃止されている。通常訓練・NEXUS・拠点・単体プレビューの可視ID方式は一切変更しない。

## 2026-11-23：外周シルエットの非対称線幅
- ビットタラン・プレイヤー（セラと装備）の輪郭は **モデル内側1画面px＋外側5画面px**。従来の線中心から左右同幅に広げる方式を使わず、隣接面と稜線の向きからGPUでポリゴン内側方向を投影して判定する。
- 入力メッシュの三角形の頂点順序により、face A は `cross(normal_a, tangent)`、face B は稜線方向を反転した `-cross(normal_b, tangent)` が各面内部を示す。この方向を実際のカメラ投影へ移して内／外のリボン幅を選択する。カメラ移動・振動・IK変更時も別Viewportの同期は不要。
- 頂点座標に使う画面ピクセル幅はNDC→実画面ピクセルの係数2を考慮する。開放メッシュ境界は従来どおり内1px／外3px（境界用のseam幅3px）を維持。深度テストも維持する。
- メッシュ同士の交差部はトップロジーの実稜線からの方式では再現できない場合がある。Android実機の最終的な内外幅は未検証。

## 2026-11-23：角の途切れ対策（GPU端点キャップ）
- 外周を5pxへ拡張後、ビットタラン装甲の角で輪郭が欠ける実機画像を確認。原因は、GPU線分の各リボンが端点で終了し、隣接線分との外側ストロークをつなぐキャップがないこと、および各頂点ごとに前面・背面を判定していたこと。
- ビットタラン専用フルGPU稜線では、各辺の中点を `CUSTOM1.xyz` に保存し、シェーダーの面方向判定を線分全体で同一にする。長い稜線の端だけ消える問題を防ぐ。
- `UV.y=-1/+1` を線の始点・終点として符号化し、画面空間で最大5pxの短いスクエアキャップを描く。線分の間にできる三角形状の隙間を埋め、別の描画パスやID用Viewportを増やさない。
- 元の内側1px／外側5px（開放境界は外3px）、凸角OFF、GPU深度判定、同一カメラ追従を維持。鋭角の隅ではキャップ同士の重なりで少し太く見える可能性があり、実機の最終結果は未確認。

## 戦闘専用の構造
- `bittaran_battle.gd` は `super._ready()` より前に `sera_bittaran_gpu_outline` を設定。SERA・ボスの14ボーン・砲台等の `ViewEdges` 登録は共通のまま、親をたどってこのタグを検出したときだけ **IDコンポジタ／ID SubViewport登録をスキップ**。
- 代わりに既存の `nexus_sera_gpu_convex_silhouette.gd` の任意フラグ `enable_combat_gpu_full_edges` を使い、共通のトップロジー抽出メッシュから、開放境界、隣接2面の前後判定を含む稜線リボンを生成。キャラクターの凸角描画は廃止。NEXUS／通常戦闘の既存動作は不変。
- `shaders/sera_bittaran_gpu_contours.gdshader` の頂点段階でシルエット（前面／背面または接線）と独立メッシュの開放輪郭を選択。閉鎖メッシュの外周は内側1px／外側5px、開放メッシュ境界は内側1px／外側3px。凸角なし。通常のGPU深度テストを使い、隠れた別装甲の線を抑制する。ポストプロセス、別World3D、IDカメラ、全画面の近傍ピクセル検索は不要。
- 稜線メッシュは**元MeshInstance3Dの直下**に子として配置。元の形状・アニメーション・破壊時の表示状態・カメラのh/v_offsetを直接継承。同一フレームで追従し、カメラ投影の二重同期は不要。
- トポロジ抽出結果はMesh単位でキャッシュ。1.05秒ごとに破損部位や装備差し替えを走査、変更なしなら再生成しない。オプションON/OFFの確認も走査時に限定し、毎フレーム設定ファイルにアクセスしない。
- マテリアルは1共有ShaderMaterial/コントローラー。輪郭シェーダーは元の装甲材質を変更しない。FXを対象外にし、リボンは自分自身を再走査しない。輪郭オフ時は該当リボンを非表示にする。
- 旧可視ID描画は他画面用に残す。ビットタラン戦ではID Viewport生成・ID カメラコピー・毎フレームID更新・投影ずれ補正を使用しない。

## 限界
トップロジー境界しか描画しないため、異なるメッシュの**内部交差線**（モデルの辺が存在しない曲線状の交差部）まで完全に再現することはできない。また、実機のGPU負荷は稜線数と端末の描画ドライバに依存する。

CI項目の確認・修正・適用は行わず、CI、Godot、Android等のテストは実施しない。実機での枠線連続性／FPS／描画レイヤーは未確認。
