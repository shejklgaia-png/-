# NEXUS ステンシル書き込み・読み取りの独立診断（2026-11-23）

## 背景と目的

NEXUS全身の輪郭では29/29件の可視メッシュが登録できているが、反転ハルが部分的に面として表示され、共通ステンシル合成では外周の大部分が消える。以前の「マスク表示」は描画パスを橙に着色しており、ステンシルバッファに正しい値が書かれたこと自体は確認できなかった。

今回の目的は **(1) Godot GL Compatibility実機でステンシル write/read が単純な立方体に対して機能するか、(2) 全身の参照値17と反転ハルのカリングのどちらに問題があるか** を診断表示で区別すること。通常の本体輪郭ロジックと見た目は変更しない。

## 追加モード（NEXUS → カスタマイズ → 輪郭診断）

従来のモード0〜9を維持して、次の4種類を追加する。

| モード | 期待する見た目 | 切り分け |
| --- | --- | --- |
| **立方体＝** (10) | 画面左側の小さな較正立方体。書き込み値29と一致する部分だけ**緑**、書き込み用の橙は薄い | 値29のwrite→compare_equalの成立 |
| **立方体≠** (11) | 立方体より少し大きい比較メッシュのうち、**マスク外側だけ紫**、中心部は抜ける | 値29のwrite→compare_not_equalの成立 |
| **全身＝** (12) | 全身のマスク値17と一致する反転ハル画素が**緑** | 値17の読み取りと、合成を行う際の配置関係 |
| **面反転** (13) | ステンシル無効・カリングだけを裏返した反転ハルが**橙** | ハル単独（紫）と比較して頂点方向・カリングを区別 |

「立方体＝」「立方体≠」では実際のセラ本体のマスク・ハル描画を停止し、専用の小さなBoxMeshを書き込み用と読み取り用に使う。セラの値17と干渉しないよう較正立方体だけ **ステンシル値29** を使う。画面左の3D領域にカメラ向きに追従して配置し、診断モードを閉じると非表示。比較メッシュは書き込み立方体より18%だけ大きくし、一致／不一致の違いを見やすくする。

立方体のwriteとreadの両方で、**深度テストは意図的に無効**。これはステンシル値の比較だけを切り分けるため。立方体の診断が成功しても、セラ全身の深度付き描画、順序、平滑化ハルが正しいことを保証するものではない。

## 判定例

- 「立方体＝」緑・「立方体≠」中心抜け紫 → 単純な立方体ではステンシルのwriteとreadが成立。全身のマスク深度・描画順・カリング・押し出しが次の疑い。
- 「立方体＝」全く緑がなく「立方体≠」紫が全面に出る → 書き込みが成立していないか、比較が常に不一致になっている可能性。
- 立方体両モードが同じ見た目 → 比較条件・描画順、またはAndroidのCompatibility側の制限を疑う。
- 「全身＝」だけ緑で「合成確認」が消える → 反転ハルの画素の多くがマスク領域内にあり、マスク外への拡張不足などが疑わしい。
- 「ハル単独」（紫）と「面反転」（橙）で広い面の描画が入れ替わる → 法線・裏表カリングの不一致を疑う。

いずれもスクリーンショットによる視覚的判定であり、ステンシルバッファをGPUからCPUへ読み出して値を測定した結果ではない。

## 範囲・運用

- NEXUS全身プレビュー・診断UIだけに追加。
- 既存の「通常」のステンシル＋反転ハル、線幅3px、色 `#0B1118` は変更しない。
- 既存のGPUエッジ診断と装備自動登録も維持する。
- 診断外は立方体を描画せず、関連の描画やパーツへの干渉を避ける。
- Godot 4.7 のステンシルは実験的機能。Android GL Compatibility実機で動作するかは未確認。
- CI項目の確認・変更・適用およびテスト実施は禁止ルールどおり行わない。
