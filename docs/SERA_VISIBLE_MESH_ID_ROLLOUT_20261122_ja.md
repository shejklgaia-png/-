# SERA 全3D場面：アイリス方式の可視メッシュID輪郭 (2026-11-22)

## 変更の目的
アイリスのH02単体プレビューで採用済みの「深度で隠れるメッシュID→画面ピクセル上の境界→3px輪郭」をSERA全体の共通方式にする。反転ハルの法線方向拡張、深度近傍4方向サンプリングは使わない。黒い面の塗りつぶし、急角度の誤線、輪郭の欠けを構造的に回避する。

## 対象
- NEXUS：全身SERA・装着中／交換候補モデル・建築バッチ。建築物の旧ポリゴン縁next_passを無効にする。
- 単体プレビュー：通常頭部・胴体・腕・脚・ブースター・武器。既存の `EquipmentPreview` 内 `SeraRig/ViewEdges` を共有方式へ変更する。
- アイリス単体：承認済みの6部品専用ID輪郭はそのまま使用。切り替え時は共通レンダラー側を無効化し二重の線を防ぐ。
- 戦闘：SERAプレイヤー、トレーニング標的、ビットタラン全身・砲塔。モーション時はメッシュの世界座標／表示状態の変化に応じてID描画を更新する。
- BASE：建物・設備・移動中のCRATE・資源／装飾の不透明メッシュ。古い施設リボン外周／角線の表示は無効化し、元データは保持。
- LAB：製作／精製／分解／倉庫の専用サブビューポートに適用。倉庫の装備3Dプレビューも同じ方式。
- PNGの静止装備サムネイル、2D UI／文字／素材ドット絵は3Dジオメトリではないため今回の描画対象外。

## 内部構成
1. `scripts/sera_view_edges.gd` は従来の反転ハル生成を廃止し、Viewport単位の輪郭コンポジタへシーンルートを登録する薄いノードになる。
2. `scripts/sera_scene_id_outlines.gd` は1個のID用 `SubViewport` と1個の `TextureRect` を描画用CanvasLayer(1)に配置する。3Dの既定Canvas(0)より後、HUDのCanvasLayer(2+)より前に合成する（ビットタラン固有のHUDは既存レイヤー30）。単体プレビューの独立SubViewportでも同じ順序を使う。操作イベントは受け取らない。
3. MeshInstance3DとMultiMeshInstance3Dの不透明な実モデルのみを別ワールドへ低負荷の識別色で複製描画する。元メッシュ、UV、原本テクスチャ、アニメーション・ヒット判定、元の材質には触れない。元のRGB材質が表示されたままで輪郭だけを合成する。
4. `sera_scene_mesh_id_*.gdshader` は可視メッシュ単位のRGB444識別色。 `sera_scene_multimesh_id_*.gdshader` は `INSTANCE_ID` からバッチ内の個々のインスタンスを区別する（新しいdraw callを一部品ごとに追加しない）。
5. 現行の `sera_scene_mesh_id_outline_safe.gdshader` はアイリス専用版と同じ3px円形近傍、片側だけ線を置く内部境界と外周比較を使用する。RGB444の画面表示値から大小比較用の単一floatへ変換し、ID整数化は行わない。旧 `sera_scene_mesh_id_outline.gdshader` は復旧検討用の参考として残す。
6. RGB444で各Viewport最大4095個の番号を使う。番号は装備変更・再生成時に解放して再使用し、連続する複数番号が確保できない大型MultiMeshバッチは1バッチ単位へフォールバックする（この場合バッチ内部の個々の境界は線にならない）。
7. 原則、姿勢／可視状態／カメラ／モデル差替え等の変化があるときだけIDサブビューポートを更新する。新しいジオメトリの探索は約0.65秒ごと。外部リソースのMultiMeshインスタンス変換値だけがその場で変更された場合は、親の座標が変わらない限り更新通知を受け取れない制限が残る。
8. ID描画用最大画素数は720×1280=921600を目安に制限し、より大きな端末解像度では縦横比を維持してIDを縮小する。低解像度表示時は3px×縮小率で計算し、最終表示に拡大される線幅の差を抑える。
9. 床・地面・背景床グリッドは描画されるがID=0の奥行き遮蔽物とし、他の物体を透過した輪郭が出ないようにする。煙・火花・残像・レーザー・透明発光・衝撃波などエフェクトは識別対象から除外する。
10. 元の建築用輪郭パスはNEXUSとBASEで重ならないよう非表示にする。BASEのデバッグ用旧リボンの形状とマテリアルは保持するが、新しい通常表示には使用しない。

## 既知の制限と注意
- 既存のアイリス専用ID版は変更せず、全場面共通版を別に用意した。画面単位のID描画用ターゲットとピクセル読取りにGPU負荷がかかるため、Android実機のFPSと品質は未確認。
- 複数色でも「一つのMeshInstanceの内部に存在する異材質／ポリゴン角」はメッシュID上で区別されない。アイリスと同様、独立したメッシュ単位の境界のみ対象。
- MultiMeshバッチ内の部品ごとのIDはビルトイン`INSTANCE_ID`を使う。単独MeshInstanceとバッチの識別総量が4095を超えるとグループ単位へフォールバックする。
- レンダリングバッファのsRGBやAndroid機種による描画差異は実機検証が必要。
- 旧反転ハルのシェーダーファイルはロールバック参照として保管するが、`SeraViewEdges`からの描画接続は廃止。

## 運用
ユーザーの運用ルールに従い、CI項目・期待値・設定の確認／変更、およびCI／Godot／Android／手動テストの実行は行わず、指定に従ってmainへ直接マージする。画像生成なし。

## 2026-11-22：共通輪郭の描画順修正
- Androidの診断画面でID画像（Roots 2／Meshes 101／Camera ON／ID 636×1449／Redraw約55）が生成済みと確認できるのに、全身SERAと通常単体の輪郭が描画されないことを確認。
- PR #751のColorRectおよびPR #753のTextureRectでも症状が変わらないことから、コンポジタの矩形形式ではなく**描画CanvasLayerの順序**を修正対象とする。Godotのレイヤー0は既定のCanvasと重なるため、共通輪郭を専用CanvasLayer 1に、NEXUS/BASE/通常戦闘HUDをCanvasLayer 2に明示的に分離する。ビットタランのレイヤー30は変更しない。
- 元のID画像、3px境界抽出シェーダー、モデル・材質・輪郭色・アイリス専用ID処理は保持。輪郭がHUD文字やメニューの上へ重ならない順序を維持。
- CI項目やテストコードは確認・変更せず、CI/Godot/Androidのテスト実行なし。描画復旧は実機未確認。
