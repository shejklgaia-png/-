# NEXUS 共通ステンシル／反転ハル 段階別診断（2026-11-22）

## 背景

PR #796 の後、全身95/95輪郭生成・非対応0と表示される一方、実機では左腕に黒／シアンの大きな面が表示され、その他の外周はほとんど描画されなかった。これだけでは、ステンシルの書き込み失敗か、反転ハルの面カリング・押し出しか、そもそも非表示パーツを描画登録したかを判別できない。

## 登録の修正

- `SeraStencilHull` の登録対象を、FX等を除外した上で `MeshInstance3D.is_visible_in_tree()` が真のメッシュに限定する。
- 診断数値を `候補総数`・`非表示`・`表示対象`・`全身マスク`・`非対応` に分ける。非表示モデルは描画メッシュを生成・維持しない。
- 再走査は従来通り0.35秒間隔。装備交換・表示切替後に登録対象を更新する。
- 元モデルや材質は変更せず、複製描画だけで診断する。

## 診断モード

既存の6モードを維持し、カスタマイズ画面の「輪郭診断」右側パネルに4モードを追加。

| モード | 可視化 | 判別すること |
| --- | --- | --- |
| 通常 | 共通ステンシル＋反転ハル（黒） | 現行表示 |
| 外周候補 | 共通ステンシル＋反転ハル（青緑） | 輪郭の位置 |
| 全エッジ | トポロジエッジ（黄） | 既存GPU抽出 |
| 開放境界 | メッシュの開いた端（橙） | メッシュ形状 |
| 接合線 | 交差補助線（紫） | メッシュ間交差 |
| 深度無視 | 裏側も含むGPUエッジ | 深度の影響 |
| 対象メッシュ | **緑**、現在表示中として輪郭登録された面 | 対象外／余計な装備がないか |
| マスク表示 | **橙**、実際のステンシル書込みシェーダーを着色 | 書き込みパスがラスタライズされるか |
| ハル単独 | **紫**、ステンシル判定を除いた反転ハル | 反転ハル自体のカリング・法線・押し出し |
| 合成確認 | **青緑**、本来のステンシル＋反転ハル | マスクで除外される場所・失敗箇所 |

「対象メッシュ」はステンシル書き込みを伴わない純粋な着色表示。
「マスク表示」では実際のステンシル書込みシェーダーに可視色を設定。ただし**色が表示されるだけではステンシル値が書き込まれたことの証明にはならない**。これを「合成確認」と比較して判断する。
「ハル単独」ではステンシルと輪郭の関係を外して、面状塗り潰しがハル由来なのか確認する。診断色の全面描画は正常な完成輪郭ではない。
各モードの終了時に既存の通常表示へ戻す。

## 原因の目安

- 「対象メッシュ」に不要な装備が見える → 登録対象の判定／原本の表示状態を確認。
- 「マスク表示」が消える → 書込み用の描画・深度・カリング等の問題を疑う。
- 「マスク表示」はあるが「合成確認」が全面塗り潰し → ステンシルの読込み／書込み／描画順の問題を疑う。
- 「ハル単独」で形が破綻 → 平滑化法線／頂点の投影拡張／面カリングの問題を疑う。
- 「ハル単独」は輪郭らしく描けるが「合成確認」で消える → ステンシルの領域／判定・深度競合を疑う。

## 範囲・制約

NEXUS全身プレビュー限定。実装は診断機能と表示対象の登録修正であり、新しい輪郭レンダラーへの切替や通常の線幅の調整はしない。通常の描画方式は実験的なGodotステンシルのままであり、修正後のAndroid結果は未確認。GPUピクセルの自動読出しは行わないため、最終判断には診断モードごとの実機画像が必要。CI項目の確認・修正・適用、CIテストの実行は行わない。
