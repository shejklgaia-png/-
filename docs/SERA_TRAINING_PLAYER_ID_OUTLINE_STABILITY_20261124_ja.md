# トレーニングのプレイヤー＋ターゲット：可視ID輪郭の追従精度・ちらつき抑制
更新：2026-11-24

## 観測
PR #893でトレーニングをビットタランと同じCompletedBattleFrame構造に変更し、トレーニングターゲットの頭部と赤いBODYの交差を修正した。最新スクリーンショットでは、プレイヤーの手足がアニメーションされ、ターゲットの周囲に赤い短い線が見える。赤い短線はゲーム内の攻撃・シールドエフェクトなどの可能性があり、黒い可視ID輪郭のちらつきとは分ける。静止画像のみで、ちらつきの頻度・原因を確定することはできない。

## 改善内容
1. `scripts/sera_scene_id_outlines.gd`：プレイヤー（SeraRigと装備）・ターゲット（FloatingBoxと頭/4脚）は、物理補間される`Player`／`VirtualTarget`の根元のTransformを描画フレームで**一度だけ取得**し、各子メッシュについて「現在の親物理Transform^-1 × 現在の子メッシュTransform」を相対姿勢として乗算する。
   - 根元の物理移動は補間済みで滑らか。腕・脚・武器など`_process`で動く部位の姿勢はそのフレームの生の相対Transformを維持し、二重補間で部位だけ遅れる可能性を抑える。
   - `Engine.get_process_frames()`単位で補間根元のTransformをキャッシュ。画面内の多数の子メッシュが**同一時点の補間値**を共有し、何度もAPIを呼ばない。
   - 複製モデルだけでなく、外周描画に用いるスクリーンAABBも**同じ合成済みTransform**で計算。ステップ中に境界探索が範囲外で切り落とされることを抑える。
   - 物理補間された根元が存在しない静的・描画更新モデルは従来どおり`global_transform`を使用。BASE/NEXUS/装備プレビューの同期方法・幅設定に影響しない。
2. `scripts/target_parts.gd`：当たりエフェクトで毎フレーム揺れる頭部/脚部の`pivot.physics_interpolation_mode`を`OFF`に設定。移動する赤い本体`VirtualTarget`だけは従来どおり補間ONを維持し、その補間済みworld Transformを子部位へ伝播。外観の被弾ワブルや部位HP・ロック・当たり判定を変更しない。
3. `shaders/sera_visible_mesh_id_outline_core.gdshaderinc`：`texture(nearest, UV)`による座標参照を`textureSize`＋`ivec2(floor(...))`＋`texelFetch`へ変更。実際のIDターゲットサイズで**整数ピクセルを1個だけ**読み、半テクセル境界やSubViewportスケーリングによるID画素選択の曖昧さを減らす。外周・可視ID片側所有者ルールは変更しない。高解像度追加のIDバッファ、GPUフェンス、ブラー、時間方向の画像蓄積は導入しない。

## 維持する既存仕様
- 共通可視RGB12 ID方式＋完成フレーム構成、`process_priority=10000`で姿勢を更新する方式を継続。
- トレーニングの**シルエット内1px／外3px／メッシュ境界3px**、ビットタランの内0px／外3px／境界1px、他画面の役割別幅を変更しない。
- 3Dモデル/材質、装備表示、ゲームの操作・衝突・カメラ制御、HUD、赤い本体・ダメージエフェクトは変更しない。
- 共有シェーダーの整数IDサンプリングは全画面で使う（処理自体の統一は維持）。

## 制約と未確認事項
- ちらつきの原因が別GPUターゲットの更新待ちや、実際の3Dモデルの同一平面重なりであれば、この姿勢/画素参照の改善だけでは完全には消えない。赤い発光線は輪郭ではなくエフェクトの可能性があり、別調査が必要。
- 別SubViewportの完了を同期するGPU fenceは実装していないため、実機の時間的ゼロ遅延・FPS向上は保証しない。
- ユーザー指定のため、CI設定/CI項目/テストの確認・変更・適用、Godot/Android/CI動作テスト、画像生成は行っていない。
- **ユーザーが今回は「マージ」と言っていないため、PRのみ作成しmainには未反映。**
