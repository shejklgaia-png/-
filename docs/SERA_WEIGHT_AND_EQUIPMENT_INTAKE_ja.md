# SERA — 装備重量・EN出力・装備追加フォーム（暫定仕様）

## ゲーム本体への反映
- 基礎値の唯一の正本は `scripts/sera_part_stats.gd`。7装備部位（頭部・胴体・腕部・下半身・ブースター・左右武器）すべてに `weight_pct` を追加。Aは各100%。
- 個別装備の重量を全身の基準質量比（頭10%、胴26%、腕17%、脚23%、ブースター9%、右武器9%、左武器6%）で加重平均して全身比率を算出する。武器だけ変更しても重量階級は再判定する。
- **軽量 = 70%以下／中量 = 70%超140%未満／重量 = 140%以上**。閾値は境界を含む。参照するのは全身比率であり、頭部だけ軽量なら機体全体が軽量になるわけではない。
- 二刀流・両手持ちの占有規則：カタナKが右手を占有すると通常の左手シールドは表示されないため、重量計算からも左手シールド相当の基準寄与6%を除外する。カタナ側に鞘・左手側の付属メッシュを含む。
- **装備暫定個別重量**：Aは全件100%。HEAD B120%、HEAD C85%、HEAD D（アイリス）65%。TORSO B170%。ARMS B145%。LEGS B180%、C（鳥脚）75%、D165%。BOOSTER B145%。RIGHT WEAPON B150%、K（カタナ）135%。LEFT WEAPON B135%。C/Kも暫定重量を定義する。今後の固有性能・特殊効果は相談後に追加する。現行`get(set_id, A)`フォールバックはゲーム互換性のため保持。
- 胴体の`en_output_mult`はA=1.0、B=1.15。基礎EN回復速度24 EN/秒へ胴体出力と重量階級のEN出力補正を**乗算**する。EN最大値・EN枯渇時60%解禁条件・消費後回復停止条件は維持する。
- 既存の部位固有補正を適用した後に、全身重量階級の補正を**1回だけ**乗算する。重量脚B/Dの古い固定「ダウン5回」は基礎3へ移し、重量階級だけで+2する。二重加算しない。
- ブースト・ステップの「消費効率」は**必要ENを効率値で割る**。軽量120%なら従来ENの83.33%、重量90%なら従来ENの111.11%。EN回復出力とは区別。
- ステップ距離補正は360°フリックと旧後方・側方ステップだけに適用。バッシュ派生のサイドキックとサマーソルトは固有コンボなので従来距離のまま。
- 近接攻撃モーション速度は斬撃・カタナ・バッシュとその予備モーションのアニメーション時計へ反映する。ユーザー入力の受付秒数やヒットストップ秒数は変更しない。
- 近接追尾速度は`_advance_homing_toward_target`の世界位置補間へ適用。物理接触・当たり判定そのものは変更しない。

## 装備追加 HTML
- `tools/equipment_intake/dist/SERA_Equipment_Intake_IRIS.html` はカメラアイ頭部の正本とA/B全身モデル、既存C/D、鳥脚・カタナのモデルを内包。オフライン動作可能。形式は `SERA_EQUIPMENT_INTAKE_V1`。
- 上部タブは MODEL、CUSTOMIZE、ICON、PARAMETERS、RECIPE/EFFECT、ANALYSIS、EXPORT。
- WebGLの全身表示は既存Icon Studio描画器を使った**編成確認用プレビュー**であり、Godot実行時のシェーダー・実機アニメーション・個別モデル接続補正を完全再現するものではない。撮影確定画像は従来通りGodot GL Compatibilityのネイティブレンダリングが正本。
- 本体とは別の軽量フォームでタブ・数値入力・分類プルダウンを管理する。部位に存在しないパラメータはグレーアウト。数値はA基準%・バー・絶対値が連動。
- モデル外接寸法はA基準。負方向サイズ指定は逆倍率で0寸法やミラーを回避（−300%=25%、0%=100%、+300%=400%）。縦横奥行を独立合わせ、形状を保ちたい場合だけ等倍モードを選択。
- 組み合わせプレビューのプルダウンにはモデルから描いたサムネイルを遅延生成。指ドラッグ回転、二本指パン・ピンチ拡大を引き継ぐ。
- MATERIALはSERAの正式な12素材名・内部IDを使用する。SPECIAL EFFECTSと新分類は`review_required`/ `approval_required`を付して文章のままChatGPTへ渡し、本人と相談してからゲーム実装、正式選択肢に追加する。
- レーダーはAを基準に正規化して同一部位の既存パーツを比較。正方形の分布図は軸選択・サムネイル表示・名前検索・個別／全件表示に対応。
- 出力にはGitHub原本パス・SHA-256・設計図ID・部位・選択中全装備・数値・素材・撮影設定と承認待ち事項を含める。共有シートでChatGPTへ渡せない場合は全文コピーを使う。
- `tools/equipment_intake/intake_ui.js`、`intake_preview_hook.js`は保守用ソース。ビルド済HTMLは両方をインライン化した独立ファイル。
- WebGLプレビューは端末ブラウザのWebGL実装差があり、**実機描画未検証**。静的検査は`intake_self_check.py`、ゲーム計算は`weight_runtime_check.gd`。Android実機操作・CIの全実行結果は別途確認する。

## 新装備を登録する場合
1. 最新の`models/manifest.json`とモデル更新履歴を確認し、原本SHAを固定。
2. 同モデルを埋め込んだ装備専用HTMLを生成し、このチャットに提示。モデル再アップロードを要求しない。
3. 本人から`SERA_EQUIPMENT_INTAKE_V1`を受け取り、分類値と自由記述の特殊性能を相談して確定。
4. LAB製作レシピ、固有UID・5件追加性能、倉庫999制限、NEXUS装備選択、セーブ/ロード、アイコン撮影を同一PRで登録し、検査。未承認の数値を創作しない。

## 2026-11-21 装備フォームのタブ整理
- `FULL BODY`: 頭Dアイリス＋他部位Aを初期値とし、全身換装プレビュー/部位別カスタマイズ/対象部位のA基準のサイズ変更だけを置く。
- `ICON`: 一度に装備単体だけを表示。全身モデルは表示しない。
- `STATS / FX`: 部位単体の小型プレビュー、A基準ステータスと特殊効果欄を配置する。必要素材は`RECIPE`専用にする。
- 操作やデータ形式`SERA_EQUIPMENT_INTAKE_V1`を維持し、複数部位の小型サムネイルは各対象部位のみを撮影する。

## 2026-11-21 制作用モデル識別子の扱い
- A/B/C/D/Kは各部位の制作用モデル識別子であり、ゲームプレイの装備セットを意味しない。
- 装備設定フォームの独立した「装備セット」項目を廃止。装備プレビューでは頭部アイリスD、その他は各部位の基準モデルAを個別に初期選択する。以後も各部位は独立して変更できる。
- データの`rig_set`は既存受入形式を維持するための歴史的なモデル参照フィールドであり、選択中の`rig_selection[slot]`から自動設定する。セット装備やセット効果を定義しない。
