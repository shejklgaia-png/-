# SERA NEXUS 全身シルエット：8方向オフセット＋ステンシル共通マスク（2026-11-23）

## 目的と変更理由

PR #810までのGPUトポロジエッジ＋法線/凸角方式は、Android実機で頭部等の外周が途切れたり、手前の凸角が強調される問題が残った。ユーザーは高精細な線や内部の接合線より、**全身の外側だけが確実に分かること**を優先し、**追加SubViewportの1フレーム追従遅延のリスクを拒否**している。

そこでNEXUSの全身3Dプレビュー限定で、同じViewport・同じカメラのGPU透明描画パスを用いる**全身マスクと8方向平行移動**を採用する。辺の抽出・法線・カリングによるシルエット推測は通常表示に使用しない。

## 本番パイプライン（診断モード0）

1. `SeraEightWayOutline` をNEXUSのSERA全身rig配下へ追加する。実際に表示中の装甲・武器メッシュを0.35秒ごとに探索し、生成した補助ノードは**必ず元のMeshInstance3Dの子**にする。回転や関節姿勢に対する輪郭の追従にCPUフレーム更新を要さず、全描画は同一フレームに揃う。
2. 各表示メッシュのオリジナル `Mesh` を参照した**ステンシル専用マスク**を1つ作り、透明描画パスで `stencil_mode write, compare_always, 17` としてマスク書込みする。`cull_disabled`、`depth_test_disabled` のため背面も含めて全メッシュの投影領域をマスクできる。描画優先度は **-22**。元モデルの材質は変更しない。
3. スキンのない通常装備には、オリジナルメッシュを参照した **MultiMeshInstance3D 1つ・8インスタンス**を用意する。全インスタンスの3D変換は恒等で、シェーダーの `INSTANCE_ID % 8` で上下左右・斜め4方向を選ぶ。描画対象メッシュの頂点をクリップ空間へ投影し、`POSITION.xy` を各方向へ **3 viewport pixels** だけ平行移動して描画する。法線・ポリゴン角度の判定なし。原本メッシュの追加コピーは作らない。
4. 8方向パスには `stencil_mode read, compare_not_equal, 17` を適用し、**元の全身が占める画素を破棄**する。マスクの外にずれた黒い部分だけが3px外周として残る。透明パス優先度は **-21**、色は `#0B1118`。処理を成立させるため、本番のマスクもオフセットパスも深度テストを無効にするが、**内部画素は全身共通マスク側が抑止**する。
5. 将来Skin/Skeleton3Dを用いる装備には、MultiMeshがスキニングを共有できないため同じ原本メッシュの MeshInstance3D 8方向（共通8マテリアル）へフォールバックする。各コピーはソースのSkeleton3DへのNodePathとSkinを引き継ぐ。
6. 装備交換・装備の表示/非表示・枠線設定変更時は紐づくマスク/オフセット補助ノードを再登録・非表示化し、旧ノードを解放する。元メッシュや通常プレビュー材質は変更しない。

## モードと旧方式

- **通常（0）**：8方向マスク外周・黒3px。
- **外周候補（1）／合成確認（9）**：同じ8方向マスク外周を青緑色で表示。
- **既存GPUエッジ（2〜5、14〜18）と旧ハル/ステンシル（6〜8、10〜15、17〜18）**：従来の診断のみ使用。通常表示では旧GPUエッジのメッシュ生成・描画を停止し、診断を閉じると不要ジオメトリを解放する。
- 合計19個の診断ボタンを維持し、統計に新8方向の登録パーツ数、描画インスタンス数、マスク描画件数を追加する。
- 全身以外の単体パーツプレビュー・戦闘・BASE施設・敵・クレートは一切変更しない。

## 同期性と限界

- **追加Viewport・カメラ・CPU毎フレーム画像解析・GPU→CPU読戻しはゼロ**。回転中の輪郭は現在フレームのソース装甲の変換でGPU描画される。ただし装備交換時の新規メッシュ検知には最大約0.35秒の更新間隔がある。
- 8方向で円を近似するため、斜めの角などで3pxの数学的に厳密な円形オフセットにはならない。**精密さを求めないというユーザー要件に合わせた仕様**。実際の幅はビュー解像度基準である。
- 以前の実機画像からステンシル値17の一致/不一致比較が機能している兆候はあるが、**オフセットした全面メッシュと合成したときの表示は未確認**。ステンシルの透明パス順序やAndroid GL Compatibility特有の挙動で外周が表示されない可能性は残る。
- 元の表示モデルに透明シェーダー由来の頂点移動がある場合は、マスクとの投影一致が崩れる可能性がある。現在の不透明Blockbench装甲を対象とする。
- GPU負荷は8方向の面ラスタライズと全身ステンシル描画が増えるため、旧エッジ方式より高くなる場合がある。一方、旧方式の毎回のトポロジ抽出は通常表示では不要になる。FPS、メモリ、実機表示は未確認。
- 8方向の同一MeshをMultiMesh化できないスキン付き等は8 MeshInstance3Dへのフォールバックとなり、描画回数が増加する。

## 次回のユーザー確認

- 通常表示：**頭部・胴体・肩・腕・脚・武器の外周が黒くつながり、手前の凸角には線が入らないか**。
- 回転：素早いドラッグ中に黒い輪郭が本体からずれたり、1フレーム遅延したように見えたりしないか。
- 装備交換：変更後に対象装備へ輪郭が適用されるか。
- もし表示が消える場合は「合成確認（9）」と旧「17一致」「書込停止≠17」で原因を分離する。
