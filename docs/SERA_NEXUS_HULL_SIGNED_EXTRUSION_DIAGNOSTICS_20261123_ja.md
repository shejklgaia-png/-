# NEXUS 全身シルエット：平滑化法線±8pxの独立比較（2026-11-23）

## 背景

PR #800 では元Blockbench装甲の面カリング方向を反転ハルへ反映したが、Android実機の「通常」では枠線がほぼ表示されないままだった。直後の「面反転」ではオレンジで面全体が描画され、「全身＝」ではステンシル値17の一致領域が緑で表示された。ステンシル比較とカリングだけではなく、輪郭用の**平滑化法線の押し出し方向**自体がモデル外側に向いているか切り分ける必要がある。

## 今回追加する診断

NEXUS → カスタマイズ → 輪郭診断の既存14モードに、次の2つを追加する。デフォルトは従来のモード0のままであり、元モデルの色・形状・装備ステータス・通常3px輪郭を変更しない。

| モード | 描画 | 目的 |
| --- | --- | --- |
| 法線＋8px（14） | 輪郭用メッシュを平滑化法線の**正方向に8画面px**移動し、半透明の桃色で表示 | ＋がモデル外側へ向くか確認 |
| 法線－8px（15） | 同じメッシュを**負方向に8画面px**移動し、半透明の黄色で表示 | －がモデル外側へ向くか確認 |

- **両モードともステンシルの書き込み・読み取りを行わず、深度テストと面カリングも無効**にする。面や深度の欠落で法線方向の判断を誤らないための一時的な診断用描画である。
- 既存GPUエッジの「外周候補」を**青緑色の比較線**として同時に表示する。現行エッジの視点判定も完全ではないので、あくまで目安であり、数学的に正確な全身最外周を示すものではない。
- 半透明の色は輪郭だけでなく装甲面の上にも重なる場合がある。**桃色・黄色が塗られた面自体は正常な最終輪郭ではなく**、元の輪郭に対してどちら側へ8px移動するかを確認する目的。
- 画面内で全身を回転し、頭・肩・武装・脚の外周で比較する。同一の表示姿勢で「法線＋8px」と「法線－8px」の2枚を比較するのが重要。
- 現在の法線はBlockbenchの頂点順・面法線を平均化しているため、**法線の正方向が必ずしも物理的な外側とは限らない**。診断ラベルも「外向き／内向き」ではなく「法線＋／－」とする。

## 判定と次の修正

- ＋8pxだけが外側に広がる → 現行法線方向は概ね正しく、輪郭欠落にはステンシルの除外範囲・カリング・描画順の関与を疑う。
- －8pxだけが外側に広がる → 輪郭用法線の符号反転が必要な可能性が高い。Blockbench専用の法線反転処理を検討。
- パーツごとに広がる符号が異なる → 全体一括反転は避け、原本トポロジ・閉じた面／開いた面に応じて法線生成を修正。
- 両方とも外周がほぼ動かない → 画面への法線投影が縮退しているか、輪郭用メッシュの法線が不適切／押し出しが実際には発生していない可能性。

この変更では**診断機能の設置のみ**を行う。結果を見ずに通常の3px外周の法線方向やカリングを決め打ちで変更しない。実機画像・FPSは未確認。
