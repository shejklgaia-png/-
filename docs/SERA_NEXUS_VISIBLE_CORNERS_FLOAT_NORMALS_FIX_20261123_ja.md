# NEXUS全身輪郭：可視凸角の復元と面法線32bit統一（2026-11-23）

## 現象と原因

最新のAndroidスクリーンショットでは、胴体・肩・武装の一部に黒い線が残っている一方、標準頭部の上面と前面の境界や頭部外周、腕・脚先の角が不自然に欠落していた。PR #809までのNEXUSの通常表示は「隣接する2面の表裏が切り替わる辺」と一部の視線とほぼ平行な辺だけを採用するため、**可視の凸角（隣接する2面とも見える箱の稜線）を意図的に除外していた**。

また、最初の面法線は `COLOR.rgb`（各チャネル8bit）、第二面法線は `CUSTOM0.xyz`（32bit）に保存され、同じ判定に異なる精度の値を使用していた。とくに面がほぼ横向きになる瞬間に、ゼロ付近の判定が不安定になる可能性がある。

## 実装

### 1. NEXUSの頂点属性のみ改善

`scripts/sera_nexus_outline_geometry.gd` のリボン生成に `CUSTOM2`（`SurfaceTool.CUSTOM_RGBA_FLOAT`）を追加。

- `CUSTOM2.xyz`：第一面法線をそのまま32bit浮動小数点で保存。
- `CUSTOM0.xyz`：既存の第二面法線32bitを維持。
- `CUSTOM1.xyz`：前回追加したエッジ中点を維持。
- `CUSTOM2.w`：**鋭い凸角**の判定フラグ。共通のBASEトポロジ抽出器が持つ `crease`（80度以上の折れ）を前提に、法線の外積と第一面の有向エッジの内積が正であることを使用。凸方向だけを対象にし、凹形状の内部エッジを無条件に採用しない。
- `COLOR.rgb` は既存診断モードで使用するので、**互換性のために残す**。NEXUS通常描画では参照しない。

### 2. NEXUS通常シェーダー

`shaders/sera_nexus_stencil_edge_outline.gdshader`:

- 面法線Aの取得元を `COLOR.rgb` から `CUSTOM2.xyz` に変更。
- 通常の前／後面切替による最外周判定は維持。外周3pxをそのまま使用。
- 両面がカメラから見える状態（既存SeraRigの面カリング方向に合わせ、`a_facing < -0.07`、`b_facing < -0.07`）かつ `CUSTOM2.w` が凸角を示す場合だけ、**可視の装甲角**を補助的に採用。
- 可視凸角の補助線幅を、画面上**全幅約1.5px**（`±3px * 0.25`）に制限。通常外周より細くして輪郭のコントラストを維持。
- ほぼ横向きの面を使う補助候補も、少なくとも片面がカメラ側を向く場合に絞り、幅を従来の62%から32%へ縮小。不要な太い線を抑制。
- **GPUの標準深度テストは維持**し、前面の装甲に隠れる線は描かない。深度テクスチャ再読込、旧ステンシル、反転ハルは通常表示に戻さない。

## 変えないもの

- 3px最外周、色`#0B1118`、エッジ中点判定、角の端点接続。
- 装備交換・回転・アニメーションと同じフレームでのGPUリボン追従。
- 既存の19診断モード（旧診断の`COLOR`データも維持）。
- BASE施設の共通トポロジ抽出器とシェーダー、戦闘、単体装備プレビュー、クレート、敵。

## 制約

本修正は**表示中の装甲の凸稜線を復元する**ものであり、全身の2D最外周を画素レベルで厳密に確定する処理ではない。非閉鎖・面順の不整合があるメッシュや、装備同士が近接した箇所では凸判定が不完全になる可能性がある。既存エッジ抽出器から除外された辺や、カメラの奥に完全に隠れた辺は復元しない。

`CUSTOM2` の追加はリボン頂点ごとに16バイトの増加となり、29メッシュの輪郭でGPU属性の転送量とメッシュメモリが微増する。毎フレームのCPUエッジ抽出・別Viewport・追加の画面テクスチャ参照は増えない。

Android実機での表示、回転中の安定性、FPSは未確認。次は標準頭部の上端と左右、肩・前腕・脚の外周、胴体内部の余分な黒線、視点変更時の瞬断を確認する。

ユーザー指定に従い、CIテスト項目の確認・修正・適用、およびテスト実行は行わない。

## 公式仕様

- Godot 4.7 Spatial shaders：`COLOR` は各成分8bit、`CUSTOM0..3` は任意の精度の頂点属性に対応。
- Godot 4.7 SurfaceTool：`CUSTOM_RGBA_FLOAT` はRGBAをフル精度の浮動小数点で保存。
- Godot 4.7 StandardMaterial3D：深度判定は描画優先度より優先される。
