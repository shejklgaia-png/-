# NEXUS 全身輪郭：同一Viewport GPUエッジ方式（2026-11-22）

## 適用範囲

NEXUS の SERA 全身プレビューのみを切り替える。BASE 施設、GRID、戦闘中の SERA/ボス、パーツ単体プレビューに現行方式が残る。既存のGRAPHICS SETTINGS「キャラクター枠線」ON/OFFに連動する。

## 描画

- 本体と同じメッシュ階層に線ジオメトリを配置する。別のカメラ・ID用Viewport・CPUの画面投影を介さないため、全身回転と各ボーンへの追従に時間差を設けない。
- トポロジから隣接面を解析し、同じ平面の三角分割線を除外する。GPUで二つの面の向きが視点を挟む場合だけシルエット線を表示する。
- 元メッシュの開放境界を3pxで描画する。
- 閉じた分離メッシュ同士の交差線は、NEXUSで組み立てた姿勢の三角形交差を事前抽出し、補助線として同一Viewportに描画する。モデルの相対姿勢／構成が変わった場合にのみ更新し、全身回転のたびには再計算しない。
- 線幅はスクリーンピクセル基準。通常輪郭4px・境界／接合線3px、色 #17212f。通常の深度テストで完全遮蔽部を隠す。
- 原本の.bbmodelや材質には手を加えず、描画用ArrayMeshを追加する。

## 限界と注意点

- 事前交差線生成には1メッシュ500三角形、全体75,000三角形ペアの上限があり、超過部分は省略する。
- 平面同士が完全に重なる場合、貫通ではなく接触するだけの場合、複雑な非多様体、スキンメッシュは自動接合線が欠ける場合がある。
- 動的に相対姿勢が変化する戦闘用の接合線処理には未対応。NEXUS上の全身姿勢を対象にした実装であり、戦闘へ直接流用しない。
- GPU負荷・見た目・Android Compatibility実機挙動は現時点では未評価。旧方式の更新遅延の構造的要因を除去することを目的とする。


## 2026-11-22 修正：全身輪郭が消失する問題への対応

ユーザーのAndroid画面では、最初のGPUリボン実装においてNEXUS全身の輪郭がほぼ表示されなかった。旧ID方式への復帰は行わない。

- NEXUS独自のArrayMesh NORMAL/TANGENT/COLORエンコードを廃止し、BASE設備側で既に用いている `sera_base_facility_crease_geometry.gd` の `SurfaceTool` エッジ出力を使う。
- 類似のGPUシェーダーもBASEの投影・深度バイアス・法線・直交投影対応の実装に揃える。
- `NORMAL` は面法線ではなく**局所エッジ方向**、`COLOR.rgb` は第一面法線、`CUSTOM0.xyz` は第二面法線。接合線用 `CUSTOM0.w=2` により、視点依存の面法線判定で交差線が落ちないようにする。
- 三角形の共面内部斜線はエッジ生成側で除外し、通常の輪郭は視線に対して前面・背面にまたがるエッジに限定する。
- 従来の SERA 可視ID用カメラへの参加は引き続き無効のまま。既存の左下単体プレビューの枠線は変更しない。

実機表示とFPSは**未確認**。CI項目の確認・修正・適用、テスト実施は行わない。再度のAndroidスクリーンショットで問題が出た場合は、GPUラインパスに限定して修正する。


## 2026-11-22 品質調整：外周優先の3px／1px

NEXUS全身プレビューの新GPU描画を継続し、外周の視認性を優先する。

- **3px：** 同一メッシュ内の表裏面の視点依存遷移（実際の輪郭）。補助ID用Viewportへ戻さない。
- **1px：** メッシュの開放境界と、分離メッシュ間の交差から事前生成した接合線。
- **非表示：** 単一メッシュ内部で手前面同士が作る凸角。ポリゴン分割の三角斜線も従来どおり出さない。
- 視点判定で両側に設けていた0.02の不感帯をなくし、シルエット際の浮動小数点誤差を許容する。線自体は元メッシュの子ジオメトリなので、回転・移動・ボーンに同期する。
- 薄い線が元の装甲面の深度判定で消えやすい点を緩和するため、GPUリボンの視線方向バイアスを僅かに増やす。背後の他メッシュを透過させる指定はしない。

**制限：** シェーダーはメッシュ単位の輪郭を基準とするため、複数の閉じたメッシュが重なった箇所の内側／全身最外周を厳密に区別して太さを変えるものではない。重なる装甲についても可視の各メッシュ輪郭が3pxになる場合がある。1px化の対象は実際の開放境界と専用の交差接合線。全身外周を一意に決定するには、別途全体の遮蔽情報を用いる方式が必要。
