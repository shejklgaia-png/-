# SERA BASE 設備シルエットと局所照明（2026-11-22）

## 枠線
- BASEの設備カテゴリ（facility role 2）の可視シルエット：**内側1px＋外側4px**。可視メッシュ接合部1px、手前向き凸角2pxは従来どおり。
- BASE小物（clutter role 3）は従来の内側1px＋外側1px、境界2pxを維持。GRIDやSERA単独の設定は変えない。
- 第4リングの外側サンプルは、カメラに投影した設備AABB合成矩形の中に限定。1px境界と既存の深度解決IDパスを維持。追加の画面全体IDパス・CPU読取りは設けない。

## NEXUSアンテナ
- アーカイブNEXUSモデルのアンテナ竿は位置・向きを固定し、旧MultiMesh回転・垂直往復・スケール拡縮のサンプル更新を廃止。
- 旧発光バッチ内Beaconキューブを削除し、同じ屋根座標に固定の防護ケース＋独立発光レンズ＋ごく弱いOmniLightを配置。
- Timerによる短点灯（約0.075〜0.14秒）、長点灯（約0.26〜0.40秒）、短休止（約0.07〜0.16秒）、組間休止（約0.45〜0.83秒）をランダム構成。毎フレームのBeaconスケール・位置変更は行わない。

## 共通側面光の整理
- 既存 `BaseFacilityVFX._add_entrance` の全面的な大きなDoorLightLeak/DoorLightFloorは**精製機SMELTERだけ**で維持。非SMELTERでは呼ばない。
- 共通のDoorLamp、NEXUS上部光帯・旧下端光帯、RECYCLER光帯、STORAGE光帯など旧側面光は廃止。小型の機能的な状態表示灯は残す。
- 局所照明のモデルは遮光ハウジング、取り付けブラケット、光るディフューザーをBoxMeshベースで生成。FX_NO_OUTLINEを付け輪郭対象から除外。スポットの影は生成しない。

## 施設別
- **NEXUS**：シャッター下に細い青白色の物理照明＋ローカルスポット＋シャッター前床への低い漏れ光。上部の門灯で側面を照らさない。
- **RECYCLER（分解装置）**：粉砕口の左右に保護フレーム付き作業灯を設置。スポットはカッター／噛み込み部に集光。
- **GENERATOR（電力制御）**：壁のメーター隙間に細い埋め込み照明を複数配置。回転ファンの**背面**に青白い放射状発光板を置き、前面の羽根を遮蔽物とする。ファン周辺には1基の局所スポット。
- **STORAGE（資材保管庫）**：入口に工業用ダウンライト2基、保護シェードと取付ブラケット、入口付近に独立した円形の暖色照射範囲2箇所。
- **SCRAP_COLLECTOR（回収機）**：回収対象エリアと回収箱にそれぞれ作業灯＋スポットを配置。
- **LABO／BUILD_TERMINAL**：従来の共通入口ビームを除去し、既存の作業用局所ライトに物理ハウジングを付加。
- **SMELTER**：従来の煙、炉内炎、炉口光、床反射を維持。

## パフォーマンス・描画
- 新規照明は影なし、定位置配置でアニメーション用ジオメトリ更新なし。精製機の既存炎・煙以外、時間変化はアンテナのTimerイベントのみ。
- スリットやファン背面光、円形床照明は透明パスで既存輪郭より後に合成し、光源自身への枠線や不透明なX-ray線は付けない。
- 実機での見え方、透過の重なり、GPU時間は未測定。


## 2026-11-23：起動直後の発光と輪郭色

- 実機比較画像の**1枚目（ロード後）が正常**、**2枚目（起動直後）が暗く光が潰れる状態**。この解釈を基準とする。
- BASEの可視IDシルエット／接合線／施設の手前角線は **純黒 `#000000`**。戦闘・NEXUS全身・単体プレビューの `#17212F` は変更しない。
- 発光は起動時と施設再構築時に同一の `BaseFacilityVFX.setup()` 内で構成する。初期ロード時だけ後から処理が生成される設計にしない。
- 簡易ブルーム：**24×24px静的な放射状アルファテクスチャ**を起動中一度だけ作成し、モデル発光面＋作業灯の位置に小さな深度テスト付き加算クアッドを配置する。各施設の最大64光源を、**1つのMultiMesh描画**へまとめる。フルスクリーンぼかし・HDRグローバルBloom・追加シャドウ付きライトは採用しない。
- 明確な光源中心（蛍光灯、炉、NEXUSシャッター、発電施設の隙間、端末モニター等）を維持し、外周だけやわらかくする。既存のエミッション強度・発光パターン・開閉アニメーション・VFX重ね順は維持する。
- NEXUSのモールス信号は消灯時に光の輪が残らないよう、固定輪を付けない。
- 起動直後とロード後の差の根本原因（ドライバーのシェーダー準備、光源上限等）は**未確定**。固定Haloで依存を減らす対処であり、実機での発光一致やFPSは未検証。ユーザー指定によりCI項目の確認・修正・テスト実行は行わない。


## 2026-11-23：明るい線すべてへの細線ハローと枠線の局所透過

- PR #829で復旧した初回起動時の発光保護役割 **ID=7** を維持する。初回/再ロードで同じデータを生成する。
- 明るい線の発光源は（1）建築の元々の自己発光MultiMesh（青白／橙／モニター／発電設備）、（2）細長い白色装飾線、（3）発電設備の10本の可視スリット、（4）前面ランプとNEXUS入口の光源。白い広い装甲面は追加発光の対象外。
- 1施設につき最大160個の小さなハローを既存の**24x24pxグラデーション1種類・MultiMesh描画1回**にまとめる。真のエミッションを優先し、その後に細い白いラインを追加。発光中心は元のシャープな形状のままで、周囲だけ低不透明度（概ね0.08〜0.16）で広がる。屋根面の水平ラインはXZ面に沿って描画。**細長い白い建築線はMultiMeshのインスタンスデータへID役割7を記録し、実在する発光材質と同じ輪郭保護規則を適用**する（広い白い面・塗装部分は従来のまま）。
- 光源位置のすぐ周囲（ID画面上半径2px）に黒い輪郭がある場合、**該当する線だけ alpha=0.45**。その他のBASE輪郭は純黒・不透明のまま。共通可視ID線のほか、元の手前側2px物理角線も同じIDマスクで判定。NEXUS全身・戦闘・単体プレビューへは影響させない。
- ランプの実体はFX_NO_OUTLINE配下にあっても、**不透明発光ガラスだけ**既存の同一ID SubViewportに役割7で登録する。透明煙・ビームは輪郭対象に入れない。
- 新規Viewport、フルスクリーンBlur、影ありライト、大量の個別Spriteは追加しない。発光ラインの位置は生成時に確定し、通常の毎フレーム処理は増やさない。発電設備の回転ルーバーは元のモデルを動かし、光の隙間は元の固定座標に維持。
- CI項目に触れずテストは実行しない。Android/GL Compatibilityでの明るさ・遮蔽・描画負荷は実機確認前であり、全面的な改善を断定しない。
