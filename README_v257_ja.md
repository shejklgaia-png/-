# SERA v257 — コントローラ発生位置 → ロックマーカーを「前方」にする実験

## フリックの方向基準
- **前（0°）**：画面に指を置いてコントローラが発生した位置から、HUDに表示されたロックマーカーの中心へ向かう線。
- **ほか7方向**：この線を軸に、時計回り45°ずつ8方向へ振り分け。各区画は中心±22.5°。
- セラがカメラ上でどちらを向くかに左右されず、コントローラの発生位置が変われば前方向も変わります。
- 対象：通常フリックステップ（8方向）、ガード→バッシュ、3段コンボ→バッシュ、および今後のフリック操作の共通判定。
- 描画に使用する `touch_ui.target_marker_position` と `target_marker_visible` を参照するため、ロック対象が頭・脚などへ切り替わればその場所に向かう方向が「前」になります。

## 安定化とフォールバック
- 操作開始位置とマーカー位置はどちらも画面座標です。タッチ開始時に方向を記録するため、操作中のカメラ旋回でいきなり判定が変わりません。
- 長押しGUARDの最後のフリック開始時だけ方向を再取得し、Androidで途中のドラッグイベントが省略された場合は離指時に再取得します。発生位置はあくまで当初のタッチ座標です。
- ロックマーカーが画面外／非表示、またはコントローラ発生位置と重なる場合は、旧セラ正面の画面投影方向を代替します。

## 変えない仕様
- ステップとバッシュの45°×8方向分類、バッシュの前方±22.5°、v256の入力時間0.42秒／正面30px／200px/s、ステップ距離・速度・EN・モーション、RUN/BOOST、ロック表示、部位限定命中、衝突／カメラは変更しません。
- Godot/Android実機の操作は未検証です。
