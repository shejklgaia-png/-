# SERA v435 — 歩行・旋回4脚IK＋攻撃時3脚支持IK

## 方針
v434で修正したBlockbenchの回転キー時刻順とEuler角補間をそのまま維持します。今回復帰するIKは、**脚の関節だけ**を解く簡略化した独立処理です。過去の巨大なIK処理に含まれていた胴体の下降・前傾・後傾、攻撃脚の床接地、下肢メッシュ個別移動などは復帰しません。

## 実装
- `scripts/bittaran_battle.gd`：`BLOCKBENCH_SOURCE_REPLAY_ONLY = false`、`BLOCKBENCH_GAIT_SUPPORT_IK = true` に設定。原本を先にサンプリングし、最後に脚のIKを適用します。
- **歩き（Approach）・旋回（Turn）**：4脚の足裏をワールド座標で保持。胴体の移動・旋回で約0.62m以上の目標誤差が発生した場合、対角線2脚を0.52秒で踏み替えます。踏み替え中は最大0.22m持ち上げ、残り2脚は定位置を維持します。Idleでは不要な新規ステップを開始しません。
- **攻撃中**：6種類の左右前脚攻撃は原本のBODYおよび攻撃脚の位置・回転キーを維持。攻撃していない残りの3脚だけを、攻撃開始直前のワールド上の接地点と足首角度に2ボーンIKで合わせます。攻撃脚にはIKを適用しません。
- **攻撃終了**：3本の支持脚は接地点を保持。攻撃を終えた1脚は0.32秒の踏み直し目標を介して待機・歩行IKに戻します。
- **Root・メッシュの安全性**：v434のWait基準による初期床合わせは1回だけ。各フレームの胴体やモデルルートのY移動、MeshInstance3Dの単独平行移動は行いません。リスポーン時も基準床位置へ戻します。
- **頭部の自動追尾**：v434から引き続き一時停止しています（今回の対象は脚のIKのみ）。
- 既存の `bittaran_foot_ik.gd` の2ボーン関節ソルバー `_solve()` を使いますが、旧 `advance_ik()` に含まれる大量の胴体・攻撃・脚変形処理は利用しません。

## 検証
- 原本との独立した回転・位置キー比較：`tools/v434_bittaran_blockbench_exact_playback_runtime_check.gd`。v435では実ゲームのIK状態に関係なく、単独ソースサンプラーを比較します。
- 新規 `tools/v435_bittaran_gait_three_support_runtime_check.gd`：実バトルをロードし、Approach・Turn・Idleの計165フレーム、6種類の攻撃を検査する設計です。支持脚3脚の接地、攻撃脚・胴体のソース一致、全18メッシュの親関節接続、ルートの高さ不変、対角踏み替えを確認します。
- `.github/workflows/sera-bittaran-original-replay.yml` に両Godotテストを追加。main push／PRで起動します。
- 現時点で静的なGitHub反映と参照整合確認を実施。**Godotの実行成功とAndroid実機映像はまだ確認できていません。**

## 残る設計課題
Blockbench原本はWait・なぎ払い・弾き・踏みつけで胴体の位置キーが異なり、攻撃クリップ開始・終了で原本の姿勢が切り替わります。**クリップ間の滑らかな遷移は今回まだ追加していません。** 原本のキーフレームを変えずに移行処理を設けることが次段階です。また、物理的な脚の届く範囲を超える接地目標は、骨格を伸ばさずソルバーの到達限界内で解くため、足裏に残差が発生する場合があります。
