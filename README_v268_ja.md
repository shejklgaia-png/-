# SERA v268 — 3段目の振り抜き中に蹴りを入力するとSTEPになる問題

## 動画に基づく原因
添付動画 `1000034689.mp4`（17秒、画面録画、SERA v267）では、約9.60秒の `STRIKE 3/3 | Melee3` が約9.76秒に `STEP DIAGONAL | BLENDED` へ切り替わり、約14.24秒→14.40秒にも同様の切り替わりが見られました。約4.48秒と11.52秒の `STRIKE 3/3` の直後にはRUNが表示されています。**蹴りが一度も開始されず、3段目が終了する前に通常移動へ移行しています**。

v267の `_begin_drag` は `side_kick_flick_candidate` を「3段目のモーション終了後0.65秒」だけで生成していたため、3段目の振り抜き中に左右フリックすると、`_change_drag`／`_physics_process` によって格闘をキャンセルするか、`_end_drag` によって通常STEPが開始されていました。蹴りクリップ未収録ではなく、**入力が蹴りへ届かない問題**です。

## 修正した仕様
- **3段目の振り抜き中も左右蹴り入力を受け付けます**。3段目の `STRIKE` または追尾前段階の `STRIKE_TRACK` で入力しても、セラが`Melee3`を最後まで再生する間は蹴りを**予約**します。
- `Melee3`が完全終了し、攻撃の表示状態を解除した後、保存したフリック方向・左右判定に従って `Kick_l`／`Kick_r` を開始します。**3段目のモーションを途中でスキップしません**。以前からの前方バッシュは、従来のキャンセル時刻・受付順を維持します。
- 蹴りはセラの正面を0°とした左右各90°セクター（中心±45°）で判定します。**入力・移動方向は画面相対のまま**。蹴りも通常STEPと同じ2〜4mの移動・衝突・速度・EN計算を流用します。
- 蹴りフリックの受付時間を、動画で途中RUN判定が発生していたことを踏まえて通常STEPの0.24秒から**既存Bashと同じ0.42秒**へ変更。最小移動30px、最低200px/秒、反転許容1.35倍を適用。通常STEPの0.24秒／78px／500px/秒の設定は変更しません。
- ガード、被弾、中断、別段のコンボ開始やバッシュの選択時は予約を解除。通常STEPの操作・攻撃キャンセルは格闘1・2段で維持し、3段目の蹴り受付にだけ例外を設けます。左右蹴り入力が通常STEPへ誤フォールバックしない排他制御も維持します。
- 動画で結果が分かるよう、既存のデバッグHUDに **`STRIKE 3/3 | KICK QUEUED`**、実際の発動時には **`KICK LEFT | Kick_l`／`KICK RIGHT | Kick_r`** と表示。単にSTEP距離を共有しているだけの蹴りが `STEP DIAGONAL` と表示される混同を解消します。

## 検証
`tools/v268_melee3_kick_buffer_self_check.py` に動画由来の再現条件、3段目中の候補保持・RUN誤キャンセル防止、最後までのMelee3再生、保存した入力の消費、左右90°判定、画面相対STEP移動、元モーションの存在、後続バッシュ、キャンセル時予約消去、デバッグHUDの表示を記録してCI検査します。

この検証はGitHubコード・データの静的検証です。**Godot Androidでの再生・操作は未検証**です。
