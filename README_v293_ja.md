# SERA v293 — AUTOロックを「頭→本体→4脚→本体」の周回順へ修正

## 現象と原因（2026-11-12、添付動画10.9秒）
動画ではAUTOボタンが有効で、セラが敵の周囲を移動しても脚のロック先が切り替わるだけでした。v292の `select_camera_front_part` は頭と4脚しか候補にせず、中央のBODY（本体）を対象から除外していました。また、投影スクリーン上の中心点との距離で比較するため、カメラの周回順が部位順と一致しませんでした。

## 修正内容
- AUTO用にカメラ位置の**ボス中心を原点とするXZ平面方位**を計算し、36度ずつ10区間へ分割。周回すると **頭→本体→左前脚→本体→左後脚→本体→右後脚→本体→右前脚→本体→頭** の順でロックします。反対回りでは逆順です。
- ボスのモデル前方はローカル +Z、左は -X。固定配置は敵の向きに追従します。頭/脚が破壊済みの場合、その区間は本体を選びます。ほかの部位へ強制ジャンプしません。
- BODYロックのIDは従来の空文字を維持し、既存の本体への格闘接触・追尾・ダメージおよび標的中心のレティクルを利用します。HUDに `LOCK BODY` と本体HPを表示します。
- 未取得とBODY選択を区別する `auto_lock_initialized` を追加。初回・破壊済み回復は即時、通常切り替えは従来の0.22秒確認を維持。特にBODY→脚の瞬間切り替わりを防止します。
- 画面横位置で選ぶMANUALの左右ボタン、モデル、モーション、武器、戦闘ダメージ式、カメラ挙動は変更していません。

## 検証
10区間と逆周回、頭への復帰、破壊脚のBODY退避、AUTOの初回取得、頭→BODY→脚の0.22秒遷移を対象とする新規Python静的テストとGodot実行テストを追加し、既存のv291/v292検査も現在仕様に更新しました。Android実機での操作確認は別途必要です。
