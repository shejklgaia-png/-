# SERA v266 — 3段完走後の左右蹴り入力を通常STEPと排他的にする

## 原因
v265の `_end_drag` は蹴り要求を先に処理しますが、`_request_combo_side_kick` が失敗したとき通常の `_start_omni_step` へ続行します。さらに `_change_drag` は短いフリックの途中で一度でも左右以外へ向くと蹴り候補を破棄するため、その後に指を左右へ抜いても通常STEPが発動し得ました。

## v266の仕様
- **通常格闘3段目が完全終了した後**、既存0.65秒の派生受付期間内に開始した有効な左右フリックは蹴り専用です。開始時点で受付を確保し、途中の軽い斜め方向の揺れでは破棄せず、指を離した時の**画面基準左右45°セクター**で確定します。
- 蹴りクリップ欠落、EN不足、行動制限などで蹴りを開始できない場合も、その入力を**通常STEPとして再解釈しません**。何も発動しない形になります。画面左右以外（前後・斜め）は以前のBash/360°STEPの判定を維持します。
- STEPと蹴りは、移動距離2〜4m、速度・EN・衝突計算・カメラ処理を共有します。変更するのは**入力の振り分け・候補保持**だけです。
- STEP判定時間0.24秒、距離78px・最低速度500px/s、移動開始後のキャンセル、格闘3段目**完走前**の通常STEPキャンセルは変更しません。入力開始時に派生受付外なら従来どおり通常STEPです。

## 回帰確認
`tools/v266_exclusive_side_kick_self_check.py` は、時間による候補期限・中間方向での候補保持・左右の排他的return・前後斜めのSTEP維持・蹴りとSTEPの移動処理共有を確認します。既存のv264/v265のテストは、版番号と「通常STEPフォールバック」について新仕様へ更新しました。Android実機のフリック操作は未検証です。
